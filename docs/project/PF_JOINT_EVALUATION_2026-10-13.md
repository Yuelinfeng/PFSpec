## 独立测试结构

F1 使用原保留测试集 `lfq_new_onpolicy/test`，16 条轨迹、6041 个位置；以 CUDA BF16 前向计算两组实际采样概率和 Teacher 概率重合度。它代表相同已存前缀上的期望接受率，不等同于在线采样接受计数。

现有 F2 目录只有训练与开发验证数据。本轮另用 481101–481108 的新 seed，分别由父提议器与联合提议器生成 K3 序列，每次最多 1024 token。只在 P1、F1、P2 都接受且实际到达 F2 时取得 Teacher 概率。两个提议器各形成一个测试来源；在各来源相同记录前缀上分别评价父模型和联合模型，不改记录中的 F1 或 P2。采集不计入后续解码测速。F2 标签只暂存内存，输出保留逐轨迹指标，无新增训练数据文件。

可用编号中的训练与开发验证轨迹不能与新测试 seed 或 F1 测试轨迹重叠。旧离线 F1 没有轨迹编号，无法通过编号证明其完全独立。不同随机 seed 表示独立生成轨迹，不能解释为不同真实场景。

## 在线测速结构

一个进程只载入一次 Target，轮转执行五个版本：普通解码、父 K2、联合 K2、父 K3、联合 K3。使用新 seed 480101–480124，每个版本每条最多 1024 token。每个版本预热后计时，逐 seed 轮换运行顺序，以减少先后顺序影响。

K2 是 `P1-F1-P2`，K3 是 `P1-F1-P2-F2-P3`；这里的 K 表示 Position 数，与普通 Draft-A 的提议 token 数含义不同。计时包括缓存分配、草稿、Target 验证、接受与拒绝处理、采样；不包括模型载入、JIT 编译、数值验证和独立 F2 采集，也不包括渲染。

先验证两组的 F1 与 F2 JIT 概率和支持范围与原实现一致，再验证 K2 新旧解码入口在同一组模型和 seed 下的输出及计数一致。运行中沿用接受概率与拒绝后的剩余概率采样，确认输出类型、长度与 Position 顺序。

结果单独记录 F1 接受率、F2 条件接受率、到达 F2 的比例、联合成功率、未评价 F2 提案数、Target 调用数、tokens/s。速度统计使用总 token 除以总时间；新旧速度比按 seed 配对重采样。相同 seed 在不同草稿模型下可能产生不同轨迹，因此速度差异也包含生成路径差异。

结论：本轮独立评价不支持替换现有父权重，也没有突破 K2 约 1.73× 的证据。保留联合第二轮实验候选及全部日志，继续使用父 K2 作为现有最快配置。本轮没有增加训练，没有对测试结果再次选模，没有修改正式解码器或权重。

评价结束后进程正常退出，GPU 无计算进程。没有新增临时权重、语料副本或后台任务，无需清理模型产物。

限制：本轮仅一个训练 seed、一个 Target 与 Position 提议器、从 BOS 生成的 1024-token 窗口，没有真实多场景重建或长上下文测速。固定前缀测试不证明完整三维质量改善。后续可研究如何减少未实际评价的深层提案，优先比较已有 K2 与按置信度启用 K3；本轮未实现该机制。

源码核实：`bench_lfq_scratch_pf_cow.py` 的 K2 草稿前向与 `pf3_depth2_decode.py` 的 K3 草稿前向都在解码器内部使用 CUDA BF16 autocast；外层计时不再添加另一层精度设置。调用现有 Target 入口，沿用已有数值路径。
