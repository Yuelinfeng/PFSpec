## 1. 正确性验证

接受/拒绝及残差采样的数值恒等式通过。生产 K2 解码循环接入有限状态 Target 后运行 4,000 次，覆盖 17 种输出；观测频率最大偏差为 1.96 个 Monte Carlo 标准误，4,800 次缓存回退都到达请求位置，所有 P/F 前缀规则均通过。

另取真实开发场景的 33 个 token 行，比较完整输出头、类型稀疏输出和逐 token/分块前向。最大总变差为 1.04×10⁻⁶；各种缓存路径都停在相同位置，类型掩码无差异。该实测覆盖一条真实序列的 33 行；它和有限状态采样结果共同支持当前实现，仍不等同于对完整模型所有前缀作穷尽证明。

## 2. 成本与收益

先在 3 个开发场景、64/256 前缀、256 token 上限下进行三种子诊断；每种方法有 18 条无埋点记录。另跑阶段计时、函数级计时以及 seed 34704 留出轨迹。按完整统一口径，又使用长度足够的开发裁剪覆盖 64/256/1024 前缀和 512 token 上限；seed 34701 为主批次，seed 34704 为留出批次，每个批次包含 45 条无埋点和 45 条埋点记录。

512 token 主批次的无埋点结果如下。Token/s 为全批次生成 token 总数除以完整计时总秒数；加速比以 Target 为参照。

| 方法 | Token/s | 相对 Target | 相对 P-only | P 接受率 | F 接受率 | 平均每轮推进 token |
| --- | ---: | ---: | ---: | ---: | ---: | ---: |
| Target | 72.25 | 1.000× | — | — | — | — |
| P-only | 104.44 | 1.446× | 1.000× | 93.19% | — | 2.000 |
| PF-K2，step12000 | 121.73 | 1.685× | 1.166× | 92.21% | 32.25% | 2.586 |
| PF-D8 | 109.70 | 1.518× | 1.050× | 93.97% | 59.39% | 3.103 |
| GPT-D8 | 67.26 | 0.931× | 0.644× | 77.82% | 54.09% | 2.112 |

按三个来源场景重采样得到的 PF-K2/P-only 几何平均速度比为 1.164×，95% 区间 [1.158, 1.173]；PF-D8/P-only 为 1.051×，[1.036, 1.061]；GPT-D8/Target 为 0.933×，[0.880, 0.996]。每个区间只有三个来源场景，属于开发数据描述，不能替代更大来源集的正式确认。

成本分解解释了接受率和速度的差别。512 token 埋点批次中，PF-K2 的 MLP Feature forward CUDA event 合计约 0.76 秒，PF-D8 的 GPT Feature forward 约 10.02 秒；两者都覆盖九条运行记录。PF-D8 的 F 接受率更高，草稿前向成本也显著更高，最终吞吐低于 PF-K2。P-only 的 Target verify CUDA event 合计约 38.09 秒；PF-K2 的 Target verify 合计约 27.48 秒。GPT-D8 的草稿 forward 合计约 27.40 秒，Target verify 约 36.08 秒。Host 时间与 CUDA event 时间分别保存，不相加。

按来源和前缀汇总的 seed 34701 → seed 34704 计时预测误差为 0.6%–3.5%。PF 阶段分项及 Target、P-only、GPT-D8 函数级预测也保存了训练值、留出实测值和逐项误差。所有埋点批次与无埋点批次逐行比对后，token 数、接受数、EOS 和轮数均为零处差异。埋点时观测到的端到端耗时变化约为 0.6%–2.7%；该数值含运行顺序和计时波动，应作为埋点影响的量级参考。

256 token 多种子诊断也支持相同排序：PF-K2 123.40 token/s、P-only 104.23、PF-D8 104.89、Target 72.47、GPT-D8 64.91。其来源场景数仍为三个，解释作用为主。

## 3. P/F 贡献消融与结构先验

Position 消融覆盖 10 个开发来源、280 条在线记录。全批次吞吐为 Target 70.468、当前 Ranker 97.100、历史位置选择器 89.531、去除空间筛选 97.339、打乱空间次序 97.065 token/s。当前 Ranker 相对历史选择器的来源组速度比为 1.084 [1.050, 1.119]；与去除空间筛选、打乱空间次序相比，分别为 0.999 [0.994, 1.006] 和 1.002 [0.993, 1.012]。因此，学习到的排序器优于简单历史选择；显式 XYZ 打分没有带来可测的额外收益。候选构造仍保留空间邻近约束。

在 6,287 个 teacher-forced Position 上，当前 Ranker 的期望接受率/采样命中率为 77.49%/77.59%，历史选择器为 56.75%/53.71%；四种候选方法的候选概率质量覆盖率为 87.54%。

Feature 输入消融覆盖同一组 10 个来源、392 条记录。全批次吞吐（token/s）为 Target 72.066、P-only 99.054、step12000 PF 115.508、等预算完整输入 112.542、移除候选 Position 112.803、移除历史 Feature 113.813、移除 Target 状态 97.779。step12000 相对等预算完整输入的来源组速度比为 1.028 [1.010, 1.050]，相对移除候选 Position 为 1.028 [1.008, 1.055]；相对移除历史 Feature 为 1.017 [0.999, 1.039]，区间含 1；相对移除 Target 状态为 1.185 [1.145, 1.225]。结果支持 Target 隐藏状态是关键输入，候选 Position 有小幅帮助；移除历史 Feature 后的速度差异仍不确定。

## 5. Medusa-style、Hydra-style 与 EAGLE 对照

参数预算近似匹配的开发比较使用 10 个来源、64/256/1024 前缀、两个种子和最多 256 个输出 token。全批次吞吐如下：

| 方法 | 核心草稿 | Token/s | 相对 Target 微平均吞吐比 |
| --- | --- | ---: | ---: |
| Target | 原始自回归生成 | 69.94 | 1.000× |
| P-only | Position Ranker | 96.21 | 1.376× |
| step12000 PF | Position Ranker + Feature MLP | 112.39 | 1.614× |

## 7. 新来源确认与完整三维输出

实验方案、模型、脚本和主指标在读取 30 个确认来源 ID 前登记。30/30 个来源完成场景准备，每个来源选出一条至少有 256 个正文 token 的裁剪；正文长度为 514–1,652 token。64 与 256 前缀各覆盖 30 个来源，1024 前缀覆盖 14 个来源。运行统一使用 RTX 4090、FP32、temperature/top-p=0.9；实际环境为 Python 3.10.21、PyTorch 2.8.0+cu129、CUDA 12.9。

Token 评测完成 666/666 次，覆盖 Target、P-only、step12000 PF，三个前缀长度、三个种子，最多生成 512 token。全批次吞吐为 Target 71.996、P-only 102.685、PF 119.729 token/s。按来源组几何平均，P-only/Target 为 1.430 [1.418, 1.444]，PF/Target 为 1.674 [1.642, 1.706]，PF/P-only 为 1.170 [1.155, 1.186]；三项均为 30/30 个来源更快。区间采用 2,000 次来源组重采样。PF 的 Position 接受率为 90.76%（48,227/53,136），Feature 接受率为 32.29%（11,903/36,859）；按 64/256/1024 前缀分层，PF/P-only 微平均吞吐比依次为 1.185、1.169、1.124。

完整三维评测完成 270/270 次：30 个来源、Target/P-only/PF 三种方法、三个种子。每种方法均为 90/90 成功并自然 EOS，没有达到正文长度上限。计时从准备好的 token 输入开始，直到 Gaussian NPZ 和六视角 PNG 保存；单个 20×20×20 latent chunk，前缀 256，正文上限 16,000；不含模型载入和输入压缩。平均完整耗时为 Target 46.35 s、P-only 31.37 s、PF 29.41 s。

按来源组配对计算，P-only/Target 完整流程速度比为 1.446 [1.258, 1.650]，27/30 个来源更快；PF/Target 为 1.530 [1.340, 1.721]，28/30 更快；PF/P-only 为 1.058 [0.958, 1.167]，21/30 更快。由此可确认 PF 相对 Target 加快完整输出；PF 相对 P-only 的额外完整流程收益仍不确定。

270 个 Gaussian NPZ 均可读取，1,350 个数值数组均为有限值；1,620 张生成视角 PNG 全部可读取。输出目录另含 180 张参考图和汇总图 `all_samples.png`，不计入生成视角数。全 chunk 平均 PSNR/SSIM 为 Target 10.894 dB/0.7240、P-only 10.991 dB/0.7239、PF 10.845 dB/0.7182。这些指标只作整块描述；当前没有生成区域遮罩，无法据此判断生成区域质量是否保持。评测只覆盖单 chunk，未测多 chunk 连续生成。

数据来源限制：Target 与 VQ-VAE 预训练资料没有可用场景 ID 清单，无法确认预训练来源与这 30 个确认来源完全隔离。纹理包 852 个文件中有 227 个可用，缺失纹理可能影响画面显示。
