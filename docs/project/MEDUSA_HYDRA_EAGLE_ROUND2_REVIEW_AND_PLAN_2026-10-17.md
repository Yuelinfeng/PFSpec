# GaussianGPT 第二轮多头与特征草稿：路线评审及实施计划

日期：2026-10-17。状态：计划稿；本轮完成材料阅读和关键源码查看，未启动新训练、GPU 测速或完整诊断实验。

后续进展：用户已授权开始执行，实际完成范围与数据见 [第二轮执行记录](ROUND2_EXECUTION_2026-10-17.md)。下文保留路线评审时的计划与判断边界。

## 1. 评审结论

建议采纳“双轨比较”，把完整 P/F 提案能力与共享 Position 条件下的 Feature 机制分开。实施顺序调整为：A0/A1/E0 无训练诊断 → B0/B1 受控 Feature 比较 → 按证据选择 A2/B2 或树式扩展 → 新来源确认。

上传路线最有价值的判断是：当前 Medusa/Hydra 首个 Position 接受率分别只有 0.78% 和 0.46%，F1/P2 可到达次数太少，现有结果不足以比较后续预测能力。当前代码还同时改变了 Position 提案来源，因此这些结果适合描述整条适配路径，不能单独归因于 Feature 网络结构。

需要补充四点：

1. 训练与推理都跨过尚未处理的历史 Feature 预测下一 Position。缺少这项输入可能损害预测能力，但目前不能称为训练标签错位。
2. 把隐藏状态直接换成 Target 处理该 Feature 后的状态，会改变输入分布，并增加 Target 计算；这种改动需要单独计费和评价。
3. 共享 Ranker 后，所有 Feature 模型还应共享相同的历史信息，才能单独分析候选 Position 的贡献。
4. 已训练 EAGLE 的存储类型、训练 AMP 和推理计算精度需要分别登记；仅凭“BF16 checkpoint”无法判断一次 FP32 推理比较是否公平。

## 3. 研究问题与可解释指标

下一轮主要回答三个问题：

- Position：低接受率主要来自条件信息不足、位置支持集/映射差异，还是模型训练不足？
- Feature：给定同一 Position，候选 P 条件、历史 Feature 条件和特征递归分别增加多少有效接受，花费多少计算？
- 系统：增加的草稿成本是否换来了足够的已提交 token 和更少的 Target 调用？

在相同前缀 c、相同合法支持集和采样策略下，标准单候选接受规则的期望接受率满足：

α(c) = Σx q(x|c) min(1, p(x|c)/q(x|c)) = Σx min(p(x|c), q(x|c))。

因此，固定前缀的分布重合度可以解释该前缀的期望接受率。离线前缀和实际生成前缀的分布不同，离线均值不能直接替代在线平均接受率。草稿只使用部分历史条件，也可以通过完整 q 与标准残差采样保持 Target 条件分布；条件不足首先是提案质量问题，不能直接视作采样错误。[标准投机采样论文](https://arxiv.org/abs/2211.17192)

计算收益用两层指标描述：每轮已提交 token、每轮完整同步耗时，以及整条路径的总 token/总耗时。近似单 token 成本为 E[轮次耗时]/E[已提交 token]。GPU event 与 CPU host 时间分别报告，存在重叠时不直接相加。上述关系用于解释结果，属于已有采样与计算分析方法。

## 4. 第一阶段：A0/A1/E0，无训练诊断

### 4.1 A0：取得足够的真实证据

复用现有环境和结果，先登记正在运行的工程、解释器、GPU 作业和数据位置。保留原训练及测试资产。

收集实际比较入口、两个模型定义、训练取样与损失、配置、训练曲线、最佳权重元数据、336 条在线记录、分项计时及 EAGLE 证据。外部审阅副本应包含这些源码和逐条 JSON；权重留在远端并登记路径。

逐项核验：token 偏移和 P/F 边界；lm_head 前后隐藏状态及归一化；Position rank/ID 对应；类型 mask 在采样前生效；完整 q 与拒绝分支；EOS、缓存位置和 3D RoPE。

交付：A0_source_audit.md、调用关系图，以及 10 个固定样本的逐 token 表。样本表包含已处理前缀、pending Feature、取样状态、标签位置、草稿/Target top-k、合法概率质量和重合度。发现确定的不一致时，先定位影响范围，后续实验单独标记行为变动。

### 4.2 A1：区分实现、信息与训练能力

先在现有 10 个开发来源的可用 64/256/1024 前缀上，每个来源与前缀组合抽取最多 16 个锚点，首批最多 480 个上下文；抽样顺序和位置保存下来。另在原训练与验证轨迹上使用相同统计，区分训练域与真实前缀域表现。

对每个上下文计算：P1 重合度、非法概率质量、真实下一 P 的 q 概率、top-1/top-k 命中、熵、EOS 概率、空间 rank 间隔。按来源、前缀和训练/验证/真实域分别汇总。

历史 Feature 的作用分三种口径：

- 当前头：继续使用原 hprev，复现已有分布。
- Ranker 提案：作为同上下文位置提案参照，明确记录替换了 P1 机制。
- 已处理 Feature 的 Target 状态：用于解释信息边界。额外 Target 前向计入耗时；把该状态直接送给旧头属于输入变化，结果只作诊断。

只有发现支持集、偏移或状态处理确有不一致，才执行相应变更后的同条件重测。避免通过改变 Target 温度或 top-p 提高接受率。

交付：A1_position_diagnostics.json、A1_position_report.md。报告需要区分“已确认问题”“数据支持的解释”和“仍未区分的假设”。

### 4.3 E0：同步诊断已有 EAGLE

优先复用已有 16,360 行审计结果，按 P→F、F→P、首步/后续步和前缀长度拆分；缺少字段时只补采所需部分。

验证 hidden_prev_raw 的实际 token 边界、训练可见条件、token embedding、输出头、类型支持集、采样策略和 3D RoPE。分别登记训练 AMP、保存张量 dtype、加载后参数 dtype、推理运算 dtype 与 TF32 设置。主比较以可用 FP32 路径为准，BF16 单列。

交付：E0_alignment_report.md。已有策略和缓存测试属于正确性证据，3.71% 离线重合度属于提案质量证据，两者分别解释。此阶段不训练更长递归链。

## 5. 第二阶段：B0/B1，共享 Position 的 Feature 比较

### 5.1 统一接口与输入条件

复用同一 Ranker-P1、Ranker-P2、原 K2 验证循环、Target、采样策略和轨迹划分。把实际线上可获得的历史条件记为 c：当前 hprev、历史 Feature，以及所有方法共享的历史位置信息。各方案只在指定输入和草稿结构上变化。

| 方案 | 共同条件 | 候选 P1 | Feature 输出方式 | 主要问题 |
| --- | --- | --- | --- | --- |
| B0 | c | 读取 | 当前 MLP 结构，使用共同轨迹重训 | 同训练条件下的参照 |
| B1-M | c | 不读取 | 独立 F 预测头 | 缺少候选 P 是否影响 Feature |
| B1-H | c | 读取 | 条件 F 预测头 | 在共同历史输入下衡量 P 条件 |
| B1-E | c | 读取 | 单步连续特征预测，再经共享输出头 | 特征建模是否值得额外成本 |

旧 step12000 PF 作为现用系统参照，单独列出；B0 使用共同训练数据和预算。B1-H 与 B0 的比较用于分析网络形式及成本。B1-M 与 B1-H 的历史 Feature 输入保持一致，以免同时改变多项条件。

B1-E 的训练标签可以由 Target 生成；推理输入必须在验证候选 P 之前实际可得。训练时用于构造标签的未来 Target 状态不能进入推理输入。共享的固定输出头不计入可训练参数，但其计算与访存成本必须计入整条路径。

这些方案是 GaussianGPT 的受控机制比较，统一使用 adapted 或 style 标记。[Medusa](https://arxiv.org/abs/2401.10774) 描述独立未来头和树式验证；[Hydra](https://arxiv.org/abs/2402.05109) 描述候选依赖头。此处的 Feature 单步对照只覆盖其中的机制。

### 5.2 训练与评价安排

先复用同一组 40 条 Target 轨迹与完整轨迹划分。四种新模型使用相同训练 token 预算、优化器安排、验证规则和种子；保留训练曲线。若原 10 轮安排明显未充分拟合，再给出共同延长预算，保留前后结果。

第一训练种子用于工程筛选；进入结论比较的方案追加两个训练种子。不同来源的运行种子与训练种子分别登记。单个训练种子的正负结果均不用于宣称结构稳定优劣。

参数量相近与实际 GPU 延迟分别报告。优先使用合理的小模型，避免单纯为凑参数添加无用计算。EAGLE 原有 20.97M checkpoint 另作参考；小预算 B1-E 与其分开解释。

在线比较复用开发集、FP32、temperature/top-p=0.9、64/256/1024 前缀、最多 256 新 token、相同随机种子与计时范围。运行顺序在方法间轮换，模型加载和 warmup 不计入主时间。必要的少量分项计时与无埋点主速度分开。

每种方法保留：参数量、共享固定参数量、P1/F1/P2 可到达次数、接受/已验证计数、固定上下文重合度、每轮已提交 token、Target 调用次数、草稿 GPU 时间、CPU 时间、完整路径 Token/s。

交付：B1_training_summary.json、B1_online_records.json、B1_paired_results.json、B1_mechanism_report.md。报告同时给出微平均吞吐与来源等权几何平均；区间按来源重采样，训练种子间差异另列。

## 6. 第三阶段：按证据选择完整适配或更长候选

### A2：改善独立 P1

若 A1 支持条件不足且未发现实现错误，比较：原 P1 头、增加 pending Feature embedding 的头、Ranker 候选集上的小型重排器。训练来源、监督预算和采样策略一致。

候选重排器需给出实际采样的完整归一化 q，记录候选覆盖率。达到较好重合度后，仍要测整轮吞吐；不设未经成本分析的统一接受率数字。

### B2：验证候选 Feature 对下一 Position 的作用

当 B1-H 具有足够 F1 可到达样本时，比较原 Ranker-P2 与读取 P1/F1 的条件候选评分。P2 同上下文比较限定在实际已到达位置，另外报告全路径收益。若后续位置很少到达，停止扩大 P2 模型。

### M2/H2：小规模候选树

在单链预测有效、且成本测量支持扩大候选时，再试节点预算 4/8/16。先固定已训练头，分别评价独立分支与候选依赖分支。

多分支算法需要与其提案过程一致的接受/残差算法，不能直接以“选最长匹配路径”替代精确采样论证。先验证小词表联合采样，再验证真实模型缓存、类型、EOS 和 3D RoPE。保留节点数、利用率、每轮推进和完整验证耗时。

### E1/E2：递归及 EAGLE 后续版本

B1-E 单步有实际价值后，再做 1/2/3 步特征递归。已有 EAGLE 的“特征与提前一个 token 条件结合”提供设计线索，具体 token 边界要按 GaussianGPT 重写。[EAGLE 原论文](https://arxiv.org/abs/2401.15077)

动态候选树和训练时模拟生成分别作为后续独立改动；同时改变多层特征、训练方式与树结构会妨碍归因。官方仓库分别提供 EAGLE-1/2/3 的论文及实现入口，执行时选择明确版本与代码分支。[EAGLE 官方仓库](https://github.com/SafeAILab/EAGLE)

## 7. 最终确认与结论范围

旧 10 个开发来源继续用于诊断和选模。10 月 17 日的 30 个确认来源已经被使用，可作历史复测集。新方法确定后，再登记一组新来源作为最终确认集；保持至少 30 个来源，并披露 Target/VQ 预训练来源 ID 不完整的限制。

完整三维输出只评价进入最终比较的候选，沿用相同单 chunk 计时范围。Token 速度、完整耗时和输出长度分别报告；生成区域质量需要对应遮罩和独立指标，当前全 chunk PSNR/SSIM 不足以说明该区域质量保持。

允许三类结论：新机制在同条件下提高吞吐；新机制改善提案但成本抵消收益；现有证据不足以区分。停止某项工程扩展时，保留可用于解释 P/F 条件与成本的负结果。
