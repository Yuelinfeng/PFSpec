# GaussianGPT 官方 Target：Position / Feature 实践评测计划

日期：2026-10-08。状态：方案已整理，评测程序与实验尚未执行。本文承接用户提供的计划，作为本对话后续实施依据。

## 1. 目标与结论边界

目标是独立评价官方 Target 的 Position（P）和 Feature（F）预测能力，再定位当前 Draft 的差距。先保持两个模型权重不变，不开展新训练或新增投机算法。

要分别回答四个问题：

1. **预测能力**：在真实验证数据的已知前缀上，Target 能否给真实 P/F 足够高的概率？用准确率、NLL 和校准表现回答。
2. **分布集中程度**：在真实前缀和 Target 自生成前缀上，概率分散在多少个候选中？用熵、Top-K mass 和候选数量回答。
3. **Draft 差距**：相同前缀上，Draft 与 Target 的最终采样分布相差多少？用概率重叠和真实投机接受计数回答。
4. **生成效果**：P/F 的 token 误差会造成多大的三维内容偏差？需要几何、解码或渲染证据。

高熵只说明模型给出的分布较分散；低接受率只说明当前提议分布与 Target 存在差距。两者都不能单独证明 Target 质量差，也不能证明小模型无法学会。Target 质量问题与 Draft 拟合问题可以同时存在。

建议顺序为：运行对象确认 → P0 数值验证 → P2 小规模生成统计 → P1 真实验证集评测 → P2 扩大样本 → P3 Draft 对比。P1 的数据准备可与 P2 独立推进。需要评价三维质量时补做 Q1 解码对照。

## 4. 分布、标签和统计口径

### 4.1 三种主分布

在同一个完整前缀上派生三种分布：

| 名称 | 定义 | 主要用途 |
| --- | --- | --- |
| `p_base` | 官方输出变换（包括 softcap）和槽位限制后，温度 1，无 top-k/top-p | 与官方验证 loss 对齐，评价基础预测能力 |
| `p_valid` | `p_base` 的 logits 再应用官方 Position 顺序限制，温度 1 | 量化结构限制带来的改善 |
| `p_sample` | 对 `p_valid` logits 执行温度、top-k、top-p，再归一化 | 实际生成与投机分布对比 |

主要采样设置为 `temperature=0.9, top_k=None, top_p=0.9`。补充记录温度 0.9、未做 top-p 时的真实标签 NLL，用于区分温度与截断效果；它不替代官方 loss。

官方 forward 在输出 softcap 后施加槽位限制；KV 推理另施加 Position 顺序限制。不能直接取 `lm_head` 输出作为 `p_base`。KV 返回结果已丢失不合法 Position 的原始值，不能从 `p_valid` 反推 `p_base`。依据：[官方 GPT forward](https://raw.githubusercontent.com/lupin4/gaussiangpt/031d916/model/gpt/nanochat_gpt.py)。

采样变换顺序按官方实现：温度 → top-k → top-p → softmax；top-p 保留跨越累计阈值的首个 token。使用同一算子和精度验证边界行为，禁止测量函数原地改写随后用于采样的 logits。依据：[官方采样函数](https://raw.githubusercontent.com/lupin4/gaussiangpt/031d916/model/gpt/engine.py)。

### 4.2 标签、槽位与 EOS

先读权重配置确认每个位置恰好一个 P 和一个 F，再使用 `[BOS,P1,F1,…,PN,FN,EOS]`。如果 F 数量大于 1，按 `tokens_per_latent` 和 F 子槽分组，不能按奇偶数分类。

输入 `sequence[:-1]`，标签 `sequence[1:]`；复用包装层时传完整序列，避免重复移位。BOS 不计入预测标签，EOS 单列，PAD 以及有效长度之后的行不计入任何均值。BOS 与 EOS 可以共享 ID，但语义按所在位置区分。依据：[官方模型封装](https://raw.githubusercontent.com/lupin4/gaussiangpt/031d916/model/gpt/gpt.py)、[官方 general_step](https://raw.githubusercontent.com/lupin4/gaussiangpt/031d916/model/gaussian_gpt.py)。

P 准确率只汇总真实标签为 P 的行，但候选空间仍保留 EOS；若模型提前预测 EOS，该行应计为错误。另报条件于“继续生成”的纯 P 分布，明确标为辅助结果。EOS 的概率和是否正确终止单列。

分布统计按“预测槽位”分类，EOS 行仍属于可结束的 P 槽，并另设 `label_type=EOS`。这样不会漏掉长序列末端的结束行为，也不会把结束概率当作坐标预测能力。

### 4.3 必报指标

| 类别 | 指标 | 说明 |
| --- | --- | --- |
| 真实标签预测 | Top-1/5/20 accuracy、平均 NLL、PPL | P、F、EOS 分开；PPL = exp(平均 NLL) |
| 置信度 | 最大概率均值、可靠性分箱、ECE | 观察高置信错误；分箱规则提前确定，少样本箱显示样本量 |
| 分布集中度 | 熵 H、H/log(L)、Top-K mass | K 为 1、2、5、10、20、50、100 |
| 候选数量 | 合法候选数 L、采样保留数、exp(H)、K90/K95 | 分别表示可选范围、实际保留数、熵对应数量和累计质量所需数量 |
| 限制影响 | 被 Position 顺序规则去除的 `p_base` 概率质量、真实标签是否合法 | 衡量模型自身是否学会顺序规则 |
| top-p 影响 | 真实标签保留率、保留前后集中度差异 | 不用截断后的有限样本 NLL 代替整体 NLL |
| 空间行为 | P rank gap、坐标 L1/L2 误差、occupancy、长度、EOS 倾向 | 坐标误差在预测和标签均为 P 时统计，同时报该子集比例 |
| F 使用情况 | code 频次、活跃 code 数、重复率 | code ID 无几何距离意义，不用 ID 数值差评价相似度 |

所有对数使用自然对数。H/log(L) 的 L 来自显式合法集合，避免把数值下溢误判为非法；L=1 时定义归一化熵为 0，L=0 作为异常。`p_sample` 同时报相对结构合法集合和相对截断保留集合的归一化熵，列名注明分母。exp(H) 与保留候选数分别报告。

若合法性规则排除了真实标签，保留该异常及计数；相应 NLL 为无穷大，先定位数据与排序问题，不能静默丢掉后报告有限均值。top-p 排除真实标签时仅在保留率中反映，官方 NLL 使用 `p_base`。

## 5. P0：验证测量实现

**输入**：官方 Target、3–5 条短序列、人工概率向量和边界 token 序列。没有真实验证数据时，可用生成序列验证实现，但不能据此评价真实数据预测能力。

| 验证项 | 实践方法 | 完成标准 |
| --- | --- | --- |
| 序列移位 | 展示前两对 P/F、EOS 的输入、标签、槽位及有效长度 | 逐项一致，BOS/PAD 未参与计数 |
| loss 重建 | 同一 batch 比较 `general_step`、返回 logits 的 CE、按类型加权 CE | 按有效 token 数加权后与官方标量一致 |
| P/F 范围 | 首 P、F、最后一个合法 P、仅剩 EOS、不同长度带 PAD batch | 不合法项概率为 0，合法行和为 1 |
| Position 顺序 | 用官方 rank map 验证 xyz/xzy 与边界位置 | 排除 rank 小于或等于前一 P 的候选；EOS 仍可选 |
| KV 与整段前向 | 对相同完整前缀，临时关闭运行实例的顺序限制，比逐 token、分块与整段输出 | 同一槽位有限 logits、概率和 NLL 在精度允许范围内一致 |
| 顺序限制复现 | 再开启限制，对比官方逐 token KV 与评测侧逐行限制 | 候选集合完全相同，概率数值相符 |
| 概率函数 | 人工分布验证熵、Top-K、top-p 边界与零概率 | 有解析答案；无 NaN；Top-K mass 随 K 单调不减 |
| 旁路观测 | 相同环境、seed、形状，观测开启/关闭各生成一次 | token stream 一致，观测未额外消费采样随机数 |

建议 FP32 下同输入同路径的标量绝对误差目标为 `1e-5`、相对误差 `1e-4`。BF16 或不同 attention 路径先在 P0 记录最大与 P99 差异，再确定可解释的容差；不能只扩大容差让异常通过。不同路径的近并列 Top-1 可以变化，须同时看概率差。

loss 重建公式为 `(NP·NLLP + NF·NLLF + NEOS·NLLEOS)/(NP+NF+NEOS)`。官方日志如采用 batch 均值再平均，应另外复现其归约方式，不将其与整套数据的 token 加权平均混为一项。

KV 分块回放必须保留历史 token、cache 位置、前一个 P 与 3D RoPE；分别验证块边界落在 P 后与 F 后的情况。先证明分块与逐 token 相符，再用于长序列。

**产出**：`p0_validation.json`，含实际误差、边界案例和失败原因。对齐、候选范围或概率计算仍有错误时，先完成相关实现再统计正式指标。

## 6. P1：真实验证数据的预测能力

**输入**：与官方 VQ-VAE 配对的验证 token、固定样本清单、P0 已验证的测量程序。

Teacher forcing 指每一步都提供真实历史 token。逐行计算 `p_base`、`p_valid`、`p_sample`；P/F/EOS 分开，输出第 4 节指标。Feature 此时条件于真实位置和真实历史 Feature，不能解释为自由生成时的整体 F 质量。

增加两类低成本参照：按当前合法集合的 uniform；仅由训练集估计并平滑的 unigram。若训练数据可用，加入已有 Position gap/n-gram。它们帮助判断 Target 相比简单统计学到了多少；不是决定模型好坏的统一分数线。

对 Position 重点报告限制前后的变化。如果 `p_base` 经常把大量概率放在过去的位置，而 `p_valid` 表现很好，应明确写出结构规则贡献较大。Feature 在相同前缀上的 `p_base` 与 `p_valid` 应相同；如果有差异，优先排查测量实现。生成途中 Position 的变化会间接改变后续 Feature，这属于另一种比较。

对 F 报告：相对 unigram 的 NLL 改善、准确率、真实标签概率分位数、高置信错误比例，并按训练频次、上下文长度和 occupancy 分组。低频 code 组要显示样本量。

主分组使用上下文区间 `[0,256)`、`[256,1024)`、`[1024,4096)`、`[4096,8192)`、`[8192,16384)`；P gap 分组只用于有前一个 P 的位置。真实 occupancy 与生成时的已生成点数比例分开命名。

**完成标准**：5 场景全流程成功 → 50 场景得到资源与方差估计 → 全部可用场景正式统计。无法确认 token 数据配对时，将结果标为重新编码数据上的评测，不能宣称严格复现官方验证集结果。

**数据缺失分支**：先完成 P0/P2；记录 P1 尚缺 tokenized 验证数据。若只有原始 Gaussian，可在后续明确数据来源后单独规划编码；本轮不自动下载大数据或启动编码。

## 7. P2：Target 自生成前缀的可预测性

**输入**：官方 Target；20/100 个预先列出的 seed；主要采样参数；仅 BOS 起始。其他 prompt 任务另成实验组。

第一步用官方引擎生成，保存完整 token stream、seed、采样参数、终止原因和最后的 token 类型。第二步按同一 token stream 回放，计算每个前缀的三种分布及指标。优先采用“生成后回放”，减少对官方生成路径的侵入；记录生成耗时与测量耗时两项。

回放获得 `p_base` 的办法是在评测实例上临时关闭 Position 顺序限制，保留完整上下文和官方其余计算，再用官方方法派生 `p_valid`。全套生成始终沿用原设置。P0 须证明该派生分布与原生 KV 推理一致；不能把已经被限制的概率当成基础分布。

第一轮最多生成 16,000 个新 token，遇 EOS 提前结束。每个 seed 只运行预定次数；达到上限、首步 EOS、异常和自然结束均保留，不只收集自然结束的样本。16,000 个 P/F token 后仍可能需要一次 EOS 决策，特别是完整占据 8,000 个位置时；这种情况标为达到长度上限。若另做 16,001 上限的结束专项，单独命名并确认 BOS 与总上下文长度仍符合模型要求。

P2 不报告 Ground-truth Accuracy。Target 自己采样 token 的 NLL 或 argmax 匹配比例仅作为采样过程描述，不用它证明预测质量。

**主产出**：P/F 的三种分布 Top-K mass 曲线、熵分布、K90/K95、候选数、P gap、F code 使用情况、EOS 概率随长度变化、自然终止比例和长度上限比例。对同一组前缀做限制前后比较；若更换生成温度或 top-p，必须生成独立实验组，不能把重算概率当作新策略的自生成结果。

**完成标准**：20 seed 给出第一轮集中度判断与资源预算；100 seed 给出正式统计。长序列区间同时报告仍在生成的序列数，避免把少量幸存序列的末端指标解释为全部样本规律。

## 8. P3：Draft 差距与实际接受率

P0–P2 已形成 Target 结果后开展。权重不更新，优先复用已有 overlap 与联合解码入口，先核实它们的前缀、采样与计数定义。

### 8.1 相同前缀上的静态比较

对 P1 真实前缀、P2 Target 生成前缀分别计算：

`alpha(h) = sum_x min(p(x|h), q(x|h)) = 1 - 0.5 * sum_x |p(x|h)-q(x|h)|`。

p 使用实际 Target 采样分布，q 使用实际提议器采样分布。两者的 token 语义和合法性需一致；温度、截断参数可以因实际算法不同而不同，必须如实记录。不能在计算重叠时把 q 换成一个与实际提议不符的分布。

F 比较时 Target 与 Draft 必须看到同一个当前 P 以及完整历史。在同一真实前缀比较是一项实验；在 Draft 候选 P 下比较是另一项，分别保留。

| 比较对象 | 用途 |
| --- | --- |
| Target 对自身 | 同一前缀、同一分布时重叠为 1，验证计量 |
| Uniform / 平滑 unigram | 无上下文或简单频率参照 |
| 现有结构化 Position proposer | 验证 P 的低成本提议能力，F 不填写伪造值 |
| 当前生产 Draft / S13b 等 | 按权重和训练版本分列，定位实际差距 |
| Oracle Top-K | 使用 Target Top-K 支持集的理论参照 |

已有结构化 P-only 路线的 F 诊断可能来自零 logits 占位，该值不能解释为结构化模型的 Feature 能力。参见 [Position 实现说明](POSITION_ONLY_IMPLEMENTATION_REPORT_2026-10-08.md)。

Oracle 定义为 `qK(x)=p(x)/MK`（x 在 Target Top-K 内），其余为 0，故重叠恰为 MK。它也给出单次提议分布仅支持 K 个 token 时的最佳重叠。它调用 Target 分布，无法用来证明实际提议成本低，也不直接等于多分支验证的速度收益。

高熵 Target 仍可与 `q=p` 达到重叠 1；不能从 Top-K mass 推导所有神经 Draft 都受相同上限约束。

### 8.2 真实投机运行

在现有解码实现上用 5 seed 短试，再按至少 20 seed、短/中/长三个上限试验。上限建议为 256、2,048、8,192；自然 EOS 提前结束照常保留。此阶段需估算预算后再确定正式数量。

分别保存 P 提议/验证/接受数、P 已接受时的 F 提议/验证/接受数、成对接受数、连续接受长度、拒绝位置和重采样次数。报告 `F接受数/F实际验证数` 与 `成对接受数/PF对提议数`，标明因前一步拒绝而未验证的 F 数量。

静态重叠的均值与真实路径的接受率可能不同，因为访问的前缀与 F 被验证的条件不同。不能要求两者机械相等；针对真正访问的验证前缀补算重叠后再解释差异。

如同时测速度，另跑关闭详细逐 token 观测的纯 Target 与投机路径，统一计时范围、精度、预热、CUDA 同步、输出长度口径和结束规则。区分固定长度计算成本与自然结束吞吐，记录实际输出数；相同 seed 不保证不同采样算法输出相同。先前不对称逐前向同步的入口不得直接用于速度结论。

## 9. Q1：需要评价三维生成质量时的补充实验

P1–P3 能回答 token 预测和分布匹配问题。若最终结论要涉及“Target 本身生成不好”，补充本阶段，先选 10 个预定验证 chunk；发现趋势后扩大到 30–50 个场景。

| 组别 | 输入与处理 | 可回答的问题 |
| --- | --- | --- |
| A：真实 token 解码 | 真实 P + 真实 F，经同一 VQ-VAE 解码 | 表示与解码器本身能保留多少原始内容 |
| B：固定真实 P 生成 F | P 依次使用真实值，F 从 Target 采样；后续历史 F 使用已生成值 | 排除位置选择变化后，F 累积生成造成多大偏差 |
| C：真实前缀补全 | 使用同一真实前缀，自由生成剩余 P/F；前缀取完整 P/F 对 | P/F 联合续写的误差传播与终止行为 |
| D：自由生成 | 使用 P2 已保存的序列解码 | 无条件生成的几何有效性、多样性与视觉质量 |

B 是受真实 P 引导的诊断实验，不能当作官方无条件生成表现。可另设全部历史 F 也用真实值的逐点版本，区分单步 F 误差与累积影响。

几何指标至少含坐标越界/重复、有效点数与 occupancy、空间覆盖和连通情况。B 与 A 使用相同位置时，可比较解码属性与固定相机的渲染差异；原始 Gaussian 和相机齐备时，再加入 A 对原始输入的比较，估计表示损失。

Chamfer、PSNR/SSIM 等仅在坐标、相机和对应关系成立时使用。C 的续写与 D 的自由生成允许多种合理输出，不能把对一个任意真实场景的逐点误差当作质量分数。无配对输出使用有效性、分布统计、多样性及一致视角的样本展示，并说明样本规模限制。

不凭低 code 准确率推断视觉失败：不同 code 的解码效果可能接近。若只有 token 数据而缺少原始场景，仍可比较 A/B，但无法评价原始内容在 VQ-VAE 中损失了多少。

## 10. 统计与结果判读

同时给出两种聚合：所有有效 token 加权的 micro；先在 chunk 内统计、再在场景内平均、最后场景等权的 macro。PPL 从相应聚合后的 NLL 取指数，不直接平均 token PPL。

P1 以场景为重采样单位，保留该场景全部 chunk；P2 以 seed/序列为单位；真实前缀启动的多 seed 续写按原场景聚类。使用固定统计种子做 2,000 次 bootstrap，给出 95% 区间；模型或分布差异使用配对重采样。5 场景试跑的区间仅作描述。

每项结果显示有效 token 数、场景或序列数、分位数和缺失数量。按序列末段、occupancy、频次等分组时报告每组样本量；不要根据少量尾端 token 排名。

| 观察 | 支持的判断 | 下一步 |
| --- | --- | --- |
| F 真实数据 NLL 明显优于简单统计，Target 自生成时质量可接受，但 Draft 重叠低 | 当前 Draft 拟合仍有明显空间 | 定位高差距上下文、频次与训练覆盖 |
| F 概率集中，当前 Draft 未覆盖主要质量 | 候选选择或概率拟合存在差距 | 比较训练目标与候选召回，之后再决定训练 |
| 小 K 的 mass 较高 | 小候选集合值得研究 | 测量实际候选器的质量、成本和可验证长度 |
| F mass 分散，低成本提议器重叠低 | 当前候选数量与提议器能力不足 | 优先保留已有效的 P-only 路线；不宣称通用不可学习 |
| P 的基础分布差、施加顺序规则后大幅改善 | 高 P 可预测性部分由结构限制提供 | 分别评价模型学习与规则贡献 |
| P-only 简单提议器在独立场景保持接近现有接受率且更快 | 结构化低成本路线得到更强支持 | 扩大独立场景的速度验证 |
| F 真实数据预测弱，且 Q1 的 B 明显差于 A | Target 的 F 建模或数据匹配值得优先调查 | 核对分布偏移、编码配对与模型来源，再讨论训练 |
| A 已明显差于原始 Gaussian | 表示或解码器存在质量损失 | 不把全部损失归因于 GPT |

预先不设“熵超过某值就差”“Top-1 低于某值就不可用”的通用标准。模型好坏依据真实数据参照、配对差异、质量证据和实际用途共同判断。纯推理评测无法证明低成本模型的能力上限；若要回答可学习性，需要后续在独立训练/验证数据上进行受控的小模型实验。

## 12. 资源预算、阶段交付与停止位置

RTX 4090 起步采用 batch size 1、逐段回放 256 token，测量后可调为 512；KV 保存完整历史。全长 16,384×12,098 的单份 FP32 logits 约 756 MiB，512 行约 23.6 MiB；三种完整分布及排序中间量会进一步增加占用。因此每段算完只保存标量指标和必要的 Top-K 信息，释放完整概率张量。生成与 Draft 比较分阶段加载模型，记录峰值显存。

P0 比较整段前向仅用短序列。长序列先验证 KV 回放的等价性；若当前 attention 路径不支持正确分块，退回逐 token KV 回放，不把每个片段独立输入。首批实测给出每千 token 的生成/回放耗时、峰值显存和每序列文件量，再按实际总 token 数估算正式预算；本计划不预报未经测量的完成时长。

| 交付 | 具体输出 | 完成后可判断什么 |
| --- | --- | --- |
| D0：对象与数据就绪 | 运行配置、现有评测模块清单、可用数据分级 | 是否可做严格 P1，是否需要补数据 |
| D1：P0 | 数值验证报告 | 测量口径是否可靠 |
| D2：20-seed P2 | 分布集中度与资源统计 | F 概率是否集中在少量候选 |
| D3：P1 + 100-seed P2 | Target 独立评测报告 | 真实数据预测与自生成分布有何差别 |
| D4：P3 | 相同前缀的差距与真实接受计数 | 当前 Draft 差在何处 |
| D5：Q1（质量结论需要时） | 解码对照、几何与渲染证据 | token 误差是否显著影响三维内容 |

数据缺失时继续做不依赖数据的阶段；数值对齐失败时停止相关统计并保留失败样本；显存不足时降低回放块大小；来源或版本不明确时限制结果的声明范围。所有已完成产物保留，不覆盖已有实验。

本计划当前仅新增文档，不改变权重、环境、源码或远端作业，不刷新自动状态页。后续代码、环境或实验产物变化后，按项目约定更新相关长期文档并运行状态生成脚本。
