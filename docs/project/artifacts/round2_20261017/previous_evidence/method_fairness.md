# Medusa-style 与 Hydra-style 方法对照（2026-10-17）

## 比较条件

使用同一 GaussianGPT Target、Position Ranker 与精确 Target 验证/残差采样。测量覆盖 10 个开发来源、前缀 64/256/1024（有足够 token 时）、种子 54751/54752、FP32、temperature=top-p=0.9、每次最多新增 256 token，共 336 条记录。六条解码路径都先通过单来源 32-token GPU 烟测，输出长度、P/F 类型顺序和 Target 缓存位置均通过。

三个新草稿使用同一批 40 条 Target 轨迹，按完整轨迹划分训练与验证。Feature MLP 有 16,348 个训练样本和 2,044 个验证样本；低秩 Medusa-style 有 16,312 和 2,040；Hydra-style 从同一批轨迹抽取 18,352 个 P/F/P 锚点。每种模型训练 10 轮，参数量控制在约 2.86M。

## 接受分支

P-only Position 接受为 6,085/6,779（89.76%）。step12000 PF-K2 的 Position 接受为 5,968/6,670（89.47%），Feature 接受为 1,548/4,497（34.42%）。同轨迹 Feature MLP 的 Position 接受为 5,810/6,594（88.11%），Feature 接受为 960/4,873（19.70%）。

低秩 Medusa-style 的 P1 接受为 52/6,675（0.78%），F1 在 P1 接受后为 9/52（17.31%）；记录到 9 次 P2 校验，接受数为 0。Hydra-style 的 P1 接受为 30/6,567（0.46%），F1 为 3/29（10.34%），P2 为 2/3。低接受率使多头方案频繁回到 Target 单步生成。

## GPU 草稿与验证耗时

另取 3 个开发来源、可用的 64/256/1024 前缀和一个种子作 CUDA event 分项测量，共 8 条记录/方法。该分项测量用于解释成本，不替代上表无埋点速度。

| 草稿 | 草稿 GPU 时间 | Target 校验调用 / 草稿轮 |
| --- | ---: | ---: |
| step12000 PF-K2 Feature MLP | 0.480 ms/次 | 1.009 |
| 低秩 Medusa-style | 1.562 ms/轮 | 1.994 |
| Hydra-style | 2.181 ms/轮 | 1.995 |

两种多头草稿单次提案开销较大，且 Target 校验调用数约为 PF-K2 的两倍。其 Target 单次前向时间约 15.7 ms；PF-K2 单次验证约 17.8 ms，但 PF-K2 每轮推进更多 token，累计 Target 调用更少。Position Ranker 的评分在 CPU 执行，另按 Host 时间记录。

## 方法选择与范围

本轮独立确认采用 step12000 PF-K2。结果支持“轻量 P/F 组合优于两种等参数量多头方案”，不支持多头方案带来额外加速。草稿 GPU 时间差距也说明参数量接近不能代表推理开销相同；本轮未另训低参数量的等延迟多头模型。

EAGLE-style 已有的链缓存等价结果通过，2,048 个状态的策略等价验证通过。保存的 BF16 EAGLE checkpoint 在 16,360 个教师强制行上的分布重合均值为 0.0371；Gamma=2 时的期望接受量为 0.0379，连续全接受概率代理为 0.000825。该多步数值是教师强制代理，不是采样式在线解码结果。由于开发信号很弱，本轮没有继续做 EAGLE 在线速度测试；其准确在线速度仍未测得。
