## 结构和状态对齐

A/B 均为 1 层、宽度 256、4 头、ReLU² MLP、四维 `(x,y,z,slot)` RoPE，共 1,572,864 个可训练参数。直接复用原 GPT 的因果 Block、RoPE、KVCache。Target 词嵌入和输出权重共享引用，保持参数不变。

每个位置使用 `(h_t, actual_token_(t+1), coordinate_(t+1))` 预测最终归一化状态 `h_(t+1)`，再由原输出权重和 softcap=15 得到下一 token 的分布。输出采用原状态加预测增量，再做 RMSNorm。A 计算 P/F 分类；B 只计算 F 分类，两者都消费 P/F 并回归两类输入之后的状态。P 分类使用 8,000 个位置和 EOS；F 分类使用 4,096 个特征。合法位置服从原空间顺序。

Draft 每轮根据已经由 Target 消费的真实历史重建自身 KV，然后沿候选递推。默认使用完整历史，重建时间计入总时间；`--draft-context` 可缩短历史，但本轮主比较取 0，即完整历史。该方案优先保证状态含义明确，长序列的重建成本仍需单独评估。

## 推理阶段和概率

所有候选窗口从 Position 槽开始。B 的 P 来自已有确定性 Ranker，实际 `q_P` 为单点分布；F 来自当前 Draft 的实际温度和 top-p 分布。A 的两类候选均来自 Draft。Target 使用相同温度 0.9、top-p 0.9。逐个按 `min(1,p(x)/q(x))` 接受，首次拒绝时从归一化的正残差 `(p-q)+` 采样。greedy 使用 Target argmax。

Target 以一次因果前向消费待处理 token 和本轮候选。仅保留已接受候选的 KV。拒绝后的替代 token 保留在输出前缀中，等下一次 Target 前向消费；替代 P 需要先由 Target 消费，再采样 F，随后开始下一 Position 窗口。F 拒绝可以直接进入下一 Position 窗口。完整接受的奇数窗口由 Target 额外采样 F；这个 F 仍待下一次 Target 消费。偶数窗口的额外 P 进入相同 P→F 恢复过程。EOS 只能结束 Position 槽，随后停止。

B 的 γ=1 完全跳过 Feature Draft，代表 Ranker-only 对照。Bonus P/F 单独计数，不进入候选接受率分母；候选率使用 accepted/verified。总时间包括缓存分配、预填、Ranker、Draft 历史重建、候选、Target 验证、恢复和采样。逐项同步计时另存，避免混用其耗时计算主速度。

## 数据和训练

真实数据来自既有 `stage_d2_adaptation/stage_c/adaptation_pool_crops.pt`：19 个场景、36 个裁剪，含 BOS 共 42,272 token。按场景分为 16 个训练来源和 3 个验证来源，共 163/22 个长度至多 256 的窗口。36 个裁剪均不含自然 EOS，训练没有人为添加结尾标签，因此本轮没有学习自然 EOS 的充分证据。

本轮三个在线开发来源与上述 19 个来源没有重合。训练、验证来源之间也没有重合；场景划分与逐次记录均有留存。

Target 以 FP32 提取最终 RMSNorm 状态。A/B 使用相同初始化种子、窗口抽取顺序、AdamW、学习率 `3e-4`、权重衰减 0.01、梯度范数上限 1.0，各完成 4,000 次更新、913,302 个状态监督位置。损失为 P/F Smooth L1 之和，加 0.1 倍分类 CE；A 计 P/F，B 只计 F。

随后各追加 100 次 γ=3 短 rollout，学习率 `3e-5`。从训练来源取 128-token 前缀，让当前提案器提出真实候选；Target 重新消费候选前缀，得到对应状态和软标签。递推使用预测状态，保留跨候选梯度，不借用原场景的后续标签。两者最终选用的都是 rollout 权重。该阶段仅覆盖很短的候选前缀，不能代表长链训练。

所选验证损失 B=1.000196，A=1.834055。A/B 分类任务不同，总损失不能跨方案比较。4,000 步末尾真实 F CE 已变差，说明增加更新次数没有持续改善该小数据训练；保留按验证集选择的权重。首轮 600 步产物也保存在独立目录。

## 复现入口

在远端主工程及既有环境执行。已保存状态可直接复用，下面输出路径应换成新的实验目录，避免覆盖已有结果。

```bash
python -m unittest test_pf_eagle -v
python train_pf_draft.py --data <states目录> --output <新训练目录> \
  --steps 4000 --window 256 --validate-every 500 --rollout-steps 100
python eval_pf_draft.py --training <训练目录> --output <新评测目录> \
  --scenes 3 --prefixes 64 256 --seeds 34701 34702 --budget 128 --old-pf
python generate_pf_scene.py --training <训练目录> --output <新三维目录> \
  --prefix 256 --gamma 3
```

主评测使用既有开发集的三个来源、两种前缀、两个随机种子；这些来源已经参与过历史开发，不能视为新的独立确认集。旧 PF 载入 `draft_a/runs/feature_target_continue_20261014/selected.pt`，通过其原有解码入口测量，保留已有 Ranker 和输出头。

三维入口采用既有单 chunk 评价的坐标、相机和 scale 显示裁剪 `[1e-4,0.05]`。NPZ 保存的是用于该显示流程的 Gaussian 参数。总三维时间从准备好 token 开始，包含自回归、VQ、NPZ 与六张 PNG 写入，模型加载不计入。它与只含 token 解码的主表采用不同范围。

## 在线开发结果

完成 108 次主运行，每种方法 12 次，每次最多生成 128 token；本轮均产生 128 token，共每种方法 1,536 token。表中吞吐按总 token / 总秒数计算，速度比以同轮串行 Target 为参照。它包含前缀预填时间，不代表纯稳态吞吐。原始输出、逐次时间、计数和分项数据在 [产物目录](artifacts/eagle_pf_v2_20261019/)。

| 方法 | token/s | 对 Target 速度比 | P 接受率 | F 接受率 |
| --- | ---: | ---: | ---: | ---: |
| Target | 71.424 | 1.000× | — | — |
| B γ=1，Ranker-only | 95.867 | 1.342× | 87.109% | — |
| B γ=3 | 86.645 | 1.213× | 83.854% | 21.587% |
| B γ=5 | 78.617 | 1.101× | 88.411% | 18.389% |
| B γ=4，偶数窗口 | 80.684 | 1.130× | 88.102% | 18.058% |
| A γ=1 | 58.553 | 0.820× | 1.823% | — |
| A γ=3 | 52.758 | 0.739× | 2.214% | 17.647% |
| A γ=5 | 47.806 | 0.669× | 1.823% | 7.143% |
| 旧 PF | 115.873 | 1.622× | 87.630% | 36.948% |

B γ=3 / Ranker-only 为 0.904×，B γ=3 / 旧 PF 为 0.748×。B γ=3 的 F 接受数为 117/542；A γ=3 的 F 接受数只有 3/17，后者样本少，不能把百分比接近解释为同等的 F 能力。A γ=3 的 P 接受数为 17/768，首次拒绝集中在 P；共 1,528 次 Target 调用，接近串行的 1,536 次，额外 Draft 计算使它变慢。

B γ=3 共 652 次候选验证和 124 次恢复前向，加 12 次预填，总 Target 调用 788；每次候选验证平均推进 2.356 token。全接受产生 102 个额外 F，均单独记账。γ=1 没有任何 Draft 调用，不能用其速度支持新 Feature EAGLE。旧 PF 的计数字段来自原入口，不具备本轮 `verify_calls`/`recovery_calls` 拆分，相关缺省值不能解释为没有调用 Target。

分项运行均复现未分项运行的输出。一个 64-token 前缀样本上，B γ=3 的 Draft 历史重建、消费 P、消费 F、分类合计约 93.5 ms；Target 验证约 459.3 ms，恢复约 91.0 ms。该同步分项样本只用于定位成本，主表使用无逐项同步的运行。γ=3 在本轮优于 γ=5 和 γ=4，但当前证据不支持新 EAGLE 优于 Ranker-only 或旧 PF。

## 验证与尚存限制

六项核心测试已通过：真实因果模块增量/整段一致、未来输入不可见、训练目标类型与梯度、A/B 在 γ=1–5 的 greedy 对齐、随机接受与残差分布、P/F 拒绝恢复及 EOS。真实 Target 分块/整段策略分布最大总变差为约 `2.17e-6`，A/B 的短 greedy 输出与串行 Target 一致。采样数学测试采用 5,000 次抽样；这些证据支持当前实现，不能替代全部长场景统计。

最终复测六项测试耗时 1.790 秒；108 条记录、每方法 12 次、同训练预算、γ=1 零 Draft 调用、分项重放一致与数据来源分离均通过验证，详见 [验证记录](artifacts/eagle_pf_v2_20261019/verification_report.json)。作业结束时 GPU 使用率为 0%、显存占用 2 MiB。

本轮是单一训练种子的开发实现。训练场景少、缺少自然 EOS、短 rollout、Draft 历史重建成本，以及缺少新来源上的质量评价，均限制性能结论。完整样本的 EOS 由 Target 保证，不能据此推断 Draft 已学会自然结束。旧生产权重保留。
