# G5 新来源在线评测与阶段判断

日期：2026-10-17  
状态：评测完成；按预设条件停止在 D1，未启动 T 来源测量。

## 目的与判定条件

G5 在 10 个此前未用于该方法筛选的开发来源上，比较 P-only、固定 PF-K2 与 Position 间隔选择策略。实验启动前已写明：只有当 D1 的 2,048-token Gap/PF 来源几何平均不低于 1.02，且来源级 bootstrap 95% 区间下界大于 1.00，才进入 G6。

## 数据与运行范围

- D1：10 个新开发来源；每个来源一条 Token crop，包含 64 和 256 两种前缀。
- T：另选 30 个来源，与 D1 及此前分配的来源组不重叠；未用于本次速度测量。
- 512-token：20 个上下文 × 3 个种子 × 3 种方法，共 180 次。
- 2,048-token：10 个 256-token 前缀 × 3 个种子 × 3 种方法，共 90 次。
- 另完成 24 次冒烟运行。全部使用 FP32、temperature=0.9、top-p=0.9。
- 计时含解码调用、Target KV cache 分配及前缀预填充；不含模型和 crop 载入。区间以来源为抽样单位，使用 10,000 次 bootstrap 重采样。

远端评测根目录：`/root/autodl-tmp/gaussiangpt_gap_selection_20261017/g5_d1_full_assets_final/`。本地原始记录保存在本目录的 `g5_raw/`。

## 结果

| 窗口 | Gap / PF-K2 | 来源胜出数 | Gap / P-only | PF-K2 / P-only | Gap 路由中的 PF 占比 |
| --- | ---: | ---: | ---: | ---: | ---: |
| 512 tokens | 1.009× [0.981, 1.036] | 7/10 | 1.185× [1.158, 1.212] | 1.174× [1.141, 1.210] | 74.34% |
| 2,048 tokens | 1.018× [0.990, 1.048] | 6/10 | 1.136× [1.113, 1.161] | 1.116× [1.094, 1.136] | 73.27% |

512-token 分层结果显示：前缀 64 的 Gap/PF-K2 为 1.025× [1.003, 1.045]，9/10 来源更快；前缀 256 为 0.993× [0.953, 1.038]，4/10 来源更快。这些是范围诊断，不能代替预设的长窗口主指标。

两种窗口中，Gap 与固定 PF-K2 的速度差都未形成明确证据。Gap 相对 P-only 有稳定优势，但固定 PF-K2 也具备相近优势；因此本次结果没有证明空间间隔选择能持续提高固定 PF-K2 的实际速度。

## 阶段判断

预设主指标为 1.018×，低于 1.02 的实际收益门槛；95% 区间下界为 0.990，未高于 1.00。判定条件未满足，结果记录为 `stop_before_T`。依据原计划，不开展 G6 的 T 来源确认，也不启动依赖该确认的 G7 完整单 chunk 三维评测。

这表示当前证据不足以支持将 Gap 选择作为固定 PF-K2 之上的稳定加速方法。结果仍说明：在本批 D1 来源上，加入 Feature Draft 的 P/F 路线整体快于 P-only；Gap 路由的 PF 使用率约为 73%–74%。后续若重启此方向，需要另行提出实验依据和预先写明的新判定条件。

## 完整性与限制

汇总脚本确认短、长窗口分别有 180 和 90 条有效记录，涵盖所有来源、上下文、种子与方法组合；生成长度、输出 token 数、EOS 标记和耗时字段一致。24 次冒烟运行通过。远端模型、权重和主工程源码未修改。

D1 仍是开发来源，不能视为独立确认。Target 训练来源清单不含完整场景 ID，因此无法完整判断预训练来源重叠。此次没有测量 VQ 解码、Gaussian 导出、渲染或完整场景质量。
