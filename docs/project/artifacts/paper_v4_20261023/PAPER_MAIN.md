# PFSpec：利用 Position–Feature 条件结构加速自回归 Gaussian 生成

## Abstract

自回归 3D Gaussian 生成通过交替预测空间位置（Position）与离散场景特征（Feature）构造三维场景，但逐 token 的串行计算限制了生成效率。本文提出 PFSpec，将 P/F 条件结构直接用于组织投机解码中的草稿计算。其核心是：利用合法空间候选与位置历史完成位置提案，并复用已有 Target 隐藏状态，直接预测下一候选位置对应的 Feature 分布。由此，Position Ranker 与条件 Feature MLP 构成一条无需逐 token 维护神经草稿历史缓存的短 P/F 路径，Target 则保留完整条件历史进行并行验证。进一步地，Position Rescue 在同次验证中预计算备用位置的条件状态，在原残差采样命中时替代串行恢复前向。我们分析有效推进、恢复调用与验证成本的关系，并给出目标分布和参考轨迹保持的适用条件。在 RTX 4090 上，PFSpec 相对采用相同执行优化的 GaussianGPT Target 获得约 **1.58× 解码吞吐**。在单 Chunk、512-token 上限、包含 VQ 解码与渲染保存的请求中，完整实现相对原 Target 获得 **4.31× 请求加速**，该结果包含共享执行优化及实际输出长度差异。此外，基础 P/F 路径在自然 EOS 的场景补全与 BOS 生成中完成三维解码、导出和渲染，支持该计算安排在完整单 Chunk 生成中的实际价值。

## 1. Introduction

自回归建模支持三维场景的逐步构造与条件补全。GaussianGPT 将 3D Gaussian 压缩为稀疏离散表示，交替生成空间占据位置 Position 与对应场景特征 Feature。完整单 Chunk 输出可能需要数千个 token，串行 Transformer 调用因而成为生成延迟的重要来源。[GaussianGPT](https://arxiv.org/abs/2603.26661)

投机解码通过廉价提案和并行验证摊薄 Target 的串行执行成本。[Leviathan 等](https://proceedings.mlr.press/v202/leviathan23a.html) 三维表示也为计算安排提供了依据：FlashMesh 利用 Mesh 层级与顶点共享，XSpecMesh 结合多头草稿与主干验证。[FlashMesh](https://arxiv.org/abs/2511.15618)、[XSpecMesh](https://proceedings.mlr.press/v306/chen26dn.html) 对 GaussianGPT，更具体的问题是：当两类 token 能够廉价取得的条件信息不同，草稿计算应如何分配？

P/F 表示提供了两种互补资源。合法空间顺序与位置历史支持从小集合中排序位置候选；已有 Target 状态则为位置条件的 Feature 预测提供近似依据。由此，短 P/F 路径中的两个 Position 可以先于 Feature 起草确定，神经预测只需直接估计中间 Feature 所需的候选位置状态。Target 对每个候选仍使用完整条件历史。提案侧的简化改变了构造候选路径所需的计算，标准接受与残差重采样则保持目标采样规则。

本文研究的问题是：**如何组织这两种资源，提高单位实际执行成本下的有效生成推进？** PFSpec 将 Position Ranker 与条件 Feature MLP 结合：前者选择合法位置，后者利用已有 Target 状态、上一 Feature 和候选 Position 预测状态残差，并复用 Target 输出头构造 Feature 提案。两者形成可联合验证的短 P/F 路径，省去部分中间神经草稿状态推进与跨轮独立草稿历史缓存。设计重点在于将空间排序与状态辅助预测分配到各自承担的提案工作。

实验沿位置投机、Feature 增量、状态输入消融以及较宽和较重草稿依次评价这一安排。已测的扩宽或加重配置可以提高推进或接受率，却同时降低吞吐，说明候选收益需要覆盖实际成本。对同一短路径的分析进一步揭示了拒绝后的串行依赖：位置拒绝后，Target 仍需处理残差采样得到的位置，才能生成对应 Feature。Position Rescue 提前验证一个共享历史的备用位置，在原残差采样命中时复用其条件状态。它与主路径互补，在保持参考接受事件的同时减少恢复工作。

PFSpec 相对共享执行优化的 Target 获得约 **1.58×** 解码吞吐。基础 P/F 路径在数千 token、自然 EOS 的完整单 Chunk 请求中也取得加速，并以参考图像指标和三维渲染展示输出情况。当前完整方法的自然终止增量仍未测量。本文贡献为：

1. **针对 P/F 条件信息分配草稿计算。** 以合法位置排序和候选位置状态的直接预测构造可联合验证的轻量短路径；评价 Feature 预测如何扩大已测位置投机收益，以及状态信息和草稿成本如何影响该增量。
2. **同一 P/F 解码流程中的恢复状态复用。** 通过单备用位置在残差命中时避免串行恢复，区分有效推进与免去的恢复工作，给出保持性质的条件，并评价解码行为与完整单 Chunk 输出。

## 2. Related Work

### 2.1 自回归三维生成与表示结构

MeshGPT 以量化 Mesh 表示支持自回归预测，MeshAnything V2 通过相邻面 token 化减少序列冗余；GaussianGPT 则将 3D Gaussian 场景编码为 Position–Feature 交替的稀疏离散表示。[MeshGPT](https://arxiv.org/abs/2311.15475)、[MeshAnything V2](https://arxiv.org/abs/2408.02555)、[GaussianGPT](https://arxiv.org/abs/2603.26661) 表示结构也为生成加速提供了不同入口：FlashMesh 结合层级特征预测与顶点共享一致性处理，XSpecMesh 使用多头预测及验证、重采样机制。[FlashMesh](https://arxiv.org/abs/2511.15618)、[XSpecMesh](https://proceedings.mlr.press/v306/chen26dn.html) PFSpec 保持 GaussianGPT 的序列化与 Target，利用其合法位置历史和位置条件状态组织草稿及恢复计算。

### 2.2 轻量草稿与状态预测

Medusa 从 Target 隐藏状态预测多个未来 token，Hydra 进一步将先前候选引入后续预测头；EAGLE 利用连续 Target 特征与移位 token 信息逐步预测隐藏状态，并复用输出头进行起草。[Medusa](https://proceedings.mlr.press/v235/cai24b.html)、[Hydra](https://arxiv.org/html/2402.05109#S3)、[EAGLE](https://proceedings.mlr.press/v235/li24bt.html) P-EAGLE 将起草扩展为并行多 token 预测，DFlash 以 Target 上下文特征辅助块扩散草稿。[P-EAGLE](https://arxiv.org/html/2602.01469)、[DFlash](https://arxiv.org/html/2602.06036) PFSpec 沿用条件化与状态复用的思想，将其落实到 P/F 的具体计算分工：Position 由合法候选排序产生，Feature 通过上一位置状态到候选位置状态的直接预测获得。该短路径不要求神经草稿逐 token 建立独立历史缓存。这里的 Feature 是离散场景码，隐藏状态是预测该场景码所使用的连续表示。

### 2.3 并行验证与条件状态复用

标准投机采样通过接受与残差重采样保持目标分布。[Leviathan 等](https://proceedings.mlr.press/v202/leviathan23a.html) SpecInfer 将候选组织为共享前缀的树，以祖先约束的注意力和 KV 管理并行计算各分支；SpecTr 从多候选最优传输出发，并讨论命中候选后利用已计算的下一条件分布继续抽样。[SpecInfer](https://arxiv.org/abs/2305.09781)、[SpecTr](https://proceedings.neurips.cc/paper_files/paper/2023/file/6034a661584af6c28fd97a6f23e56c0a-Paper-Conference.pdf#page=5) Position Rescue 使用这些执行基础处理 P/F 短路径中的恢复事件：保留原有主提案和残差采样，备用仅用于覆盖实际恢复位置所需的条件计算，并维持后续起草使用的隐藏状态与 KV。

### 2.4 成本感知投机与拒绝分支计算

Sequoia 综合树结构与硬件成本选择验证配置，OPT-Tree 根据草稿路径概率在线构造候选树；Learning to Draft 直接优化草稿—验证周期吞吐。[Sequoia](https://arxiv.org/html/2402.12374#S4.SS1)、[OPT-Tree](https://aclanthology.org/2025.tacl-1.8/)、[Learning to Draft](https://proceedings.iclr.cc/paper_files/paper/2026/hash/34345e243156da67605d4b63d71c8d98-Abstract-Conference.html) SpecBranch 利用回退风险组织并行分支，Speculative Speculative Decoding 在验证期间预备后续草稿。[SpecBranch](https://proceedings.iclr.cc/paper_files/paper/2026/hash/67089958e98b243d5cc1881ad60418b8-Abstract-Conference.html)、[Speculative Speculative Decoding](https://proceedings.iclr.cc/paper_files/paper/2026/hash/1b96f01343ff10150e6719eb163e1536-Abstract-Conference.html) PFSpec 关注固定 P/F 参考流程中的具体工作分配：主路径候选改变有效推进，备用 Target 状态改变恢复需求。我们的分析将这两种收益与完整执行成本联系起来。

## 3. Method

PFSpec 包括类型化短路径起草与位置恢复预计算。无备用版本记为 W1，完整 PFSpec 在 W1 上加入一个备用 Position。整个过程保持 Target 权重、序列表示与目标采样策略。

![PFSpec 的类型化起草与条件恢复路径](figures/pfspec_overview.png)

**图 1. PFSpec 的计算安排。** 位置历史产生主位置 \(a\)、后续位置 \(c\) 与备用 \(b\)，Feature MLP 从已有状态直接预测 \(a\) 的条件分布。Target 对交替主路径保留完整条件历史；备用与主位置共享前缀，原残差采样命中 \(b\) 时复用其条件状态。位置排序、状态预测和恢复预计算分别对应候选选择、有效推进和串行恢复工作。

### 3.1 P/F 生成与设计目标

GaussianGPT 的序列由交替的 Position 与 Feature 构成，EOS 在位置槽位终止生成。对正常位置和特征，给定已输出历史 \(h\)，目标联合分布为

\[
p(P,F\mid h)=p_P(P\mid h)\,p_F(F\mid h,P).
\]

本文的 \(p\) 指经过实际类型约束、合法空间顺序、温度和 top-p 处理后的归一化 Target 分布。上述分解保留 Feature 对位置和完整历史的依赖。

在一个常规轮次开始时，\(h=(\ldots,P_i,F_i)\) 已输出，Target KV 消费到 \(P_i\)，\(F_i\) 尚待送入 Target。此时可用信息包括位置历史 \(h_P\)、已生成的 \(F_i\) 以及 Target 在 \(P_i\) 后的归一化前隐藏状态 \(u_i\)。PFSpec 利用这些已经取得的信息构造下一条候选路径。

**提案信息与执行成本。** PFSpec 使用 \(h_P\) 提出合法位置，并使用 \((u_i,F_i,a)\) 预测候选位置的 Feature 分布。这是提案侧的信息选择，两类 Target 分布仍保留完整历史；尤其是先于 \(f\) 选择 \(c\)，不会从 Target 对 \(c\) 的验证历史中移除 \(f\)。设计目标是提高实际吞吐 \(v=N/T\)，同时计入有效输出及起草、验证、恢复与初始化的全部成本。短路径将神经预测用于位置条件的 Feature 步骤，备用则将额外 Target 验证用于可能需要的恢复状态。第 4、5 节分别分析并测量这些安排带来的推进、成本与实际性能。


### 3.2 类型化短路径起草

**合法位置排序。** Position Ranker 在由位置历史构造的合法候选集合 \(\mathcal C(h_P)\) 内评分，确定性地选择主位置：

\[
a=R(h_P)=\arg\max_{v\in\mathcal C(h_P)}s_\theta(v;h_P),
\qquad q_P(v\mid h)=\delta_a(v).
\]

候选生成器在 8,000 个位置码中使用短历史构造小集合：根据最近两个位置码差值、边长 20 网格中的当前位置相位及在线差值频数，合并单位差值、历史众数和少量高频差值，再按 Target 的扫描顺序映射移除非法位置。当前规则至多产生六个不同候选，无需枚举完整位置词表。候选只来自已有 Position 历史，EOS 由 Target 采样处理。

Ranker 使用直方图梯度提升二分类器，为每个候选读取 32 维历史统计，包含差值、空间索引、最近四个差值、频数、条件频率和出现间隔。训练标签表示候选是否等于 Target 采样的下一位置；采用 150 轮、每棵树最多 15 个叶子的模型。在线进度特征使用固定尺度的已生成位置序号，避免依赖最终长度。评分用于候选排序，实际提案为点分布。将 \(a\) 加入位置历史后，再得到后续候选 \(c=R(h_P\oplus a)\)。两个 Position 均可在 Feature 起草前确定。完整候选规则与训练参数见附录 C.6。

**从已有状态直接预测 Feature。** 条件 Feature MLP 利用 \(u_i,F_i,a\) 预测候选位置的状态残差：

\[
\widehat u_a=u_i+g_\phi\!\left(\psi(u_i),e_F(F_i),e_P(a)\right).
\]

其中 \(\psi\) 编码已有状态，\(e_F,e_P\) 为类型相关嵌入。随后复用 Target 的归一化层与 Feature 输出头：

\[
q_F(\cdot\mid u_i,F_i,a)
=\Pi_F\!\left(\operatorname{softcap}
\bigl(W_F\operatorname{Norm}_T(\widehat u_a)\bigr)\right).
\]

\(\Pi_F\) 包含实际 Feature 词表、温度与 top-p 归一化。抽取 \(f\sim q_F\) 后，形成 \((a,f,c)\) 主候选。该路径的提案可写为

\[
q(a,f,c\mid h)
=\delta_{R(h_P)}(a)\,
q_F(f\mid u_i,F_i,a)\,
\delta_{R(h_P\oplus a)}(c).
\]

实际预测器将 1,024 维已有状态归一化并映射到 256 维，与两个 128 维类型嵌入拼接；残差网络采用 \(512\to512\to512\to1024\) 的三层线性变换及 GELU。模型含 2,864,384 个可训练参数，复用固定的 \(4096\times1024\) Target Feature 输出权重。训练使用 Target 轨迹上的完整分布监督，并以采样策略分布的总变差距离辅助训练；模型结构、训练阶段和选择方式见附录 C.6。

这一计算分工使位置选择直接使用空间历史，神经草稿集中预测 Feature 所需的候选位置状态。草稿无需依次建立 \(F_i\)、\(a\)、\(f\) 后的全部神经状态，也无需跨轮维护独立的神经草稿历史缓存；下一轮使用实际提交路径的 Target 状态。上述分解定义了低成本提案，Target 对第二 Position 的验证仍使用完整条件分布 \(p_P(c\mid h,a,f)\)。

在一次完整候选轮中，W1 使用两次位置选择和一次 Feature 状态预测，随后执行四节点 Target 验证。Rescue 复用首次位置选择的候选评分，增加一个备用验证节点。二者的正常位置拒绝均可能触发一次恢复前向；Rescue 仅在命中首位置备用时省去该调用。这一工作量对应关系明确了省去的神经草稿状态推进，以及为并行验证支付的实际计算。

### 3.3 并行验证与主路径提交

当剩余预算至少为四 token，且 \(a,c\) 均为合法非 EOS 候选时，Target 一次计算

\[
[F_i,a,f,c],
\qquad \mathrm{parents}=[-1,0,1,2].
\]

对应输出提供历史 \(h\)、\((h,a)\)、\((h,a,f)\) 和 \((h,a,f,c)\) 下的条件分布。按 Position、Feature、Position 顺序验证候选；前序拒绝后，仅保留真实前缀。

给定真实提案 \(q\) 和对应历史下的目标分布 \(p\)，候选 \(X\sim q\) 以 \(\min\{1,p(X)/q(X)\}\) 接受；拒绝时从

\[
r(y)=\frac{[p(y)-q(y)]_+}{\sum_z[p(z)-q(z)]_+}
\]

采样。[Leviathan 等](https://proceedings.mlr.press/v202/leviathan23a.html) 对确定性 Position 提案，接受概率为该候选的 Target 质量，残差采样排除已拒绝的点。Feature 接受使用实际起草分布 \(q_F\)。

若第一 Position 接受而 Feature 拒绝，抽取残差 Feature 后结束本轮；若首对 P/F 接受，则继续处理第二 Position。三个候选全部接受时，从最后一个位置的 Target 输出抽取额外 Feature，完成四 token 的推进。位置拒绝并恢复到未经验证的正常位置时，W1 执行恢复前向以取得该位置的 Feature 分布和状态。EOS 直接终止；启动、候选不足和尾轮采用参考解码路径。

### 3.4 Position Rescue

第一 Position 的恢复依赖实际残差采样结果。PFSpec 利用主位置的同一排序，取第二个合法非 EOS 候选 \(b\ne a\) 作为备用，将验证输入扩展为

\[
[F_i,a,f,c,b],
\qquad \mathrm{parents}=[-1,0,1,2,0].
\]

备用 \(b\) 与主位置 \(a\) 共享历史 \(h\)，使用相同逻辑位置；其注意力不包含主分支的 \(a,f,c\)。验证同时生成 \(p_F(\cdot\mid h,b)\)、对应隐藏状态及 KV。

主位置拒绝后，仍由 W1 原有残差分布抽取实际位置 \(Y\)。当 \(Y=b\) 时，提交树路径 \([0,4]\)，直接复用备用状态生成 Feature；其余情况沿用 W1。该节点不参与新增接受测试，备用选择与计算也不消费参考采样随机数。没有合法备用时直接使用 W1。单备用仅覆盖第一 Position 的恢复。

Rescue 将可能需要的恢复前向并入当前验证，以额外并行计算换取命中时的串行调用节省。它与主路径预测作用互补：主路径通过连续接受增加推进，Rescue 在保持相同参考采样路径时降低恢复需求。

## 4. 正确性与计算收益分析

### 4.1 目标分布与参考轨迹

**命题 1：目标分布保持。** 在每个实际历史下使用正确 Target 条件分布、真实提案以及标准接受与残差规则，W1 保持目标采样分布。其单步输出质量满足

\[
\Pr(Y=y)=\min\{p(y),q(y)\}+[p(y)-q(y)]_+=p(y).
\]

沿真实前缀递归即可得到序列结论。并行验证负责提供正确条件分布，候选只在其前序实际接受时提交。

**命题 2：相对 W1 的轨迹保持。** 在确定性 Target 和精确算术下，若主路径在增加备用后保持等价，备用分支与普通恢复具有相同条件历史、逻辑位置、注意力及条件状态，并沿用同一采样算法与随机数消费顺序，则 Rescue 与 W1 产生相同对应输出、接受事件和后续生成状态。

证明按是否命中备用分支逐轮归纳。命中时，等价条件状态替代普通恢复前向；未命中时，执行参考操作。因此 Rescue 也保持目标分布。两项命题的详细状态条件见附录 C.1；有限精度实现另由配对输出和数值结果评价。

### 4.2 有效推进与位置恢复

考虑剩余预算至少四 token、两次位置提案均为非 EOS 的完整候选轮。令 \(s\) 为起草前的生成状态，\(w\) 为第一 Position 接受概率，\(j\) 为首对 P/F 连续接受概率，\(\beta\) 为到达第二 Position 后的条件接受概率，\(e\) 为该轮两种残差 EOS 终止事件的总概率。新增 token 数与额外位置恢复调用数满足

\[
\mathbb E[N_r\mid s]=2+2j(s)-e(s),
\]

\[
\mathbb E[K_r^{W1}\mid s]
=(1-w(s))+j(s)(1-\beta(s))-e(s).
\]

两式区分了 P/F 路径上的两种收益：首对 P/F 接受增加有效推进；第二 Position 接受保持该轮的四 token 上限，同时省去一次位置恢复。在第一 Position 已接受的条件下，Feature 接受概率等于目标分布与提案分布的重叠质量。由此，Feature 预测需要同时评价分布匹配与起草成本。完整分支推导见附录 A。

### 4.3 恢复预计算的价值

令 \(H_b\) 表示主位置拒绝且原残差采样命中备用 \(b\)。对当前确定性主提案和合法非主点备用，

\[
\Pr(H_b\mid s)=p_P(b\mid h),
\qquad
K_r^{Rescue}=K_r^{W1}-\mathbf1_{H_b}.
\]

因此，仅主位置接受率不足以决定备用的计算价值，还需要考虑备用在残差恢复中的命中质量。令 \(D_r\) 包含额外验证、注意力、KV 提交及执行交互的净成本，\(c_{\rm rec,r}\) 为命中时实际省去的恢复时间，则

\[
C_{Rescue,r}-C_{W1,r}
=D_r-\mathbf1_{H_b}c_{\rm rec,r}.
\]

只有节省的恢复工作覆盖附加成本，预计算才获得净收益。该分解用于解释局部计算安排；完整请求还包含初始化和首次图费用。实验统一使用实际生成量与完整时间 \(v=N/T\)，并区分解码吞吐和请求耗时。相应定义及适用条件见附录 A.5–A.7。

## 5. Experiments

实验围绕三个层次展开：位置投机是否提供有效的加速起点，轻量 Feature 路径能否在此基础上扩大收益，以及恢复预计算能否进一步减少串行工作。共享执行优化和完整三维请求另行评价。

### 5.1 实验设置

实验使用 GaussianGPT 和单张 RTX 4090，采用 FP32、关闭 TF32，batch size 为 1，温度与 top-p 均为 0.9。主要解码比较覆盖 30 个场景来源、64/256-token 前缀和最多 512 个新 token。结构消融覆盖 10 个开发来源，输出上限为 256 token。Target 权重和场景表示保持相同。

解码时间覆盖前缀与 KV 准备、首次实际图建立、提案、验证、采样、恢复和状态维护；模型加载、独立预热、VQ 解码与渲染不在此范围。各配置使用共同 Target 执行后端。吞吐倍率由来源内配对对数比汇总，再跨来源等权取几何平均；95% 区间按来源重采样。重复测量先在同一输入条件内汇总。补充材料列出样本组成、计时范围和训练对照设置。

**已有 Target 状态是 Feature 预测的重要信息。** 表 2 使用相同初始化、数据和训练预算比较条件输入；各版本接入同一 W1 流程。

### 5.4 为什么采用短路径

扩大草稿可以提高连续接受，但也增加起草和验证成本。表 3 比较单 Feature 分支 W1 与双分支 W2，两者均生成完整 512 token。

**表 3. 扩宽的推进收益与执行成本。** 三个开发来源、18 对输入；各比值采用相同配对及来源权重。

| W2 相对 W1 | 比值 | 变化 |
|---|---:|---:|
| 每轮有效推进 | 1.0437 | +4.37% |
| 摊入完整计时的每轮成本 | 1.0868 | +8.68% |
| 解码吞吐 | 0.9603 | −3.97% |

W2 的推进增长未覆盖每轮成本增长。验证物理节点增加 43.93%，Target 输入增加 36.23%，而 Target 调用仅减少 1.37%。这一结果支持当前轻量短路径的选择：提案价值取决于以多大成本取得实际推进。另一组较重 PF-D8 草稿同样获得更高 Feature 接受率而低于轻量路径的吞吐，补充结果见附录 C.4。

### 5.5 保持主路径时的恢复收益

Position Rescue 评价的是恢复计算的增量。主比较中，W1 与 Rescue 的 60 对输出、轮数和语义接受计数全部相同；357 次备用命中逐对对应 357 次恢复调用减少，恢复调用由 1,080 降至 723。与此同时，验证增加 4,015 个备用节点，Target 输入净增加 3,658 个 token。完整吞吐仍提高 **1.52%**，表明被避免的串行工作能够覆盖额外验证成本。

四进程重复实验进一步覆盖 120 个唯一输入条件、480 对重复观测。Rescue 相对 W1 的吞吐提升为 **1.81%**，95% 来源区间为 **[1.48%, 2.13%]**；480 对输出及语义接受计数全部一致，恢复调用减少 2,908 次。该结果在不增加参考主路径接受的情况下取得收益，与第 4 节的恢复成本分析一致。

首次图建立会影响这项较小的增量，增加备用数量也未带来稳定的进一步加速。相关结果与负向实验保留于附录 B。配对输出为已测实现提供证据，数学性质则依赖第 4.1 节的条件。

## 6. Discussion

PFSpec 展示了将序列表示用于草稿计算安排的一条路径：利用位置历史提出空间候选，将神经状态预测集中于 Feature 所需的状态，并将部分恢复计算并入验证。该方法的设计依据是可用条件信息与实际执行成本，具体预测器可以进一步发展。对于其他结构化序列，类似设计是否有效，取决于是否存在廉价候选结构、可复用状态以及足以抵消验证成本的推进或恢复收益。

当前实验覆盖一个 Target、RTX 4090 和单 Chunk 生成。基础轻量 P/F 路径已有自然 EOS 的较长输出；包含 Rescue 的完整 PFSpec 主要比较仍采用 512-token 新增上限，其全长增量需要进一步评价。适配方法之间仍有训练与输入差异，跨模型、跨设备及多 Chunk 连续生成的效果尚待研究。Rescue 的收益对图建立和分支覆盖敏感，其局部成本分析也不提供通用最优策略。详细适用条件和负向结果保留于补充材料。

## 7. Conclusion

本文提出 PFSpec，将 GaussianGPT 的 Position–Feature 条件结构落实为类型化短路径与恢复预计算。位置排序和 Target 状态辅助的 Feature 预测共同减少主路径串行工作，Position Rescue 进一步利用备用状态降低恢复需求。在保持目标采样规则的设计下，PFSpec 获得约 1.58× 的同执行后端解码吞吐，并在有长度上限的完整三维请求中取得实际加速。结果说明，结构化生成中的条件信息既可用于预测，也可用于决定哪些计算值得提前完成。

## 附录 A. 完整轮次推导与有限请求计时

### A.1 完整候选轮次与事件定义

以下式A、B、C条件于完整候选轮次的生成状态 \(s\)：剩余预算至少四token，主位置 \(a\) 与第二位置 \(c\) 均为合法非EOS提案，Feature词表不含EOS。EOS只可能出现在这两个位置拒绝后的残差恢复中；启动、候选不足和尾轮不进入这一适用域。

状态 \(s\) 包含该轮起草前已确定的历史、位置排序与可用 Target 状态；概率计算对本轮 Feature 起草、接受测试和残差采样取平均，不以尚未使用的随机结果为条件。主位置、第二位置及备用位置均由已有位置历史确定。Feature 起草与第一 Position 接受测试使用独立随机抽样，因而第一 Position 接受后，Feature 候选仍服从 \(q_F(\cdot\mid u_i,F_i,a)\)。

令 \(A_P,A_F,A_{P_2}\) 分别表示第一Position、Feature及第二Position被接受，定义

\[
w(s)=\Pr(A_P\mid s),\qquad
j(s)=\Pr(A_P\cap A_F\mid s)
=w(s)\alpha_{F\mid P}(s),
\]

\[
\alpha_{F\mid P}(s)=\Pr(A_F\mid A_P,s),\qquad
\beta_{P_2}(s)=\Pr(A_{P_2}\mid A_P,A_F,s).
\]

条件事件概率为零时，相应联合概率项取零，不单独估计未定义的条件概率。这里没有引入接受事件独立性假设。第二Position的条件接受率已包含到达不同Feature历史后的平均。

定义 \(E_1\) 为第一位置拒绝后恢复到EOS，\(E_2\) 为首对P/F接受、第二位置拒绝后恢复到EOS。两个事件互斥，并记

\[
e(s)=\Pr(E_1\mid s)+\Pr(E_2\mid s).
\]

在上述非EOS提案和完整轮次前提下，\(E_1,E_2\) 覆盖该轮所有EOS终止路径。扩展到其他控制流程时，应重新列出全部终止事件。

### A.2 式A：有效推进

令 \(N_r\) 为本轮新生成token数，\(K_{\rm rec}^{W1}\) 为额外Position恢复前向的调用数。完整候选轮次的路径如下。

| 实际路径 | \(N_r\) | \(K_{\rm rec}^{W1}\) |
|---|---:|---:|
| 第一Position拒绝，恢复为EOS | 1 | 0 |
| 第一Position拒绝，恢复为正常位置 | 2 | 1 |
| 第一Position接受，Feature拒绝 | 2 | 0 |
| 首对P/F接受，第二Position拒绝并恢复为EOS | 3 | 0 |
| 首对P/F接受，第二Position拒绝并恢复为正常位置 | 4 | 1 |
| 三个主候选全部接受 | 4 | 0 |

由表中路径计数，

\[
N_r
=2+2\mathbf1_{A_P\cap A_F}
-\mathbf1_{E_1}-\mathbf1_{E_2},
\]

故

\[
\boxed{\mathbb E[N_r\mid s]=2+2j(s)-e(s).}
\tag{A}
\]

当相关目标条件分布的EOS概率均为零时，\(e(s)=0\)，得到普通非终止模型的简化形式

\[
\mathbb E[N_r\mid s]
=2+2w(s)\alpha_{F\mid P}(s).
\]

某一观测轮没有输出EOS，不足以证明其 \(e(s)=0\)。

标准接受概率满足

\[
\alpha_{F\mid P}(s)
=\sum_f\min\{p_F(f\mid h,a),q_F(f\mid u_i,F_i,a)\}
=1-\operatorname{TV}(p_F(\cdot\mid h,a),q_F(\cdot\mid u_i,F_i,a)),
\]

其中 \(\operatorname{TV}(p,q)=\tfrac12\sum_x|p(x)-q(x)|\)，当前点提案给出 \(w(s)=p_P(a\mid h)\)。该关系把条件匹配与有效推进连接起来，但成本和实际到达状态也可能随提案器变化，不能单独推出吞吐最优。

### A.3 式B：W1的两类位置恢复

第一Position拒绝且未产生EOS时，需要恢复该位置并预测Feature。首对P/F接受、第二Position拒绝且未产生EOS时，需要第二类恢复。因此

\[
K_{\rm rec}^{W1}
=\mathbf1_{\neg A_P\cap\neg E_1}
+\mathbf1_{A_P\cap A_F\cap\neg A_{P_2}\cap\neg E_2}.
\]

利用 \(E_1\subseteq\neg A_P\) 和
\(E_2\subseteq A_P\cap A_F\cap\neg A_{P_2}\)，得到

\[
\boxed{
\mathbb E[K_{\rm rec}^{W1}\mid s]
=(1-w(s))+j(s)[1-\beta_{P_2}(s)]-e(s).
}
\tag{B}
\]

式A和式B分别描述推进与恢复。第二Position接受不提高该轮四token的推进上限，却减少第二类恢复调用。首对P/F连续接受增加推进，同时使第二Position路径有机会被执行。

调用数不能直接替代时间。若两类实际恢复时间分别为 \(c_1,c_2\)，恢复成本应按真实事件写为
\(C_{\rm rec}=\mathbf1_{\mathcal R_1}c_1+\mathbf1_{\mathcal R_2}c_2\)，其中 \(\mathcal R_1,\mathcal R_2\) 为上述两种非EOS恢复事件。不同历史和运行状态可能具有不同恢复成本。

### A.4 式C：备用命中与恢复调用减少

进一步假设该轮具有已确定、合法、非EOS且不同于 \(a\) 的备用 \(b\)。令 \(H_b\) 为主位置拒绝且真实残差恢复到 \(b\) 的事件。当 \(w(s)<1\) 时，

\[
\Pr(Y=b\mid \neg A_P,s)
=\frac{p_P(b\mid h)}{1-p_P(a\mid h)},
\qquad
\Pr(H_b\mid s)=p_P(b\mid h).
\]

前式为拒绝条件命中率，后式为该适用轮的无条件命中质量。当 \(w=1\) 时拒绝事件概率为零，备用质量为零，无需计算条件分母。备用选择使用验证前已知历史与排序，不利用参考恢复抽样的随机量改变主路径。

由命题2，命中备用时省去一次第一Position恢复，其他对应路径不变，因此

\[
K_{\rm rec}^{Rescue}=K_{\rm rec}^{W1}-\mathbf1_{H_b},
\]

\[
\boxed{
\mathbb E[K_{\rm rec}^{Rescue}\mid s]
=\mathbb E[K_{\rm rec}^{W1}\mid s]-p_P(b\mid h).
}
\tag{C}
\]

没有合法备用时沿用W1。对包含不适用轮次的总体统计，应加入适用轮次指示，不能直接把所有轮次视为具有备用。

式C描述Position恢复调用。Rescue增加一个验证节点，不能由恢复调用的降幅推出Target总计算量或时间的同幅下降。与此同时，命题2保持对应生成状态和轮次边界，因此Rescue不增加参考W1的主路径推进量。

### A.5 恢复复用的完整成本条件

在相同生成状态和耦合随机操作下，令 \(D_r\) 为除被替代恢复前向外的全部净成本变化，包含额外验证节点、树组织、KV、图及执行交互。命中时省下的实际恢复时间记为 \(c_{\rm saved,r}\)。则

\[
C_{Rescue,r}-C_{W1,r}
=D_r-\mathbf1_{H_b}c_{\rm saved,r}.
\]

取条件期望，

\[
\mathbb E[\Delta C_r\mid s]
=\mathbb E[D_r\mid s]
-p_P(b\mid h)\mathbb E[c_{\rm saved,r}\mid s,H_b].
\]

零概率命中项取零，不单独定义其条件成本。固定状态下获得正期望局部收益，当且仅当

\[
p_P(b\mid h)\mathbb E[c_{\rm saved,r}\mid s,H_b]
>\mathbb E[D_r\mid s].
\]

这是完整成本定义下的局部成本条件。没有独立估计各项时，它提供记账和解释，不能提前预测策略一定获得多少加速。额外图驻留、容量和首次执行可能改变后续成本，因此不据此主张全请求最优选择。

完整请求的时间差还包括初始化：

\[
T_{Rescue}-T_{W1}
=\Delta T_{\rm init}
+\sum_rD_r-\sum_r\mathbf1_{H_{b,r}}c_{\rm saved,r}.
\]

各轮净差必须覆盖实际运行状态的影响，不能仅将孤立微测的节点时间代入。

### A.6 启动量、轮次计数与有限请求恒等式

对方法 \(m\)，令 \(N_m\) 为实际生成token数，\(T_m>0\) 为完整解码时间。当前W1类实现的rounds只统计进入主循环的次数；BOS启动可能先生成一个P/F对，或生成EOS。令 \(N_{\rm boot,m}\) 为启动分支产生的token数，不包含输入中的BOS，则

\[
N_m=N_{\rm boot,m}+\sum_{r=1}^{R_m}N_r.
\]

该求和包括主循环内的完整候选、候选不足和尾轮；式A、B、C只用于其中满足各自前提的轮次。对 \(R_m>0\)，区分

\[
G_m^{request}=\frac{N_m}{R_m},\qquad
G_m^{loop}=\frac{N_m-N_{\rm boot,m}}{R_m},
\qquad
\bar C_m=\frac{T_m}{R_m}.
\]

因此

\[
\boxed{v_m=\frac{N_m}{T_m}=\frac{G_m^{request}}{\bar C_m}.}
\]

\(G^{request}\) 将启动输出摊入轮数；\(G^{loop}\) 才是已计数循环轮次的实际平均推进。仅有完整非终止轮且无启动量时，可直接对应无EOS普通轮的路径计数；使用其期望简式仍需相关EOS概率为零。若 \(R_m=0\)，不定义这些轮次比值，仍使用 \(v_m=N_m/T_m\)。

原 Target 和优化 Target 采用逐 token 自回归生成，其执行步数与 W1 的候选轮次定义不同。两者与 PFSpec 的性能比较直接使用输出 token 数和完整解码时间；上述按候选轮次的分解仅用于具有相同轮次定义的方法。

完整计时写为 \(T_m=T_{\rm init,m}+\sum_rC_{m,r}\)。 \(T_{\rm init,m}\) 包括未计入主循环轮数的BOS启动生成成本，以及未归入各轮 \(C_{m,r}\) 的其他循环外解码开销，使该分解覆盖完整计时范围。当前解码测速计入运行时创建、前缀、KV准备、首次图、提案、验证、抽样、恢复和状态维护，排除模型加载、VQ与渲染。首次图按实际发生位置计入一次。阶段时间应互不重叠，共享前向保留联合项；CUDA event与host完整时间分别报告，不能相加。最新通用方法比较没有完整阶段时间，调用与输入计数不能替代相应秒数。

### A.7 配对加速比与性能归因

任意方法 \(a,b\) 的直接吞吐比为

\[
S_{a/b}=\frac{N_a/T_a}{N_b/T_b}
=\frac{N_a}{N_b}\frac{T_b}{T_a}.
\]

只有输出数量相同时，它才等于请求耗时比 \(T_b/T_a\)。对具有明确正轮数的配对，进一步有

\[
S_{a/b}
=\frac{G_a^{request}}{G_b^{request}}
\frac{\bar C_b}{\bar C_a}.
\]

因此净加速需要相对推进收益超过相对完整成本增长。W1/W2已有相同轮次定义及无启动的输入，可用上述分解；W1/Rescue保持对应输出和轮次，速度差来自完整时间变化。更换提案器则可能改变实际生成轨迹与轮次分组，不能套用Rescue的逐次轨迹保持结论。

跨来源采用同一配对集合和来源等权log平均时，几何平均保留乘法分解。池化总token/总时间采用不同权重，不与该分解拼接；置信区间按来源重采样。共享执行优化、W1与Rescue的同轮吞吐倍率可相乘得到整体倍率，但5.13倍属于实测归因，不由接受概率直接预测。

本文分析重点为P/F条件接受与W1推进、两类位置恢复的联合刻画，以及Rescue的条件状态复用性质。标准残差抽样、有限请求恒等式和乘法关系承担正确性与解释作用，不作为新的通用最优理论。第 5 节将这些机制与比较、消融和成本证据对应。

## 附录 C. 证明条件与实验细节

### C.1 分布与轨迹保持的详细条件

**命题 1：W1的目标分布保持。** 在每个实际到达的完整历史下，使用正确目标条件分布、实际提案以及上述接受与残差规则，则下一输出服从该Target policy。因为接受并输出 \(y\) 的概率质量为 \(\min\{p(y),q(y)\}\)，总拒绝概率为 \(Z\)，有

\[
\min\{p(y),q(y)\}+Zr(y)
=\min\{p(y),q(y)\}+[p(y)-q(y)]_+
=p(y).
\]

当 \(Z=0\) 时拒绝事件概率为零，无需定义恢复分布。并行验证为各候选提供对应条件历史的输出，顺序接受仅提交真实前缀，因此可沿真实输出历史逐步应用上述结论。该命题保持目标分布，不要求W1与普通自回归实现在相同种子下逐token一致。

**命题 2：Rescue相对参考W1的轨迹保持。** 固定W1提案与参考随机操作，假设Target确定且采用精确算术；主路径各节点在增加备用后仍与 W1 等价，备用分支与普通恢复具有相同完整历史、逻辑位置、注意力范围、输出分布、隐藏状态和 KV；仅真实路径进入后续状态，借用图输出缓冲在覆盖前已消费或复制。还需两者使用相同的 Feature policy、采样算法及随机数消费顺序，包括后续草稿所使用的随机流。则 Rescue 与 W1 产生相同对应输出、接受事件和生成状态。

证明按一轮的控制流程展开。主接受时两者执行相同W1操作；主拒绝时相同残差和随机操作产生相同 \(Y\)。若未命中，两者沿用同一路径；若命中，等价备用状态使下一Feature和提交后的生成状态相同。EOS、启动与尾部沿用参考操作。逐轮归纳得到完整有限请求的对应轨迹一致。结合命题1，Rescue同样保持目标分布。

两项命题采用不同前提，分别陈述。GPU算子次序、注意力执行与有限精度可能影响状态数值；已测输出一致和数值误差作为实现证据，不能代替数学前提。

### C.5 执行实现与完整请求

共享 Target 执行路径采用动态位置 CUDA Graph，按缓存、输入形状及历史读取范围复用图。树验证使用祖先约束的注意力与真实路径 KV 提交。图输出缓冲在后续执行中可能被覆盖，选中状态需在覆盖前使用或复制。

同轮归因使用 30 来源、两种前缀、采样种子 51101、四配置，共 240 次解码。精确点值为：优化 Target/原 Target 3.240487，W1/优化 Target 1.557471，PFSpec/W1 1.016788，PFSpec/优化 Target 1.583618，PFSpec/原 Target 5.131692。同配对及来源权重下，未舍入的点值满足乘法分解；其他批次的倍率和置信区间不代入该等式。

完整请求组使用 10 来源、20 个输入、三个方法，共 60 次请求。计时从准备好的 token 前缀开始，包括生成、VQ 解码、NPZ 导出、六个 384×384 视图的渲染和 PNG 保存，排除模型加载、独立预热、输入获取及编码。请求加速比定义为对照耗时除以被评价方法耗时。

PFSpec/原 Target 为 4.307862 [3.867624, 4.660647]，PFSpec/W1 为 1.001848 [0.962270, 1.024833]。原 Target 合计输出 10,240 token，W1 与 PFSpec 各输出 9,837 token；共同满 512 token 的 19 对输入给出 PFSpec/原 Target 4.185458 [3.546722, 4.660647]。全量与等输出数量子集分别报告，均限定于当前单 Chunk 与长度上限。

W1 与 PFSpec 的 20 对 token 序列相同；60 份 NPZ 和 360 张 PNG 有效，Gaussian 数值与像素存在极小差异。该结果描述输出兼容性，未评价绝对视觉质量提高。

### C.6 候选构造、预测器与训练细节

**位置候选。** 令已提交位置为 \(v_i\)，过去的位置码差值为 \(g_i=v_i-v_{i-1}\)，空间相位为 \(\varphi=v_i\bmod20\)。差值统计按最近两个差值的状态 \(s_g\)、相位及二者组合分别累计，记为 \(M,Z,B\)。某计数器的总量少于三时，其众数采用指定回退值。基础差值候选为相位条件众数、1、历史众数和 \(Z\) 的前两个高频项；当 \(\varphi=1\)，或 \(s_g=(1,1)\) 且 \(\varphi\in\{12,14\}\) 时，加入 \(Z\) 的前三项；当 \(Z\) 的总量小于三时，加入 \(B\) 的前两项。候选去重后，经 \(v_i+g\) 映射为位置，并保留词表内且扫描序号严格增加的项。

该规则的候选上界为六个：稠密 \(Z\) 下，其众数已位于前三项中，连同单位差值和历史众数至多五项；稀疏 \(Z\) 下，条件众数回退为历史众数，\(Z\) 至多含两个已观测差值，再加两个相位候选，至多六项。合法性过滤只会减少数量。该上界描述候选生成规则，未替代在线完整耗时。

每个候选使用 32 维统计。除差值、相位、空间索引和最近四个差值外，还包括集合大小、众数及高频命中标记、历史平滑权重、二阶及三阶条件频数、条件频率和最近出现间隔。进度项为已生成位置序号除以 511；这是沿用训练时的固定尺度，长请求也不读取最终 EOS 位置。在线状态仅在实际位置提交后更新；第二位置使用主位置的临时历史，随后只保留实际路径。

排序器为 HistGradientBoostingClassifier，学习率 0.05、150 轮、最多 15 个叶子、叶节点最少 40 个样本、L2 系数 10，关闭提前停止。以 Target 已采样的下一位置为正标签，其他集合内候选为负标签；候选及输入先由已有历史生成，再读取标签。部署采用数值分裂树的 CPU 编译评分器，单候选无需调用评分器。历史 12 种子、1,024-token 实验有 2,273 次评分，总计 0.182772 秒，平均 0.080410 ms；此项只覆盖评分调用，不含候选构造、状态复制或 Target。树评分及历史平滑权重均不作为实际 Position 提案概率。

**Feature 预测器。** 输入状态先经 LayerNorm 和 \(1024\to256\) 线性层，历史 Feature 与候选 Position 分别使用 \(4096\times128\)、\(8000\times128\) 嵌入。拼接后的 512 维向量经 LayerNorm、两层 512 维 GELU 变换及末层 \(512\to1024\) 变换，输出加到已有状态。随后调用 Target 的最终归一化、固定 Feature 输出头及 \(15\tanh(z/15)\) softcap。

| 部分 | 可训练参数 |
|---|---:|
| 输入 LayerNorm 与 \(1024\to256\) 线性层 | 264,448 |
| Feature 嵌入 | 524,288 |
| Position 嵌入 | 1,024,000 |
| 拼接 LayerNorm | 1,024 |
| 三层残差变换 | 1,050,624 |
| 合计 | **2,864,384** |

共享输出头含 4,194,304 个固定权重元素。按线性层维度，一次状态预测及输出读出约含 5,505,024 次乘加，其中输出头占 4,194,304 次；该计算量不包含归一化、激活、概率处理、访存及调度，不直接等于执行时间。

主模型沿用已有状态蒸馏初始化，再使用原始 Target 的完整 Feature 分布训练。数据按完整轨迹划分，训练 400 条、418,021 个状态行，验证 50 条、46,893 行；这些数量表示 Target 轨迹，不表示独立三维来源场景。每行包含上一 Position 状态、上一实际 Feature、当前 Position 和对应教师分布；第一 Feature 由 Target 生成，不进入该状态监督。

令 \(p^{(1)}\) 为温度 1、未截断的 4,096 类教师分布，\(q^{(1)}_\phi\) 为对应草稿分布，\(p^\pi,q^\pi_\phi\) 为温度及 top-p 均为 0.9 的采样策略分布。直接 Target 训练的目标为

\[
\mathcal L_\phi
=-\sum_f p^{(1)}(f)\log q^{(1)}_\phi(f)
+\lambda\operatorname{TV}(p^\pi,q^\pi_\phi).
\]

前三阶段各 1,200 次更新，学习率起点为 \(3\times10^{-5},10^{-5},10^{-5}\)，\(\lambda=0,0,2\)；随后沿用 \(\lambda=2\) 再更新 8,400 次。各阶段使用余弦下降至起点的 0.1 倍，AdamW 权重衰减 0.01、梯度范数上限 1。每次更新处理两条轨迹，按 256 行分块累积；训练采用 BF16，验证与本文正式解码采用 FP32。按完整验证集的逐行分布重合度选择权重，得到直接 Target 训练的累计 step12000；初始化阶段的训练另计。该选择指标不等同于独立在线提速结论。

### C.7 全长单 Chunk 输出与定性结果

自然 EOS 实验使用原 Target、既有 Ranker 与 step12000 Feature 模型，P/F 路径的三个提案和四行验证与基础短路径一致，执行后端早于本论文的共享图优化，未包含 Rescue。真实补全使用 30 个测试来源的预定裁剪、256-token 前缀和种子 51701–51703；BOS 使用种子 51801–51830。正文上限 16,000，FP32，温度及 top-p 均为 0.9，局部 Chunk 物理边长为 4 米。

360 次请求均自然终止，无截断，并完成三维输出。计时从已准备前缀或 BOS 开始，覆盖生成、VQ、NPZ 导出、六张 \(384\times384\) 图像的渲染与保存，排除模型加载、独立预热、输入编码与参考重建。补全时间比先在同场景三个种子内取几何平均，再按 30 场景等权；BOS 按 30 个种子配对。表 5 的置信区间采用 10,000 次重采样估计。该批来源数量不与其他批次相加，BOS 种子也不计为场景来源。

基础轻量 P/F 的补全正文总长度含前缀范围为 306–5,792 token，BOS 为 2,462–5,646 token；全部自然终止。真实补全的平均 Gaussian 数量依次为 Target 218,986、Position-only 212,133、轻量 P/F 222,091；相应尺度裁切比例为 8.74%、8.84%、8.63%。这些数值描述解码输出，未定义生成质量排名。

主文表 5 报告相对于同一真实裁剪 VQ 重建的全图 PSNR 和 SSIM 均值。这些数值属于描述性统计；当前没有评价质量差异的置信区间或等价范围。全图包含随机续写区域，不能据此确认分布等同或视觉质量提高；BOS 没有对应真实场景参考。已知区域掩码、KID/FID 和多 Chunk 连续性未在该批建立评价结果。
