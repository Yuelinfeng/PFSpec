\section{Related Work}
\label{sec:related}
\paragraph{Autoregressive 3D generation.}
MeshGPT models quantized mesh sequences, and MeshAnything V2 reduces sequence redundancy with adjacent mesh tokenization~\cite{meshgpt,meshanything}. GaussianGPT instead uses a sparse, alternating P/F representation for 3D Gaussians~\cite{gaussiangpt}. Representation structure also supports acceleration: FlashMesh combines hierarchical feature prediction with vertex-sharing consistency, and XSpecMesh uses multiple prediction heads with verification and resampling~\cite{flashmesh,xspecmesh}. \PF\ keeps GaussianGPT's target and serialization unchanged, using legal position histories and position-conditioned states to organize drafting and recovery.

\paragraph{Lightweight drafts and state prediction.}
Medusa predicts future tokens from target hidden states; Hydra conditions later heads on earlier proposals; EAGLE predicts continuous hidden features using shifted token information and reuses the output head~\cite{medusa,hydra,eagle}. P-EAGLE extends this approach to parallel drafting, while DFlash conditions block-diffusion drafting on target context features~\cite{peagle,dflash}. \PF\ builds on conditional prediction and state reuse, assigning position proposals to a ranker and estimating the state needed for feature prediction directly from an earlier position state. Its short path requires no separate neural history cache across rounds. Here, \emph{Feature} denotes a discrete scene code, distinct from the continuous hidden features predicted by EAGLE.

\paragraph{Parallel verification and state reuse.}
Standard speculative sampling preserves the target distribution through acceptance and residual resampling~\cite{leviathan}. SpecInfer verifies a shared-prefix token tree with ancestor-constrained attention and KV management~\cite{specinfer}. SpecTr studies multi-candidate coupling and discusses reusing the next conditional distribution when a selected token belongs to the precomputed candidate set~\cite{spectr}. Position Rescue uses these execution primitives for a specific P/F recovery event: the main proposal and residual sampler remain fixed, and a backup supplies the distribution, hidden state, and KV required by the selected recovery position and subsequent drafting.

\paragraph{Cost-aware speculation and rejection branches.}
Sequoia jointly considers tree structure and hardware cost; OPT-Tree adapts draft trees using path probabilities; Learning to Draft optimizes draft-and-verify throughput~\cite{sequoia,opttree,ltd}. SpecBranch uses rollback-aware branch parallelism, and Speculative Speculative Decoding prepares subsequent drafts during verification~\cite{specbranch,ssd}. \PF\ analyzes work allocation within a fixed P/F reference process: main proposals affect useful advance, while backup target states affect recovery work. Its cost decomposition explains this local mechanism without claiming a generally optimal tree policy.
