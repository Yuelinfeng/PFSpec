# PF-Branch2 连续残差采样的概率依据

本材料按 `WEB_PLAN_R1_ORIGINAL.md`（Round01-R1）中的第二阶段提案定义展开概率，范围只到离散候选与残差输出，不涉及解码器实现或性能结论。可复跑脚本是 [`verify_multicandidate_cpu.py`](../../../../../../GaussianGPT/patches/pf2x_round01/verify_multicandidate_cpu.py)，结果在 [`probability_cpu.json`](results/probability_cpu.json)。

## 两阶段分布

在同一已接受的 `P₁` 前缀下，令 Target 分布为 `p`，首提案为 `q₁`。抽到首候选 `a` 并拒绝的联合质量是

```text
δ(a) = q₁(a) − min(p(a), q₁(a)) = [q₁(a) − p(a)]₊
R₁ = Σₐ δ(a) = Σ_f [p(f) − q₁(f)]₊
r₁(f) = [p(f) − q₁(f)]₊ / R₁       (R₁ > 0)
```

因此 `δ(a)` 已同时包含抽到 `a` 与拒绝它的概率；它不是只在“已拒绝”条件下的归一化权重。首阶段合成输出为 `min(p(f),q₁(f)) + R₁r₁(f) = p(f)`。

给定首候选 `a` 被拒绝后，实际第二提案由 `q₂(·|a)` 抽取。若先有不依赖 `p` 的 `q₂_base`，再排除 `a`，则 `q₂(b|a)=0`（`b=a`），其余为 `q₂_base(b)/(1−q₂_base(a))`。分母为零时直接从 `r₁` 输出，不产生第二阶段接受事件。

定义接受联合质量 `mₐ(b)=min(r₁(b),q₂(b|a))`。Round01 §4.2 的量可写为

```text
β(a) = Σ_b mₐ(b) = P(第二候选被接受 | 首阶段拒绝了 a)
P(首阶段拒绝 a 且第二候选接受 b) = δ(a)mₐ(b)
P(首阶段拒绝且第二候选接受) = J = Σₐ δ(a)β(a)
β̄ = J/R₁                         (R₁ > 0)
```

对 `β(a)>0`，第二候选在“接受”条件下的分布为 `mₐ(b)/β(a)`，通常不等于完整的 `r₁`。令 `sₐ(b)=[r₁(b)−q₂(b|a)]₊/(1−β(a))`；第二阶段拒绝后按 `sₐ` 抽取，则包括接受分支和拒绝残差分支的完整输出满足

```text
mₐ(b) + (1−β(a))sₐ(b) = r₁(b)
```

所以 Round01 §2.2 中“`F₁*` 与 `F₁b` 具有相同条件分布”的表述，只适用于把 `F₁b` 指作第二阶段接受/拒绝之后的最终输出。若 `F₁b` 专指被接受的第二候选，该句一般不成立。计算后续 `P₂` 事件时，不能把接受子集当作 `r₁`。

令 `u(a,b)` 表示在首阶段拒绝 `a`、第二阶段接受 `b` 后，`P₂` 被正确验证并产生所需后续推进的条件概率。则在已具备合法 `P₁` 前缀下，真正有利事件的权重为

```text
H = Σₐ δ(a) Σ_b mₐ(b)u(a,b)
```

若还要计入到达该前缀的 `P₁` 接受概率 `A_P₁`，相应无条件事件概率为 `A_P₁ H`；跨上下文时应按各上下文发生权重求和。这里的 `u(a,b)` 必须使用 `F₁b=b` 条件下的 Target `P₂` 分布与正确分支状态。`β̄` 只描述二次候选接受，不代表新增输出 Token 或节省 Target 调用。当前 CPU 合成数据没有 `P₂` 条件分布，故不计算 `u` 或 `H` 的项目数值。

## CPU 结果

运行命令：

```sh
python3 patches/pf2x_round01/verify_multicandidate_cpu.py
```

脚本 `run_small_exhaustive()` 使用 `Fraction` 穷举 9 组配置；词表类别数覆盖 2、3、4、8。新增的 8 类别配置为 `vocabulary_category_count=8, integer_denominator=2`，含 36 个离散分布、1,296 组 `p/q₁` 配对及 46,656 组独立 `q₂_base` 三元组合。合计覆盖 2,207 组配对和 60,463 组三元组合。每条路径展开接受、拒绝与残差分支；最终质量最大误差和归一化误差均为 `0`。边界覆盖首提案点质量、排除后第二提案无质量、支持集不同、首/次残差为零、连续两次拒绝，以及 `2⁻⁶⁰`、`2⁻⁶¹` 的极小正残差；分支判定未设置正数截断。

4096 维全向量展开采用 Python binary64。`p` 与 Draft logits 分别由种子 `20261020` 生成；`q₁` 使用 temperature 0.9、top-p 0.9，宽支持 `q₂_base` 使用同一组 Draft logits 的 top-p 1.0 结果，生成 `q₂_base` 时没有读取 `p`。两种 `q₂` 策略的最终分布最大绝对误差为 `9.54×10⁻¹⁸`，归一化误差为 `0`。宽支持策略下 `R₁=0.694420`、`β̄=0.164626`、`J=0.114319`；加权最大分支的 `β(a)=0.169187`。该分支中接受子集分布与 `r₁` 的总变差为 `0.432885`；所有分支合并后的接受子集与 `r₁` 总变差为 `0.434232`。这些数值只演示概率权重差异，不是模型输出。

4096 维辅助 Monte Carlo 用种子 `20261021` 抽样 100,000 条完整路径。首阶段拒绝观测值为 `0.694970`（全向量值 `0.694420`）；二次接受联合观测值为 `0.113790`（全向量值 `0.114319`），给定首阶段拒绝后的接受率为 `0.163734`（全向量 `β̄=0.164626`）。最终输出按 Target 概率最高的 16 个 Token 与其余 Token 分组，最大组概率误差 `0.000537`，分组总变差 `0.001275`。二次接受样本的分组最大误差为 `0.001813`。该 Monte Carlo 只辅助核对抽样循环；精确有理数穷举与 4096 维全向量展开仍是主要依据。

## 证据边界

这些运算没有调用模型、权重、GPU 或当前解码器。binary64 结果不证明 CUDA / GPU FP32 的数值行为；脚本也未覆盖 Target KV、4D RoPE、EOS、Ranker 状态或计时。它不能支持任何性能结论，不能替代真实 `P₂` 条件概率与分支成本测量。
