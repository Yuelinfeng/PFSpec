## 固定输入、KV 与 RoPE 调用位置

配对行在每个上下文、每个形状的 8 次重复中保持输入 token ID 和 KV 起止位置不变；每次恢复到同一 keep 位置。实测示例如下：

| 来源 prefix / round | main_4 起点 | 配对 keep | short_2 输入；KV 变化 | narrow next_4 输入；KV 变化 | wide next_4 输入；KV 变化 |
|---|---:|---:|---|---|---|
| 64 / 17 | 112 | 114 | `[10190, 2445]`；114→116→114 | `[10190, 2445, 10190, 2446]`；114→118→114 | `[10190, 2445, 10447, 2446]`；114→118→114 |
| 256 / 1 | 260 | 262 | `[8443, 3689]`；262→264→262 | `[8443, 3689, 9522, 3690]`；262→266→262 | `[8443, 3689, 9461, 3690]`；262→266→262 |

输入依次为残差 Feature、P2，以及四 token 路径额外包含的 F2、P3。prefix 字段是来源的初始 token 数；目标测量发生在该 W1 前缀已经推进若干轮后，因此样例实际 KV 起点为 112/260。`get_pos` 统计已处理输入：重放 `context_prefix[:-1]` 后，待处理末尾 Feature 还未进入 KV；主块输入 pending Feature、P1、F1a、P2，随后截短到处理完 P1 的位置，即 `n+2`。配对短块和四 token 块都从这个位置开始。

调用链也符合该位置关系：`measure_target_shapes.py:525–540` 每次按当前 `cache.get_pos()` 生成 `typed_kinds`，并以 `prefix[:-1]` 建立前缀 KV；`source_current/draft_a/pf_ranker_eval.py:39–40` 按绝对槽位奇偶生成 Position/Feature logits 类型。`source_current/bench_gaussiangpt_pf_block2_cow.py:61–68` 截短 KV 长度并清除 token cache 尾部；`source_current/model/gpt/nanochat_gpt.py:602–609, 643–648` 从保留 token 前缀与当前输入构造稀疏 RoPE 索引。因此重复前向从同一 cache 位置进入 RoPE 构造，并使用同一固定输入。JSONL 没有记录 RoPE 张量本身；这里确认的是源码调用位置与输入/KV 记账一致。

## 结果适用范围

本次数据证明采集、两种分支测量、预热、交替重复与分析阶段均完成，并量得特定前缀状态下短块与四 token 块的条件前向成本。样本计时集中在两个同来源上下文；这些数值仅支持条件前向成本结论。真实解码速度需另有包含正常解码、输出推进、采样、Ranker、缓存恢复与自然 EOS 的端到端测量。
