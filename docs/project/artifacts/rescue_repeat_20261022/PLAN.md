# 备用Position重复验证

目标是核验约1.75%的新增解码收益是否在多次运行中保持，不预设正结论，不混入旧结果抬高样本量。

固定既有source_run02的W1与备用实现，不训练、不调参数、不替换权重。四个独立Python进程顺序执行，同一GPU一次只运行一项。每次三十来源、64/256前缀、两个新seed52101/52102、512-token上限、W1/备用两臂，共240次；总960次、480个配对观测、120个唯一来源×前缀×种子case。每个来源在四次进程与两种子下重复，统计仍以三十来源为单位。

四次方法列表顺序交替；实际每个prompt继续沿用旧runner轮换。来源组循环偏移0/8/15/23，使首图成本落在不同来源。每次所有模型与图运行时重新载入，独立预热对象丢弃；正式首图、前缀、提案、验证、抽样、恢复、缓存准备与同步均计入外层墙钟。载入权重、VQ、渲染与保存不计入。

新入口只包装原runner的prompt组排序，不改计时和算法。记录真实CLI、来源顺序、seed及方法顺序。各次目录独立，完整结果和失败都保留。先完成全部既定重复，再进行总体结论；不得因为中途不利结果改变方法或停止选择性收集。

主指标为备用/W1来源等权几何平均吞吐倍率，先在同一case内平均重复的log比，再在来源内对case等权平均，最后跨三十来源平均；子集也沿用该层次避免不同重复数量造成不等权。来源重采样10000次。另列每次、每seed、方法先后顺序、全预算、无新增图和首图子集，以及来源留一敏感性。四次重复不能当作四倍独立来源。输出相同时同时报告配对耗时比。

逐条核验W1/备用生成token、EOS、长度、alpha与语义计数，以及恢复调用差额=备用命中；同一case跨重复的输出与计数也应相同。实际新增树节点和输入量单列。图前向与图创建事件均保留。

本轮专门核验增量，不追加原Target的慢执行；不借新结果外推新的相对原Target倍率或三维端到端倍率。三十来源已经用于此前实验，称作重复性验证，不称为全新数据的一次最终测试。生产默认、主工程、原服务及权重保留。
