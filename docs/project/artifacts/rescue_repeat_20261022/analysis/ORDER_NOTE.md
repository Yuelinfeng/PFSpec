# 重复运行顺序差异说明

本说明只解释 `repeat_analysis.json` 中的 243 条顺序差异，不改动原始记录或已有分析结果。

结论：这 243 条属于运行顺序元数据的判读提示，当前证据不支持把它们视为实质数据问题。

- 240 条为 `record_order_differs_from_plan`。分析器将计划中的方法先后与每个 case 的记录先后逐条比较；runner 会按批次主动轮换 `w1` 与 `rescue` 的先后，因此实际记录顺序在轮换批次中与计划顺序相反。方法身份仍由记录字段配对，未因行序改变而错配。
- 3 条为 `observed_source_order_differs_from_offset`。批次使用来源循环偏移，实际来源首出现顺序与按 offset 推出的顺序不同；这只影响顺序提示，不改变来源、prefix、seed、方法或 case 的字段配对。

只读复核得到：四批共 960 行、480 个 W1/rescue 配对，覆盖 30 个来源和 120 个唯一 case；每个 case 出现 4 次。W1/rescue 的输出与语义计数均为 480/480 相同，恢复调用差额与命中数为 480/480 相等。独立程序结果为 `status=passed`、`errors=[]`。

因此，243 条应保留为顺序元数据提示，不能据此删除记录、重排原始结果或否定重复批次的配对分析。后续分析应按稳定的 case 字段和方法字段配对，不能把文件行序当作方法或来源身份。
