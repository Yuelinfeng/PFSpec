# 理论独立审阅：T1–T7 与当前恢复实现

## 结论先行

2026-10-23主代理整合说明：审阅交付后，THEORY_NOTES.md已补明Z_F的实际输入、评估对训练结果的条件化、恢复成本零扩展和EOS质量为零的理想化前提。下文保留审阅时提出的问题，作为这些限定的来源。当前实际策略仍在Feature抽样前确定B；更一般地，B读取已抽Feature并不必然破坏T1的轨迹保持，但T2的固定集合质量公式需按其联合随机条件重新表达。两种性质不可混用。

当前真正改变的算法是：在固定 W1 的 Position 主提案、Feature 提案、接受规则、残差抽样与随机流顺序下，按 Ranker 分数预先加入一个或多个合法备用 Position 的 Target 条件状态；主 Position 被拒后，只有当既有残差抽样实际返回该 Position 时，才复用对应 Feature 行与 hidden/KV。它没有按 `m_b` 在线选集合，也没有把 `q` 训练成 T6 的条件 TV 最优解。

T1 与 T2 在固定参考映射和精确算术条件下可以成立。T3 与 T4 是受限集合选择和近似决策的标准结果。T5 只覆盖语义状态与执行状态都不受动作影响的理想局部模型；当前图、缓存、容量和首次建图行为使它不能直接描述实际请求。T6 与 T7 的概率表达、重加权分布和三角不等式界基本正确，真正的缺口在信息对象和评估分布没有完全绑定到当前 MLP：`Z_F` 是否包含 `a`、`h_prev` 及其全部输入尚需明定；`μ` 必须是动作外生的评估分布，或在给定训练数据后使用留出分布；`q` 的训练和在线随机性不能隐含在同一个条件均值里；TV 最优只说明联合推进量，不直接说明完整墙钟时间。

这份审阅把结果分为正确性、分析和未实现算法。当前可交付的论文主张应停在“固定参考过程上的恢复复用及其条件化成本分析”，并把 T6–T7 用作类型提案的诊断模型。CPU 有理数枚举和已有实测只作为有限实现证据；本轮不重复它们，也不把它们升级为一般证明。

## 1. 当前算法与完整状态

### 1.1 已实现的动作

`patches/spec_next_20261022/position_rescue_decoder.py:237-258` 从 Position Ranker 候选中按正类分数取主位置与备用位置。`position_rescue_decoder.py:385-399` 只有在剩余预算至少四个 token、且后续 Position 也能提出时才启用树；否则清空备用集合并走 K1 或普通路径。当前选择依据是 Ranker 顺序，代码没有读取本轮 Target Position policy，也没有估计 `m_b`。

`position_rescue_runtime.py:9-26,101-116` 把备用 Position 放在主 W1 路径的共同前缀旁边。一个备用时父节点为 `(-1,0,1,2,0)`；多个备用时仍是共同前缀下的 Position 兄弟节点。`verify` 只写入物理缓存槽，逻辑缓存位置保持不变；`commit` 只提交真实路径。备用命中以后从备用行抽 Feature，并保存该行 hidden；备用未命中时不把它的状态带入在线历史。

`combined_decoder.py:425-446` 在树验证前从真实 Feature 提案 `q` 抽取候选。主 Position 被拒后，先从原残差抽真实 Position；命中备用才提交备用行，否则提交共同前缀并做普通恢复前向。备用没有第二次接受测试。`combined_decoder.py:505-565` 仍按 W1 的 Feature 接受、残差抽样和 P2 分支运行。若启用该文件的 `reuse_weight`，`combined_decoder.py:429-433` 会把 Feature `q` 与缓存的 Target Feature policy 混合；这已经改变 W1 的提案映射，不能套用固定 q 下的 T1 结论，必须单列为另一动作。

### 1.2 语义状态、执行状态和随机流

适合写入证明的完整状态至少为

\[
 x=(h,\tau,K_{\rm logical},d_{\rm ranker},h_{\rm prev},n,\xi),
 \qquad g=(G,\,K_{\rm physical},\,r,\,\mathrm{capacity},\,u),
\]

其中 `h` 是已提交的完整 P/F 历史，`τ` 是下一类 token，`K_logical` 是 Target 已消费的逻辑 KV，`d_ranker` 是 Ranker 在线状态，`h_prev` 是 Feature 提案器实际读取的上一 Position hidden，`n` 是剩余预算，`ξ` 记录主随机流位置。`g` 还要记录图是否已建立、图的节点数和读桶、物理 KV 槽、缓存容量以及设备执行上下文。只写 `h` 或只写 `Z` 无法预测图冷启动、缓存容量和并发影响。

这里要区分三类量：

1. `p` 是同一合法性遮罩、温度和 top-p 之后的 Target policy。Position 残差使用该 policy；Feature 的 `P_s` 也必须是历史 `(h,a)` 下经过同样处理的 Feature policy。
2. `q` 是实际抽样所用的 Feature 提案分布。它由当前提案器输入决定，并在 Target 验证前抽取候选。若选择器观察了 `p` 或 Target hidden 后才改变 `q`，原有 `q` 的接受率公式需按联合条件重新写。
3. 备用集合 `B` 是预先确定的计算动作。它可以依赖 Ranker 候选、廉价状态和已经支付的提案成本；它不能依赖本轮尚未取得的 `p`，也不能观察 Feature 候选后继续使用观察前的 `q` 公式。

当前随机顺序是：先用 `q` 抽 Feature 候选；树中取得 P1、Feature、P2 和备用行；用 Position policy 做 P1 接受试验；P1 被拒后从 Position 残差抽真实位置；命中备用时直接从备用 Feature 行抽样；未命中且非 EOS 时做普通 Position 恢复前向，再抽 Feature；P1 被接受后继续 Feature 接受试验、Feature 残差、P2 接受试验与 P2 恢复。预计算本身不应消费主随机流；若未来选择器使用随机数，应使用独立流，或把新增消耗显式放入耦合映射。

### 1.3 适用轮、EOS 与浮点边界

恢复树只适用于：剩余预算至少四个 token、主 Position 与后续 Position 均可由 Ranker 提出、备用为互异合法的非 EOS Position。BOS 起步、K1、候选缺失、剩余预算不足四个 token、P1 残差直接抽到 EOS，均不进入备用收益公式。EOS 后不生成 Feature；把 EOS 放入 `B` 会产生无效节点。

T1–T7 的精确对象是离散分布和确定性 Target 算子。GPU 上的 FP32、算子重排、top-p 临界排序、稀疏位置遮罩、物理 KV 复制和图缓冲覆盖都会把精确等式变成数值近似。已有输出相同、计数相同和有限 policy 距离记录只支持所测输入与执行配置。若要从数值误差给出请求级界，需要约束整个转移核，包含提案、支持集、接受、残差、状态提交和停止事件；单行 logits 误差不够。

## 2. T1–T5 的独立审阅

### T1：固定参考映射下的轨迹保持

在以下对象固定时，T1 的耦合证明成立：完整语义状态、主提案 `a`、Feature 提案 `q`、备用集合 `B`、所有合法性规则、树中每一行的逻辑历史、提交路径和主随机流。备用行必须和普通恢复前向给出相同的 policy、hidden 与 KV；未选行不能改变后续物理状态。

T1 需要收窄三处文字：

- “任何合法 `B`”只适用于 B 在 Target 验证前确定、没有改动 `q` 和随机流的动作。若 B 由当前 `p` 选择，证明对象已经包含一次额外 Target 访问；若 B 由 Feature 候选选择，固定 B 的残差证明也不再直接适用。
- “同一个 `(s,ξ)`”中的 `ξ` 必须是主随机流，选择器的独立随机流另记。若把预计算的图执行顺序也混入同一 RNG，额外调用会破坏同一位置的说法。
- 语义轨迹保持不等于实际浮点逐元素相同。当前五节点实现仍需依赖树 attention、稀疏 rank mask、KV 物理槽与普通恢复路径的数值等价条件。

因此 T1 属于当前固定 W1 备用实现的正确性命题，结论应写为“相对 W1 的参考轨迹保持”。它不覆盖 `reuse_weight` 改变 Feature `q` 的运行模式，也不提供任意重训草稿的同种子保持。

### T2：恢复位置的概率质量

点提案 `q=δ_a` 且 `B` 在残差抽样前固定时，`Pr(H_b|s)=p_h(b)` 对合法非 EOS 的 `b` 成立；这是拒绝概率和点残差相乘后的直接结果。一般 `q` 下，固定候选和固定集合的事件质量为 `[p_h(b)-q(b)]_+`，前提是 q 已包含实际候选抽样分布，且 B 不依赖这次抽样的结果。

当前需要补足的边界是：`H_b` 应明确包含“本轮属于可用树轮次”的指示，或者在全轮统计中显式乘适用轮概率；否则命中次数会和条件命中概率混用。若 `b` 是 EOS，恢复位置事件可以有概率质量，但 `c_rec` 为零且不能拿来解释 Feature 复用。若 `p_h(a)=1`，残差分布不定义，相关收益项直接取零。

对实际 Feature `q`，不能把 P1 接受概率与 Feature overlap 当作两个无条件独立事件。正确写法是先条件于 P1 被接受和历史 `(h,a)`，再使用 `\sum_f\min(P_s(f),q(f))`。T2 只描述恢复 Position 的质量；它没有说明 Feature 提案训练或全轮成本。

### T3：等节点成本下的集合排序

当给定 `Z` 后所有候选身份带来的额外成本只依赖数量 `k`，且 `m_b` 不随集合身份和其他节点改变时，按 `m_b` 排序、枚举 `k` 并包含空集，确实给出局部精确解。这个命题的交换论证成立，属于标准决策工具。

它对当前实现的解释力有限：Ranker 分数没有被证明等于 `m_b`；备用节点会改变树形状、读桶、图缓存和物理写入；同一轮虽只会命中一个恢复 Position，节点之间仍会共享 Target pass 和设备资源。若 `d(Z,B)` 依赖节点身份，或 `m_b` 的恢复成本随 B 改变，排序结论失效。实际 `backup_count=1..4` 实验臂只是固定数量臂，不是按 `m_b` 排序的在线选择器。

### T4：估计误差与 `2(ε+δ)`

对固定 `Z` 和同一候选全集 `C`，若

\[
 \sum_{b\in C}|\widehat m_b-m_b|\le \epsilon,
 \qquad
 \sup_{B}|\widehat d(Z,B)-d(Z,B)|\le\delta,
\]

且优化器精确最大化 `\widehat F`，则 `F(B^*)-F(\widehat B)≤2(ε+δ)` 成立。只有逐候选误差 `ε_0` 时，最多 K 个节点给出 `2(Kε_0+δ)` 的相应版本。这个结论本身没有漏洞，漏洞在证据常被误读为满足假设：平均 MAE、单一来源误差、一次计时或有限几个动作都不能自动给出统一上界。

还需写清两点：

- 这是每个固定 `Z` 的点态界。要给部署策略的总体后悔界，需要对所有会出现的 `Z` 给出统一界，或给出按部署分布加权的误差项。
- `d(Z,∅)=0` 只在选择器不运行或其公共成本已从所有动作中扣除时成立。若每轮都先运行选择器，空集也要承担该成本。

### T5：局部收益到整请求

T5 的结论在很窄的模型中成立：动作保持同一语义轨迹和轮次边界；未来的 `g`、容量、并发、图驻留、内存和总节点预算都不变；动作不改变后续可用集合；状态分布对动作保持一致。此时逐轮收益可加，按 `Z` 最大化局部 `F` 确实最小化期望总时间。

当前实现不满足这些条件。备用运行时拥有自己的图组；第一次使用某节点数会建立图；图布局和读桶与节点数绑定；物理 KV 槽和缓存容量会影响后续运行。备用数量、`reuse_weight` 和树路径也会改变设备状态以及未来耗时。即使语义输出分布在精确算术下保持，`g` 仍可变化。因此实际对象应写为有限状态成本过程

\[
 V(x,g,n)=\min_{B\in\mathcal A(x,g,n)}
 E[C(x,g,B)+V(x',g',n')\mid x,g,B],
\]

并把 EOS、提交 token 数和预算耗尽作为停止转移。当前没有求解这个方程，局部 F 不能推出实际整请求最优。

## 3. T6–T7 的独立审阅

### 3.1 T6 的概率式成立范围

在一个无 EOS、预算至少四个 token、P1 与 P2 均存在的正常 W1 轮次，设主 Position `a` 已由 Ranker 确定，

\[
 w(s)=p_P(a\mid h),
 \qquad P_s(f)=p_F(f\mid h,a),
\]

二者均指经过同一合法性处理、温度和 top-p 的 policy。若 Feature 提案在 P1 接受前已确定为 `q`，且其随机抽样与 P1 接受试验使用独立随机数，则

\[
 \Pr(A_P\cap A_F\mid s)
 =w(s)\sum_f\min(P_s(f),q(f))
 =w(s)(1-\operatorname{TV}(P_s,q))
\]

成立，其中本文必须明定 `TV(P,Q)=\frac12\|P-Q\|_1`。这不是把两个接受事件当成独立事件；第二项是条件于 P1 已接受后的 Feature 接受概率。

正常轮次的 `E[R|s]=2+2w(s)(1-TV)` 也成立，因为 P1 与 F1 同时有效时多提交一个完整 P/F 对，P2 接受与否只改变 P2 的恢复成本，不改变该前提下的提交量。

### 3.2 T6 的四个真实建模漏洞

第一，`Z_F` 必须包含 `q` 实际读取的所有信息。当前 Feature 提案器输入包括前一 Position 的 Target hidden、前一 Feature 和当前候选 Position；若 `Z_F` 只写成一个不含 `a` 的压缩特征，`q_Z` 不能表示实际提案器。可行写法是 `Z_F=ψ_F(s,a)`，或把 `a`、`h_prev`、前一 Feature 以及所有廉价辅助量明确列入 `Z_F`。否则 T6 优化的是另一个策略类。

第二，`P_s` 必须是 `(h,a)` 后的 Feature policy。写成 `p_h(f\mid h,a)`容易让人误解为对已经包含 `a` 的历史重复条件；建议全文统一使用 `p_F(f\mid h,a)`，并注明合法 mask、温度与 top-p 已在其中。

第三，T6 所需的是动作外生的评估分布。数学上不必要求 `q` 与 `μ` 永远相互独立：可以先用训练样本拟合 q，再在给定训练结果的条件下从独立留出 `μ_eval` 评估。必须避免以下两种混用：

- 用同一批状态和标签同时选择 `q`、估计 `\mathcal R_z`，再把训练内风险当成泛化结论。
- 把 q 改变后的执行状态、图驻留或浮点输出所诱导的状态分布仍记为原来的 `μ`。这时应写成 `μ_q`，或只声称单轮固定状态分析。

因此，T6 中“与本次 q 选择无关”应改为可验证的条件：`μ` 是固定的部署状态分布；q 在评估前已确定，或评价对训练随机性条件化；当前动作不改变本轮状态分布。若 q 由当前 Target policy 访问决定，`w` 与 `P_s` 也需要按该访问动作重新条件化。

第四，T6 优化的是联合推进量，忽略 q 的计算时间、候选抽样、显存占用和后续图状态。网络容量变大可能减少 TV 却增加提案成本。若目标是时间，应把 q 的计算与设备影响加入 `C(s,g,q)`；`q_z^*` 只在成本固定或另有预算约束时才是合适目标。

### 3.3 T6 中 `ν_z` 的正确含义

在 `\bar w(z)>0` 时，

\[
 d\nu_z(s)=\frac{w(s)}{\bar w(z)}d\mu(s\mid Z_F=z)
\]

确实是联合推进事件对状态的重加权分布。它强调高 `w` 的状态，因为这些状态的 Feature overlap 更有机会带来第二个 P/F 对。`\bar w(z)=0` 的组不应定义 `ν_z`，也不产生联合推进收益。

这里有两个必须写进方法定义的条件：`μ` 只在可提出主 P1、P2 且未 EOS 的正常轮中取样；连续 `Z_F` 不能把“恰好相同的 z”当作有重复样本，必须预先定义离散化、核权重或参数化条件模型。实际 high-dimensional hidden 可能几乎没有相同值，任意事后分箱得到的 `D_z` 只反映分箱方案。

若 q 还依赖随机变量 U，例如采样温度、dropout 或候选抽样，策略对象应写成 `q(·|z,u)`，并对 U 求期望。把随机 q 先取均值再代入 TV 通常会改变目标，因为 overlap 对 q 的关系需要按实际抽样分布求平均。

### 3.4 T7 的界与含义

给定 `z` 后，令 `S,S'` 独立服从 `ν_z`，定义

\[
 D_z=E\,TV(P_S,P_{S'}),\qquad R_z^*=\min_q E\,TV(P_S,q).
\]

三角不等式给出 `R_z^*≥D_z/2`；取 `q=E[P_S]` 并使用 TV 对第二个参数的凸性，给出 `R_z^*≤D_z`。T7 的代数成立。`.8/.2` 的两个点质量例子也确实说明，条件均值 `(0.8,0.2)` 的 TV 风险为 `.32`，选 `(1,0)` 的风险为 `.2`；它只说明 CE 与 overlap 目标不同。

T7 需要避免三种更强的解读：

- `D_z>0` 是相对于给定 `Z_F`、`μ` 和 `ν_z` 的条件异质性量，不是对任何完整历史算法的计算下界。完整 `h` 可见时，`p_F` 数学上由 `h,a` 确定；“尚未运行 Target”是受限 oracle 的时间约束。
- `R_z^*` 是全体概率向量中的表示上界。实际 MLP、temperature、top-p、有限参数 softmax 和跨 z 参数共享形成更小的策略类，真实最优风险只能更高。CE 的条件均值结论还需要总体分布 CE、无限数据、无正则和同一 support 设定。
- `D_z` 的估计需要不同完整状态的 Target policy 与独立 W1 抽样。单个状态的一次命中或一次随机轨迹只能估计接受事件噪声，不能识别状态之间的 `P_s` 差异。

所以 T7 可以解释“固定压缩输入可能造成匹配损失”，不能解释当前 Feature MLP 已达到信息上限，也不能单凭接受率平台期认定网络容量无用。

## 4. 成本分解的可识别性

### 4.1 `m_b` 的定义需要反事实扩展

\[
 m_b(Z)=E[\mathbf 1_{H_b}c_{\rm rec}(s,b,\xi)\mid Z]
\]

适合表达“事件质量乘命中时可省的恢复时间”。为使式子严格，`c_rec` 要在 `H_b` 外定义为任意零扩展，或改写为

\[
 m_b(Z)=P(H_b\mid Z)\,E[c_{\rm rec}\mid H_b,Z].
\]

当前日志中的备用命中计数、命中排名和总恢复调用可以估计部分事件质量；它们没有自动给出每个候选的反事实恢复时间。未命中 `b` 的轮次不会观测“若这次残差返回 b，普通恢复前向要花多少时间”。离线识别至少需要以下一种来源：

- 在相同完整前缀上保存 Target policy，并用独立残差抽样或精确枚举估计 `P(H_b)`；
- 在相同缓存、图冷热状态和输入长度下测量候选 `b` 的普通恢复前向；
- 用同一前缀的成对动作与共享随机流估计完整成本差。

### 4.2 `D` 不能同时当作分项因果量和总差额

把 `D(s,g,B,ξ)` 定义为除被替代恢复外的全部净变化，能得到路径级记账恒等式；这一定义本身没有给出可独立测量的分项。图创建、KV 物理写入、读桶变化、GPU 调度和缓存复用彼此交互，某一分项移出后会改变其他分项的数值。

因此建议把 `D` 分成两个层次：论文理论中的完整配对差额 `D_total`；工程诊断中的节点、图、KV、选择器等观测计数。只有在相同前缀、相同 `g`、相同随机条件的动作对照中，才可把 `m_b-d_B`解释为动作效果。分开的微基准可以解释机制，不能单独识别在线动作的因果收益。

图首次建立会影响后续轮次和后续请求。将其全部记在当前轮 `d(Z,B)` 会依赖轮次切分；将其排除又会低估完整成本。只要 `g` 受动作影响，局部 `F` 只能用于预测，整请求必须使用 `(x,g,n)` 的状态转移。

### 4.3 `p/q`、`μ` 与成本模型的联动

固定 W1 恢复集合时，`q` 和语义轨迹按 T1 固定；T2 的 `H_b` 可直接解释。Feature q 被重训、混合或改变输入后，输出仍可能在精确拒绝抽样下服从同一 Target 边缘分布，但与固定 q 的随机轨迹不同，当前状态序列和图耗时路径也可能不同。此时 `m_b(Z)`、`d(Z,B)` 和 T6 的 `μ` 不能默认沿用旧 q 的数据分布。

这给出一个具体的可证伪建模问题：预先固定一组 `Z_F` 表示和正常轮筛选规则，在训练来源上拟合 q，在独立来源上记录完整 `P_s`、`w(s)`、实际 q、重复残差事件和冷热图状态。若按 `ν_z` 加权的 `D_z` 与零值的置信区间重叠，或 TV 风险较低的 q 在计入提案时间后不能改善 Feature overlap 与完整吞吐，则“压缩信息损失解释当前容量瓶颈”不成立；若 `D_z>0` 且加权 TV 目标在相同提案成本下改善留出 overlap，却不改善墙钟，则信息模型成立、时间模型仍需补充。这一问题能区分状态异质性、训练泛化和设备成本三种原因。

## 5. 两项已提出但尚未实现的算法方向

本节只保留主线已有的两个方向，不增加新的方向。二者都应标注为“尚未实现”，并与当前固定 Ranker 备用实现分开。

### 5.1 提案前的恢复集合选择

给定完整运行状态 `(x,g)` 的廉价压缩信息 `Z`，先由 Ranker 给出合法候选全集 `C(Z)`，再在 Target 验证前选择

\[
 B=\pi(Z),\qquad B\subseteq C(Z),\quad |B|\le K.
\]

策略不能访问本轮 `p`，也不能观察 Feature 候选后改变 B。固定 W1 点提案时，`m_b(Z)`按 `H_b` 的命中质量和普通恢复时间定义，`d(Z,B)`包含新增 Target 节点、图与 KV 操作、选择器时间及资源交互。局部目标是最大化 `F(Z,B)=\sum_bm_b-d`。

可证明命题：若 `d(Z,B)=d_k(Z)`只依赖 `k=|B|`，`m_b` 与集合身份无关，且未来 `(x,g)` 不受 B 影响，则按 `m_b` 降序取得前 k 个，并枚举 `k=0,…,K`，是该局部动作类的精确解。证明只用交换论证；它不构成新的树优化理论。

反例：两个候选的恢复收益为 `m_1=.9,m_2=.8`，选择一个节点的身份成本为 `d({1})=.6,d({2})=0`。按收益排序会选 1，净收益 `.3`；选 2 的净收益 `.8`。因此实际图节点身份、读桶或缓存冲突存在时，Ranker 或 `m_b` 单独排序不足以保证动作正确。

与标准树优化的重合风险在于：候选集合、节点预算、期望推进和硬件成本的组合已经是常见的树选择表达。真正可辨认的差异只能来自当前 P/F 恢复事件与可重复的执行收益；若没有预验证选择器、留出来源收益和同条件树方法对照，它应作为成本分析补强。

### 5.2 有限预算下的成本选择

令完整状态为 `(x,g,n)`，动作集合包含固定 W1、不同备用数量和其他已经存在的验证配置。动作 `A` 产生提交长度 `R_A`、成本 `C_A`、下一状态 `(x',g',n')`。严格目标是

\[
 V(x,g,n)=\min_A E[C_A+V(x',g',n')\mid x,g,n,A],
\]

EOS 和预算耗尽取终止值。只有在所有动作共享同一后续语义与执行状态、没有跨轮节点预算、且 `Z` 的分布不随动作变化时，才可退化为逐轮最大化 `F`。

可证明命题：在上述退化条件下，若每个 `Z` 的条件收益 `F(Z,A)` 可精确获得，策略 `π(Z)∈argmax_A F(Z,A)` 最小化期望总成本。反例：动作 A 当前成本 1、动作 B 当前成本 2；A 让下一轮图状态带来额外成本 100，B 不带来该成本。局部选择 A 的总成本为 101，选择 B 的总成本为 2。这个反例正对应当前图驻留和冷启动风险。

该方向与标准有限状态决策和硬件感知树选择高度重合。论文若保留它，应把新内容放在 P/F 类型的恢复状态如何形成动作标签、以及成本预测能否在留出来源上改变真实选择；标准递推式和局部比值本身不提供新颖性。
