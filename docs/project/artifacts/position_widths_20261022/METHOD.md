# 多备用位置的执行语义

本轮只增加首个 Position 的备用路径。主路径节点为 pendingF、P1、F1、P2，备用节点 P1b_i 均与 P1 共享父节点 pendingF。每个备用只计算自己的 Feature 分布与 pre-finalnorm hidden；没有 Feature 草稿子树。

Ranker 在当前 Position 候选上执行一次 predict_proba，保持原首候选与相同分数的原顺序。前 k 个剩余候选组成备用集合，实际候选不足时缩小。k 是固定数量上限，未设计动态启用策略。

接受判定和残差抽取保留原规则。P1 被拒绝后，先抽取实际位置；若命中备用 i，则提交节点路径 [0,4+i] 并复用该节点的 Feature logits 和 hidden。未命中时提交 pendingF 后做原普通恢复前向。备用命中不算 Position 接受，也不额外抽随机数。

原首候选为点提案。当 p(P1)<1 时，拒绝后的分布在其他 token 上为 p(P)/(1-p(P1))。备用集合的条件命中率为其 Target 概率质量之和除以 1-p(P1)。EOS 保留在拒绝分布中，不能成为备用 Position。p(P1)=1 时没有拒绝事件，条件值在诊断中记零。

候选数量变化需要分别捕获不同节点数的图，缓存按实际备用数与原读取长度分组。一次成功验证必须提交或清空，禁止重入；不同备用路径不能读到彼此的节点。KV 提交保留原实现的路径合法性和缓存长度要求。

第 k 个备用的边际收益来自多省的恢复调用，成本包括新增验证节点、索引、KV 提交、缓存及首次建图。局部数值和同步成本测试用于解释，完整 token 解码仍为最终速度证据；不能用局部成本乘次数代替真实请求测量。

补充成本测试使用同一 DynamicTargetGraph 接管短恢复调用；另采样 W1 四节点与5/6/7/8节点的同步暖态验证成本。每次树验证后清空待提交状态并保持相同前缀。T1恢复在同一缓存位置重复，正式统计前先完成一次暖态调用。输出clone、逐项比较和后续生成分开计时，首次建图与预填充不进入暖态均时。该固定前缀成本不代替完整解码结果，也不宣称其覆盖真实拒绝轨迹。
