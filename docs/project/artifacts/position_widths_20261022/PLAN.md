# 备用 Position 数量比较

本轮固定比较原 Target、W1 和 1/2/3/4 个备用 Position。不训练、不调 Feature 提案、不增加动态策略，不替换生产默认。主问题为新增备用排名能减少多少恢复调用，以及额外 Target 节点和缓存提交是否抵消收益。

先使用已有 position_overlap_run01.json 的完整 Target policy 做 CPU 累计质量分析。该资料属于十开发来源、39 个教师前缀，不能作为在线命中率或加速比。短 GPU 数值和成本测试对每个备用节点分别对照普通前向、Feature policy、hidden、KV 提交和后续执行，记录冷态建图及暖态成本。正式计时关闭诊断。

完整解码使用既有三十来源、64/256 前缀、新 seed53101、512-token 上限和六臂同轮配对。方法顺序按请求轮换，正式各臂首次建图计入时间，预热对象丢弃。FP32、TF32 关闭、temperature/top-p=.9/.9，Target/VQ/Ranker/step12000 MLP 均保留。候选不足时使用实际可用数量，按节点数各自复用图。

本轮新增 GPU 进程累计墙钟上限 1200 秒，包含模型载入、预热和正式计算。数值测试、短解码和主测分别设置有限时长；主测在开始新六臂配对组前预留足够时间，若预算不足停止于完整组。若外层超时仍留下部分组，保留全部原始记录，仅在主统计使用完整六臂组。上一批已经结束的四次重复不计入新预算，不重跑。

统计使用实际生成 token / 同步后的外层耗时，来源内配对 log 倍率平均后跨来源等权。分别给出相对原 Target、W1、单备用和相邻备用数的倍率、10000 次来源重采样区间、满512及无新增图子集。输出与接受计数逐条对照，恢复调用差额须等于备用命中，备用命中不算提案接受。按排名累计命中与额外输入/节点分别报告。
