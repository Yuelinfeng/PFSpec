# 恢复价值决策：证据实验

目标命题：验证前可用信息能够预测备用分支的计算收益，并在独立来源上优于固定选择及简单概率排序，完整请求仍获得净收益。正结论以实际数据为准。

本轮沿用原 Target、VQ-VAE、Ranker 与已选 Feature MLP；不改变神经权重、参考抽样和生产入口。所有新源码与输出进入 recovery_value_evidence_20261023 独立目录，既有结果保留。

1. 对原十个开发来源进行概率分布、候选排序与预测误差分析。原八个训练来源和两个验证来源仍按原清单使用；过去二十个评价来源已被阅读，本轮只能作为开发数据。
2. 在原开发数据上比较四个预先列出的浅树概率估计器，以来源等权备用概率均方误差选择容量。纯 Python 推理须与 sklearn 数值相同。Target 概率只作为训练标签。
3. 补测同一缓存位置的验证、真实路径提交与单 token Target 恢复。分别记录首次建图和温态重复，保护缓存与随机数状态。该测量只覆盖所列操作，不能称为完整解码决策的精确最优值。开发诊断最多 300 秒 GPU 外层墙钟。
4. 用实际动作成本建立价值选择，并与同一执行入口的固定零/一备用、简单 Ranker 分数选择、概率选择对照。先在旧来源上做开发评价；来源、前缀、seed、生成上限和轮换次序保持配对，所有输出须与参考过程一致。开发评价最多 600 秒外层墙钟。
5. 只有开发结果足以支持继续，才采集未使用的来源组。独立来源、模型容量、成本模型、阈值、比较对象在读取评价收益前写入具体运行清单。正式解码与完整三维请求分别在两个进程测量，启动前给出有限时长。若开发结果无法支持关键命题，保存数据并明确剩余缺口，不把参数搜索写成独立确认。

统计同时报告来源等权时间比与累计墙钟时间比，按来源组重采样区间。只有动态价值相对强对照的独立收益、完整请求净收益、实现正确性三项均得到支持，才报告关键证据成立。

意外结果先核验代码、参数、状态恢复、计时范围及输出，再解释研究方向。没有完整动作标签的上下文不填零，也不称为已测最优选择。
