# 开发评价运行清单

概率估计器：原八个训练来源学习，原两个验证来源按备用概率均方误差选择浅树容量，最终 64 棵深度 2 的树。控制规则的阈值只按八个训练来源的操作收益代理选择：Ranker 分数阈值 0.05，预测拒绝概率阈值 0.15。

动作成本：33 个开发状态，缓存读取长度 128/256/512/1024；各动作三次同步重复，包含真实提交与普通 Target 恢复。成本取各长度的中位数。新价值策略使用各长度的成本与预测主/备用概率；概率规则使用全局成本中位数。两者都在正式墙钟中支付首次建图费用，当前启发式没有优化首次建图决策。EOS 概率与 Feature 后续分支比例尚未单独预测，已在模型元数据列为限制。

下面配置在读取本轮速度结果前确定：

- 输入：原 `stage_c/dev_crops.pt` 的十个来源，前缀 64/256，新 seed 60201，新生成上限 512。
- 七种方式：同一入口固定零备用、固定一个备用、新操作价值、全局概率规则、训练阈值 Ranker 规则、相同动作数的 Ranker、预测接受率规则。
- 两个独立进程，第二进程轮换来源起点与方式顺序；每个 140 条，共 280 条。方法分别持有自己的执行对象与图，首次图和回调计入墙钟。
- 每进程外层最多 290 秒，内部 270 秒；开发总外层上限 600 秒。模型加载与短预热留在每条请求计时外。
- 逐 token、EOS、长度及接受语义应一致，备用少用的 Target 调用应等于命中数。运行异常或不符预期时先核验实现与参数。

这一轮仍使用旧来源，任何正收益都只作为开发证据。若价值选择在两个进程里均有稳定的强对照优势，再制定未使用来源与完整三维请求的正式确认清单。来源等权比值和累计墙钟比值同时报告，不能以局部操作节省替代完整收益。
