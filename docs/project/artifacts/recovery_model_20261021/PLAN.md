## 输入与动作

沿用已测 W1 的 Target、Ranker、12k MLP、FP32、温度与 top-p 0.9；不训练新神经网络。独立复制诊断解码器，原已测源码与权重保留。动作 K1 是预算 2 的一对路径，W1/W2 是预算 4 的完整树路径，各执行一轮。它们共享输入前缀和随机种子，随机数消耗可不同。

开发数据为 `stage_c/dev_crops.pt` 的十个来源，每来源在 64、256、512、1024 token 处取第一条足够长的裁剪。一个来源最长 570 token，因此共有 39 个上下文。初定八个种子，从 46101 开始，三个动作，936 个唯一观测；同种子计时重复三次时共 2808 行。真实输入、动作顺序、裁剪路径和随机种子均保存。先运行小规模真实 GPU 对照，确认克隆与原解码器输出及共有计数相符，再采集开发矩阵。

动作拥有跨上下文复用的运行时，执行顺序轮换。前缀准备、预填充、单轮同步墙钟、完整调用墙钟分别记录。首次建图与已复用状态分开分析。诊断同步与状态提取的开销要明确；单轮标签不能直接当作完整请求加速。

## 拟合与评价

输入仅用决策前可以取得的低成本状态。当前 Target 概率、接受结果、恢复事件与实际耗时只用于标签或诊断。已支付提案计算后的 q 特征与提案前状态分别报告。相同上下文的计时重复先聚合，随机种子用于估计动作期望，不能以逐种子最佳动作冒充可实现策略。

开发评价按来源留出，比较固定 W1、接受量目标、节点或验证耗时目标、直接进展/成本目标以及恢复分项模型。报告排序、选择损失、误差与选择开销。局部 `E[R]/E[C]` 只表示已测状态下的进展率，不提供完整序列最优保证。
