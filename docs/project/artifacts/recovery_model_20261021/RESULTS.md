# 同前缀恢复成本：实现、验证与阶段结论

**结论：保留静态 W1，当前不继续实现在线预算选择。** 十来源开发测量没有显示恢复分项模型能稳定优于固定 W1；它与直接分别预测进展和总成本的模型，在 39 个状态上选择完全相同。通用进展/成本目标与学习式选树已有相关工作，不能把这些形式单独作为新的理论贡献。

本轮补齐了同前缀探针、实际成本标签、来源留出评价与相关工作比对。没有新的完整请求或端到端加速结论。此前的 4.966× token 测量和 4.335× 固定长度端到端结果仍按各自原始范围引用。

## 1. 已完成的范围

复用原三名 gpt-6-luna/max，分别完成探针与采集、CPU 分析和文献及源码审阅；主代理执行 GPU、独立复算与整合。

- 主测：10 来源、39 个真实前缀状态、8 个种子、K1/W1/W2、3 次计时重复，共 **2808/2808 行**。64/256/512 token 覆盖十来源，1024 覆盖九来源；一个来源仅有 570 token。每来源每长度选择第一条足够长的裁剪，路径与 crop seed 保存在 `dev_run01/prompts.json`。
- 分项诊断：同十来源、64/512、相同八种子、三个动作、一次计时，共 **480/480 行**，独立程序运行，未与主测耗时混合。
- 动作语义：K1 以预算 2 运行一对路径；W1/W2 以预算 4 运行一个完整树轮。`max_rounds=1` 在首轮结束停止，避免原预算 4 请求可能执行两轮的问题。
- 运行设置：RTX 4090、PyTorch 2.8.0+cu129、FP32、TF32 关闭、温度和 top-p 均 0.9、CPU 线程数 1、KV 容量 2048。Target、Ranker、12k MLP 与已测 W1 相同；未追加神经网络训练。

主测程序总历时 370.675 秒，分项程序 56.875 秒，包含加载与记录写入，不等同于 GPU 核函数活动时间。主测动作各有跨状态复用的运行时，执行顺序轮换。

## 2. 计时与统计定义

主成本 C 为预填充完成后、单轮开始至 CUDA 同步结束的墙钟。它包含 Ranker、提案、验证、随机采样、恢复和 KV 提交；运行时创建、适配器准备和预填充分别记录。首次图创建发生在实际前向中，已经进入该轮墙钟，不能再次相加。

主要分析使用已复用图的记录。同一上下文、种子和动作的计时重复先取中位数；再用八个种子估计该状态的 E[R] 与 E[C]。先按来源汇总所选动作的进展/成本，再计算相对 W1 的来源等权几何平均。来源区间重采样 2000 次，种子区间另做 1000 次配对重采样；它们分别描述不同不确定性，未合并为一个区间。

输入限于已有前缀长度、最新两个 Position 的真实 rank 与间隔、末个已知 Feature 类别，以及动作计划的节点数和读桶。当前 Target 概率、接受结果、恢复次数、实际执行形状和计时均未作为选择输入。按整个来源留一拟合，未随机拆分轮次。末个 Feature 使用类别编码，其整数 ID 不被解释为有序数值。

恢复模型训练时使用真实恢复次数拟合 `C=b(x,a)+d(a,length)·Nrec`；留出预测时以模型估计的 E[Nrec|x,a] 代入。局部 E[R]/E[C] 不提供完整序列最优保证。

## 3. 主结果：没有稳定选择收益

以下全部是**单轮局部进展率相对固定 W1**，未包含在线选择执行，也不包含完整请求的预填充和结束处理。

| 留源模型或简化对照 | 相对 W1 | 95% 来源区间 | 39 状态的选择 |
|---|---:|---:|---|
| 固定 W1 | 1.0000× | — | W1：39 |
| 只预测进展 | 0.9981× | [0.9654, 1.0310] | W2：39 |
| 节点与上下文成本 | 0.9981× | [0.9654, 1.0310] | W2：39 |
| 接受数/成本 | 0.9937× | [0.9610, 1.0305] | W1：5，W2：34 |
| 直接预测 R/C | 1.0102× | [0.9844, 1.0435] | W1：31，W2：8 |
| 分别预测 R 与 C | 0.9875× | [0.9537, 1.0205] | K1：3，W1：28，W2：8 |
| 恢复事件成本模型 | 0.9875× | [0.9537, 1.0205] | K1：3，W1：28，W2：8 |

这些是已有三个动作上的小型线性预测对照，没有完整复现 Sequoia 或 OPT-Tree 的树构造和策略，不能将表中名称等同于原论文实现。

恢复模型与分别预测 R/C 的动作 **39/39 相同**。直接比值模型的点估计只有约 1%，来源区间跨过 1，配对种子区间为 [0.9996,1.0214]，当前没有稳定净收益依据。本机 CPU 三动作评分中位约为十几至几十微秒；这不是远端在线成本，前缀特征维护也尚未接入真实选择循环，因此表中倍率不扣除这项本机计时，更不称为在线加速。

独立从原始暖图记录和导出的选择重新评分，八个模型的点估计全部一致。固定 K1/W1 为 0.9741×，固定 W2/W1 为 0.9981×；前者的独立来源区间为 [0.9179,1.0323]，后者为 [0.9652,1.0329]（独立复算使用 10000 次重采样）。

## 4. 成本模型解释了什么，仍缺什么

| 动作 | 每轮平均实际提交 R | 平均 C（毫秒） |
|---|---:|---:|
| K1 | 2.0000 | 7.6783 |
| W1 | 2.3846 | 8.8323 |
| W2 | 2.5769 | 9.5472 |

这张表按 312 个状态×种子观测求算术均值。W2 的进展约增 8.06%，成本约增 8.09%，总体优势很小；主要倍率仍采用上面的来源等权定义。它与此前三个来源的完整 512-token 结果 W2/W1=0.9603 属于不同输入与计时范围，不替换旧结果。

来源留出的 R 预测平均 MAE 为 0.3389 token；直接总成本预测 MAE 为 1.3352 ms，恢复事件模型为 1.3324 ms，仅减少约 0.0029 ms。恢复次数预测平均 MAE 为 0.3550 次/轮。这说明当前低成本状态对恢复的预测仍弱，增加分项表达没有带来清楚的决策改善。

恢复本身确有成本。分项诊断中，发生恢复时的 Target 恢复事件区间中位为 K1 3.781 ms、W1 3.648 ms、W2 3.718 ms。此处是 CUDA 流事件区间，可能包含主机提交间隙，不解释为纯 GPU 核函数时间。恢复模型按动作合并后的平均边际斜率均为正，约 2.41–3.37 ms/次，仍仅作预测诊断；共享项与动作项线性相关，不能给单个回归系数附加因果含义。

同一组有限种子上，逐状态看过结果再选最佳动作的局部倍率为 1.0868×；用四个种子选动作、另四个评分的均衡半切分为 1.0542×。它们提示动作可能存在差异，也显示同集选优偏乐观。二者都不是跨来源在线策略效果，不能写成已取得 5% 或 9% 新加速。

## 5. 理论和论文主张的调整

[相关工作比对](NOVELTY_REVIEW.md)覆盖九篇原始论文和一篇综述。Sequoia 已使用预期生成量与实测验证/草稿成本选择树；2026 年 Dynamic Delayed Tree Expansion 已使用根状态与系统耗时训练轻量选树网络。P/F 对进展公式与 EOS 项可嵌入普通状态转移奖励，标准残差采样也有明确出处。

因此，本轮不把通用比值目标、pair 计数恒等式、EOS 扣减或线性选择器当作新的通用理论。当前支持的论文主线仍为：异构 Position/Feature 提案与类型化执行协同，以及接受改善为何未转化为速度的实测分析。恢复成本细分保留为可复现解释与负结果，暂不作为有效新算法模块。

后续真正影响论文可信度的是同轮贡献分解、质量、另一模型或硬件及可比的强实现对照。当前不继续用相同开发记录调整特征、模型容量或超参数来追求正倍率，也未读取本轮保留的外部测试来源。

## 6. 验证与限制

- 最终探针 32 项 GPU 对照通过：首轮输出、提交量和接受长度，以及完整 16-token 输出和共有计数。首版另有 32 项通过，二者分别保存。
- 2808 行主测与 480 行诊断的独立 JSON 审核通过；936 组唯一主测动作观测的重复输出相同，1872 个树轮及 936 个一对轮的提交量与 Target 调用关系相符。分项诊断与对应主测输出 **480/480 相同**。
- 本轮没有 EOS 样本，不能新增 EOS 概率或自然结束收益结论。原理论中的 EOS 推广仍依赖既有自然结束计数与代码路径分析。
- 24 条首次建图记录单列；三动作共同冷图样本仅七状态、三个来源、各一种子，不据此训练可靠冷启动选择器。
- 有限精度范围沿用已测 W1 的验证证据；本次对照覆盖所选真实前缀，不证明任意输入逐位相同。BOS-only 不在本次探针范围。
- 来源与种子区间均固定已得到的留源选择，不重新拟合每次重采样的策略；同一来源仅少量真实裁剪前缀，未覆盖部署中的全部生成中间状态。

CPU 分析初版的种子重采样使用了不合适的低位取余随机序列，八个种子时区间退化。最终改为标准 `random.Random(...).choices`，并加入非退化样例验证；点估计和动作不变。**正式统计只用 `dev_analysis_v2.json`**，旧 `dev_analysis.json` 保留供追溯。采集入口首次导入失败日志亦保留；正式数据来自后续通过的 `source_run03/`。
