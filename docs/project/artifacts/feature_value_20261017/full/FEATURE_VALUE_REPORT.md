# GaussianGPT：Feature 条件收益分析（成本路线 B1）

2026-10-17。范围：开发数据、FP32、现用 Position Ranker + Feature MLP、固定 PF-K2。

## 结论

**Feature 的有效推进收益随上下文变化，现有证据更支持 H1。生成前的信息能够预测部分接受概率差异，但还不足以证明动态选择优于固定 PF-K2。**

最明显的可用线索是首个候选 Position 的间隔：间隔为 1 的组中，PF/P-only 为 **1.190×**；间隔大于 1 的组为 **0.970×**，后者区间跨过 1。这个线索值得后续验证，当前还不能据此宣称新算法提速。

本轮没有训练神经 Draft，没有增加 P₂ Head，没有实现在线调度，也没有新增完整三维生成测试。

## 1. 数据与可复用证据

沿用 A1–A3 的 10 个开发来源、28 个场景与初始长度组合。补采了 56 条 PF 轨迹的概率标签，共 5,122 个轮次，其中 5,078 个包含完整 P₁/F₁/P₂ 候选。另重放 448 次 PF 单轮试验，逐 Token 输出、分支及计数均与原记录一致。

**所有速度结论仍来自 A1–A3 的低干扰计时数据**：56 个固定前缀，每个前缀分别运行 8 次 PF 和 8 次 P-only，共 896 次。补采概率时增加的操作不参与速度比较。

56 个前缀包含 28 个真实初始前缀及 28 个 PF 生成中间前缀。置信区间按来源重采样，速度比采用来源等权几何平均。同一来源的重复轮次不能当作新的独立场景。

## 2. Feature 的价值怎样定义

在相同前缀及首个位置候选下，计算：

\[
A_P(h)=p_T(P_1\mid h),\qquad
A_F(h)=\sum_f\min\{p_T(f\mid h,P_1),q_F(f\mid h,P_1)\}.
\]

`A_F` 是完整 Feature 分布的重合度，对应条件接受概率。Position 使用点分布提案，因此连续接受 P₁/F₁ 的概率是 `A_P × A_F`。

没有 EOS 的普通轮次满足：

\[
C=2+2\mathbf1(P_1,F_1\text{ 均接受}).
\]

因此 Feature 的收益还依赖 P₁ 是否被接受。只提高 Feature 接受率，不能保证净速度提高。

同前缀测得的收益与成本如下，后两项采用来源等权平均：

| 指标 | 结果 | 95% 区间 |
|---|---:|---:|
| PF/P-only 单轮推进效率比 | 1.141× | [1.085, 1.195] |
| 每轮额外推进量 `G` | 0.496 Token | [0.371, 0.604] |
| 每轮额外时间 `C` | 1.856 ms | [1.388, 2.204] |

时间差包括第二次 Position 提案、较长 Target 验证和各分支处理的净变化，不能解释为 MLP 单独的耗时。该 1.141× 是同前缀单轮结果；A1–A3 固定窗口的 1.171× 使用另一计时范围。

## 3. 哪些条件下收益更明显

以下是开发数据上的探索性分组，仍需使用更多独立开发前缀确认。

| 分组 | 固定前缀数 / 来源数 | PF/P-only | 95% 区间 |
|---|---:|---:|---:|
| 真实初始前缀 | 28 / 10 | 1.059× | [1.004, 1.118] |
| PF 生成中间前缀 | 28 / 10 | 1.208× | [1.114, 1.315] |
| 首个 Position 候选间隔 = 1 | 40 / 10 | 1.190× | [1.117, 1.261] |
| 首个 Position 候选间隔 > 1 | 16 / 8 | 0.970× | [0.934, 1.015] |

中间前缀与初始前缀的速度比差异，在相同来源上比较为 **1.141× [1.031, 1.279]**。这支持收益具有上下文差异。两组的内容、历史和长度同时变化，不能单独归因于训练条件或上下文长度。

按长度分组，短于 256、256–1023、至少 1024 Token 的速度比分别为 1.146×、1.105×、1.140×，没有形成简单的单调关系。

5,078 个候选轮次中，`A_F` 的第 10/50/90 百分位为 **3.80% / 29.60% / 67.96%**。在 56 个固定前缀中，按精确 `A_F` 从低到高分成四组，对应速度比为 **0.977×、1.030×、1.152×、1.361×**。这说明接受概率与有效收益存在联系，但这些组使用了 Target 验证信息，只能用于解释。

Feature 草稿熵与 `A_F` 的总体相关系数为 **−0.717**。低熵组更有收益的迹象值得保留；熵需要在运行 Feature Draft 后获得，不能作为免费决定是否运行该 Draft 的依据。

## 4. 能否在生成前预测收益

使用固定的标准化加岭回归模型，按来源留一验证。所有同来源轮次均放在同一折，没有搜索模型参数。这里评估预测能力，尚未实施策略选择。

| 预测目标与信息 | 来源等权 R² | 平均绝对误差 | 训练均值预测的误差 |
|---|---:|---:|---:|
| `A_F`：历史与首个 Ranker 候选特征 | 0.264 | 16.21 个百分点 | 19.95 个百分点 |
| `A_F`：再加入 Feature 草稿统计 | 0.509 | 12.70 个百分点 | 19.95 个百分点 |
| 同前缀额外推进量：生成前特征 | 0.222 | 0.323 Token | 0.414 Token |
| 同前缀额外时间：生成前特征 | −2.695 | 1.683 ms | 0.968 ms |

生成前特征包括历史长度、近期位置间隔、位置坐标、候选间隔与坐标变化、候选数量，以及已有 Ranker 得分与分差。Ranker 得分用于排序，不能直接解释为接受概率。精确 `A_F`、Target 概率和实际接受结果均未作为输入。

接受概率与推进量具有一定可预测性。**当前时间预测比简单均值更差，因此还不能形成可靠的净收益决策。** 时间预测只基于 56 个前缀、每种方法每个前缀 8 次，样本量和分支随机性都限制了结论。这个结果也不能证明更好的时间模型不存在。

## 5. 对下一步的影响

保留固定 PF-K2，继续暂停仅提高 P₂ 接受率的独立 Head 训练。

下一项值得验证的是低成本的 Feature 使用条件，优先考察首个 Position 候选间隔等生成前已有信息。应先增加独立开发前缀及重复测量，稳定估计净时间收益，再与固定 PF-K2 做在线对照，并计入策略选择本身的耗时。

如果后续开展真实候选条件训练，需要单独证明训练与推理条件差异。当前 B1 证据没有识别出这项差异的因果作用，尚不能直接据此扩大训练或启动 EAGLE 递归模型。

本轮支持“Feature 收益具有条件差异”，尚未得到新算法的加速结果。固定前缀单轮结果仍须与长期生成及完整单 Chunk 输出分开；既有完整三维结果中 PF/P-only 区间跨过 1 的限制仍然保留。
