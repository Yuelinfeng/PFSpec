# SpatialAdapter CUDA 结果与适用范围

本次本地记录支持两件事：480 行离线概率在 CUDA 在线路径中与 CPU 保存值接近；两个固定前缀上的零残差重放与旧 PF 逐 token 相同。非零模型在两次相同输入、相同种子重放中也逐 token 相同。样本范围较窄，不能据此判断普遍生成质量或速度。

## 在线计算路径

`SpatialAdapter` 固定读取 `model_S3_seed_29.npz`、条件统计与 `condition_inputs.npz` 中的 `pca_embedding32`（4096×32）；模型参数数为 3585。每次提案仍调用原 Feature 一次，输入当前 Target hidden、最近已提交 Feature 和候选 P。适配器从实际已提交前缀解析完整 P/F 对，只查询六个轴向相邻位置；每个有效邻居输入 PCA32 类向量、相对坐标除以 19、以及相对历史长度归一化的年龄。8 项统计为 raw logits 均值/标准差/最大值/最小值、前两名 logit 差、归一化 q 熵、q 最大值和 top-8 q 总质量；q 项由原 FP32 policy q 转为 double 后归一。统计使用已保存的 fit 均值和尺度标准化，S3 输出 4096 维残差。CUDA 上 S3 计算期间关闭 TF32，并在调用后恢复原设置。

零残差模式仍执行邻居查询、统计计算与 S3 前向，之后直接返回原 `.9/.9` policy q；因此它检验在线状态和重放一致性，不代表关闭 S3 的运行成本。旧 `MLPAdapter` 与 SpatialAdapter 都从原 Feature logits 调用同一 `.9/.9` policy。

## 预热与边界

预热记录含 `target_only`、`old_pf`、`spatial_s3` 三种模式，各在前缀 64 和 256 上生成 32 token；六次均未遇到 EOS。这些记录用于确认路径能运行，不用于比较速度。

回放仅覆盖两个既有开发来源、两个前缀长度和 16 token 输出。四次回放均未自然生成 EOS；未测完整解码分布、拒绝过程以外的长程状态、独立来源、专门 3D 任务，也没有可用于速度结论的同条件统计。`neighbor_lookup_ms` 未单独记录，邻居与 S3 操作包含在外层计时内。故此处只报告数值一致性和固定种子重放，不推断总体质量、EOS 行为或加速幅度。
