# N2-S3 在线矩阵计时复核

run01 已完成 180 次解码，组成 60 组三方法配对，端到端用时 936.744 秒，低于 1800 秒总限额。运行使用 RTX 4090、FP32、matmul precision `highest`、TF32 关闭，Target、旧 PF 与 S3 的温度和 top-p 均为 0.9。主代理的独立复算状态为 `passed`，180 行、60 组、10 个来源；主指标及共同满 512 Token 的结果与 runner 汇总误差小于 1e-12。

## 运行与阶段计时

计时来自 [pipeline.json](raw/run01/pipeline.json)、[summary.json](raw/run01/summary.json) 和逐次 [records.jsonl](raw/run01/records.jsonl)。每条方法计时以 CUDA 同步包围完整解码，包含 KV 创建、前缀预填、提案、Target 验证、拒绝后的缓存恢复、抽样及 adapter 准备和收尾。模型加载和预热不计入单条解码时间，但计入总时限。

表中 250、400、1750 和 1800 秒均为从进程启动计起的累计截止时刻；阶段用时来自 `pipeline.json` 的分项。

| 阶段 | 分项用时 | 累计截止 | 结果 |
|---|---:|---:|---|
| 导入、输入载入、480条q一致性、Target/Ranker/旧MLP载入 | 14.233秒 | 累计250秒 | 完成 |
| 零残差重放、矩阵 adapter 准备、预热 | 4.555秒 | 累计400秒 | 完成 |

`summary_write` 记录 0.005377 秒，涵盖此前实际测得的摘要写入用时；末次摘要写入的少量时间没有计入该字段。`pipeline.json` 的总 elapsed 包含最终摘要、进度文件和运行状态的保存。分项阶段时长合计 935.914 秒，与总用时相差约 0.831 秒；未单列的开销包含计划与验证文件写入、进度更新和收尾操作。

## 配对顺序与完整性

输入来自既有 10 个开发来源，与 N2 使用的来源相同；矩阵新增种子为 38101、38102、38103，前缀长度为 64 和 256，生成上限为 512 Token。每一组的三种方法使用相同前缀和派生种子。实际顺序覆盖六种方法全排列，各执行 10 组；此处采用六序平衡，原网页方案列出三种轮换。实际分组、派生种子及顺序见 [plan.json](raw/run01/plan.json)。

三种方法均各有 60 条记录，覆盖全部 10 个来源与两种前缀；60 组均有完整的三方法记录。Target-only 与 S3 各生成 512 Token 60 次。旧 PF 生成 512 Token 58 次，另有两条自然 EOS 输出：51 Token 与 75 Token，末 Token 均为 EOS ID 12096。三方法共同生成满 512 Token 的组有 58 组，覆盖全部 10 个来源。

| 方法 | 解码次数 | 输出 Token | 外层同步时间 | 合并吞吐 | EOS次数 |
|---|---:|---:|---:|---:|---:|
| Target-only | 60 | 30,720 | 418.213秒 | 73.455 Token/s | 0 |
| 旧 PF | 60 | 29,822 | 240.968秒 | 123.759 Token/s | 2 |
| 空间 S3 | 60 | 30,720 | 257.354秒 | 119.369 Token/s | 0 |

旧 PF 的 Feature MLP 前向为 11,382 次；S3 的 MLP 前向和 S3 网络调用各为 11,568 次。`neighbor_lookup_ms` 在 180 条记录中均为空，邻居查找没有单独同步计时；其开销包含在外层同步时间内。

## 速度结果与适用范围

主指标先对每个配对计算 log 吞吐比，在来源内平均，再对 10 个来源等权取几何平均。S3/旧 PF 为 **0.9726569**，来源 bootstrap 95% 区间 **[0.9520744, 0.9932893]**，10,000 次重采样，seed 381012。当前 S3 路径在本轮来源上的速度比旧 PF 低约 2.73%。

共同满 512 Token 的 58 组采用相同输出长度下的外层时间比。S3/旧 PF 为 **0.9619980**，来源 bootstrap 95% 区间 **[0.9456455, 0.9779270]**，仍覆盖全部 10 个来源；这一子集的速度低约 3.80%。包含自然 EOS 长度差异的全部 60 组，汇总吞吐比为 0.9645250，作为补充口径。

旧 PF/Target-only 的主指标为 1.6815802 [1.6071853, 1.7425929]；S3/Target-only 为 1.6356005 [1.5432153, 1.7017085]。因此 S3 仍快于 Target-only，但本轮空间处理使旧 PF 相对吞吐下降。来源均属既有开发来源，并与 N2 共用；本次数据说明该实现的在线成本与速度，不构成未使用来源上的确认。分项邻居查找成本尚未单独测出，不能从本次记录判断其独立耗时。
