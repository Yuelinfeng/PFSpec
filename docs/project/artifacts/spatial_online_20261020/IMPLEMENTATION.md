# 空间模型完整解码比较实现

本轮由用户直接要求补测加速效果。使用现有S3 seed29、原step12000 Feature MLP、原Position Ranker和原Target；不增加训练，不重新选择模型、倍率、PCA或统计参数。完整网页方案保存在WEB_PLAN_ORIGINAL.md。

实际源码沿用本轮已建立的目录`patches/spatial_embedding_20261020`：`spatial_online_adapter.py`提供独立空间适配器，`compare_online.py`执行真实CUDA比较，`validate_online.py`以标准Python独立复算。生产文件及原权重保留原样。远端独立目录为`/root/autodl-tmp/gaussiangpt_spatial_online_20261020`。

适配器每次提案只调用一次原Feature MLP，从已有softcap输出取得原FP32概率，以原统计定义转换为binary64归一概率后构造8维输入。六个方向的邻居只读取当前已知P/F历史，重建查询包含在完整解码耗时内。S3使用既有3585参数与固定PCA32表，倍率1.0；得到残差后按原temperature0.9、top-p0.9策略采样。零残差验证仍运行邻居、统计和S3，然后直接使用原概率。

Target-only直接调用现用`draft_a.pf_ranker_eval.decode`的k=0路径，独立副本仅将函数已经生成的output随统计一起返回。原Target缓存容量保持length+budget+2，原PF保持length+budget+6；不改变模型计算或采样行为。每次外层同步计时覆盖整个decode，包括缓存、前缀、Ranker、MLP、空间处理、Target验证、恢复和输出。

运行顺序采用六种排列各10组，替代网页所列的三种旋转各20组。这是主代理在运行前选定的顺序平衡实现，覆盖更多方法先后组合；每组的数据、三方法、种子、采样和预算均相同。10来源×2前缀×3新种子共60配对组、180次解码。种子38101/38102/38103，派生规则为seed_base+crop_seed*1009+prefix*17；历史记录查询未找到相同预设种子。

加载、480行CUDA概率对照、两长度重放、三方法两长度预热、正式解码与结果保存共用1800秒。累计阶段上限为250/400/1750/1800秒。正式部分不添加逐阶段同步；邻居分项耗时不单独采集，主耗时包含全部工作。

主统计对每组计算吞吐比例的对数，来源内六组求平均，再求来源等权几何均值。来源重采样10000次，种子381012；另报合并吞吐及三方法共同满512token的等长结果。10个来源此前已用于开发，本轮不能替代独立来源、自然EOS完整生成或三维质量评价。
