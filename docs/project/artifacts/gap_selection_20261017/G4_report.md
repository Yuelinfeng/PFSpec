# G4 归因实验结果

G4 在 D0 开发来源上比较了固定 PF-K2、按既定概率随机选择 PF、反向间隔分配，以及每轮执行 PF 同时记录间隔判断的方案。512-token 窗口完成 672 次运行；2048-token 窗口完成 120 次运行。统计以来源为重采样单位，使用 10,000 次 Bootstrap。

| 窗口 | Gap/PF | Gap/随机选择 | 反向分配/PF | 判断开销/PF |
| --- | ---: | ---: | ---: | ---: |
| 512 token | 0.998× [0.979, 1.015]，5/10 来源胜出 | 1.026× [1.010, 1.040]，9/10 | 0.859× [0.843, 0.879]，0/10 | 1.000× [0.998, 1.002] |
| 2048 token | 1.036× [1.017, 1.054]，8/10 | 1.055× [1.034, 1.075]，10/10 | 0.887× [0.869, 0.903]，0/10 | 1.001× [0.997, 1.005] |

随机选择与间隔策略的实际 PF 使用率接近：512-token 分别为 77.33% 与 77.63%；2048-token 分别为 74.01% 与 74.25%。因此，Gap/随机选择的差异不能简单归因于少调用 Feature。短窗口中 Gap 尚未快于固定 PF；长窗口中 Gap 同时快于固定 PF 与随机选择，来源配对区间均在 1 以上。反向分配在两种窗口都明显变慢；额外间隔判断没有可测的速度惩罚。

这组结果支持在较长生成窗口中继续验证空间间隔的选择价值，但所有来源仍属于 D0，不能作为新来源确认。G5 转到预先选定的 10 个 D1 来源，保留 512-token 及 2048-token 两种窗口，并以长窗口的 Gap/PF 来源比作为主要推进依据。

PF 重跑与 G3 的相同种子输出和计数完全一致；持续执行 PF 并记录间隔的方案也与固定 PF 输出及 Token 计数一致。原始数据、运行协议和环境信息见 [`g4_raw/`](g4_raw/)；汇总数值见 [`G4_summary.json`](G4_summary.json)。
