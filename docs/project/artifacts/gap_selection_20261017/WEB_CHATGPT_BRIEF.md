## 问题背景

GaussianGPT 以交替的 Position/Feature Token 表示场景。自回归序列大致为 `P₁ → F₁ → P₂ → F₂ ...`。固定 PF-K2 使用 Position Ranker 提出 Position、轻量 Feature MLP 提出 Feature，再由原 Target 批量验证；P-only 跳过 Feature 提案。此前的成本测量发现，PF-K2 的额外推进可带来净收益，但 Feature 相关收益受上下文影响。因此本轮提出：能否用生成前已知的 Position 空间顺序信号，在 P-only 与 PF-K2 之间选择，从而稳定快于固定 PF-K2？

本轮没有训练新模型。Target、VQ-VAE、Position Ranker、Feature MLP、精确接受/残差抽样逻辑保持不变；策略判断只决定每轮走既有 P-only 或 PF-K2 路径。

## 算法定义与数据流

Position Ranker 对当前已确认上下文给出确定性的首个 Position 候选 `P₁`。定义：

```text
gap = candidate_position_id - previous_position_id
```

此处的 gap 是序列化 Position ID 的差，不是三维欧氏距离，也不是坐标轴上的单位长度。策略为：

```text
合法 P₁ 且 gap = 1  → PF-K2
合法 P₁ 且 gap > 1  → P-only
BOS、无候选、异常值或剩余预算不足 → 原 P-only 路径处理
```

决策发生在 P₁ 提出后、Feature MLP 和本轮 Target 验证前。两条路径都使用原 Target 验证、接受/残差抽样、EOS 与缓存更新流程。B1 中的 gap 公式已对 5,122 个候选逐项重算，5,122 个标签全部匹配；其中 gap=1 为 3,970 条，gap>1 为 1,152 条。

## 正确性与运行环境

- 真实 Position Ranker 的多候选选择使用分数 `argmax`，不是随机抽取；相同前缀下 P₁ 相同。间隔选择因此依赖当轮验证前已有状态。
- G1 强制执行 P-only、PF-K2、Gap 路由切换、拒绝分支、EOS 和缓存状态用例；运行端点及分支计数与对应原路径相符。
- 两步小词表序列枚举覆盖 144 条序列。P-only、PF-K2、Gap 路由相对 Target 的总变差分别约为 `1.52e-18`、`3.82e-17`、`2.08e-17`。这是小词表模型中的精确枚举结果，不等于对所有真实模型数值行为的形式证明。
- 真实解码器的缓存/全前缀对照存在 FP32 数值差异；所测若干上下文的下一 Token 最大总变差约 0.0075。论文表述应区分采样算法的分布保持设计和真实 GPU 数值误差。
- 评测设备 NVIDIA RTX 4090；Python 3.10.21、PyTorch 2.8.0+cu129、CUDA 12.9；FP32、temperature=0.9、top-p=0.9。Target 为 `gpt_vfront.ckpt`，VQ-VAE 为 `vqvae_vfront.ckpt`，使用现有 Ranker 和 Feature MLP。

## 进入本轮前的依据

**A1–A3 成本测量**：固定窗口 PF/P-only 来源等权速度比为 `1.171× [1.130, 1.211]`。相同前缀单轮推进效率比为 `1.141× [1.085, 1.195]`。P₂ 拒绝后的整段处理占计时总量 `1.337%`；假定免费去掉该处理得到 `1.0136×` 的乐观时间估算。这不代表其他算法可能获得的全局上限。

**Feature 条件收益 B1**：首个 Position 候选 gap=1 的 40 个前缀中，PF/P-only 为 `1.190× [1.117, 1.261]`；gap>1 的 16 个前缀中为 `0.970× [0.934, 1.015]`。这些前缀来自 10 个开发来源，分组并非随机分配，结果只构成探索性关联。生成前特征对 Feature 接受概率的来源留一预测 R² 为 0.264；加入 Feature 草稿统计后为 0.509，但该统计需要先计算草稿。额外时间预测 R² 为 −2.695，弱于简单均值参照。

**既有完整单 Chunk 数据**：此前 PF 相对 P-only 的端到端速度比区间曾报告为 `1.070× [0.912, 1.252]` 与 `1.058× [0.958, 1.167]`，均跨过 1。因此本轮目标聚焦于先验证间隔选择的 Token 生成收益；完整三维增益没有预先成立。

## G0–G5 实验过程与结果

统计中的来源等权速度比以来源为单位聚合，区间使用 10,000 次来源级 bootstrap 重采样。短、长窗口分别报告。

| 阶段 | 工作 | Gap / 固定 PF-K2 | 对照和解释 |
|---|---|---:|---|
| G0 | 核对权重、Ranker 确定性、gap 定义、两条数据流 | — | 发现 gap 是序列化 ID 差；非欧氏距离。 |
| G1 | 正确性与有限分布测试 | — | 强制分支、EOS、缓存状态通过；两步小词表序列枚举接近数值精确。 |
| G2 | 56 个已反复使用的前缀、10 来源、8 seeds；1,344 次单轮测量 | `0.996× [0.989, 1.002]`，5/10 来源更快 | Gap/P-only `1.221× [1.159, 1.275]`；Gap 尚未显示超过固定 PF-K2。 |
| G3 | D0 连续在线；672 次 512-token，90 次 2,048-token | 512：`1.006× [0.991, 1.022]`；2,048：`1.026× [1.008, 1.044]` | 长窗口信号为正，短窗口区间跨过 1；来源仍属已用于开发的数据。 |
| G4 | D0 路由归因：固定 PF、频率相近随机选择、反向分配、间隔判断成本 | 512：`0.998× [0.979, 1.015]`；2,048：`1.036× [1.017, 1.054]` | Gap/随机为 `1.026× [1.010,1.040]`、`1.055× [1.034,1.075]`。长窗口 D0 数据支持空间信号继续验证，尚非独立确认。 |
| G5 | D1 新开发来源；270 次正式测速，另有 24 次冒烟 | 512：`1.009× [0.981,1.036]`；2,048：`1.018× [0.990,1.048]` | 预先设定的长窗口推进条件未满足，停止在 D1。 |

### G5 细节

- D1 为 10 个新开发来源，每个来源一条 Token crop，前缀长度 64 与 256。512-token 共 180 次：20 contexts × 3 seeds × 3 methods。2,048-token 共 90 次：10 sources × 3 seeds × 3 methods。
- D1 预处理时 10 个来源的场景几何、Gaussian 拟合、渲染和 Token 化均成功。160 个活动模型 ID 均可用（35 个来自既有资源链接，125 个从完整模型包定向抽取）；160 个纹理 ID 中有 64 个找到 PNG/JPG，其余沿用 SceneZoo 的纯灰纹理回退。这是输入场景准备情况，不代表本轮对生成质量做了评测。
- 方法为 P-only、固定 PF-K2、Gap 选择。计时含 Target cache 分配、前缀预填和解码调用；不含模型与 crop 载入。
- 512-token：Gap/P-only `1.185× [1.158,1.212]`；固定 PF-K2/P-only `1.174× [1.141,1.210]`。Gap 的 PF 实际路由占比 74.34%。前缀 64 的 Gap/PF 为 `1.025× [1.003,1.045]`，9/10 来源更快；前缀 256 为 `0.993× [0.953,1.038]`，4/10 来源更快。
- 2,048-token：Gap/P-only `1.136× [1.113,1.161]`；固定 PF-K2/P-only `1.116× [1.094,1.136]`。Gap 的 PF 实际路由占比 73.27%，10 个来源中 6 个 Gap 更快于固定 PF。
- 预先记录的继续条件是：D1 2,048-token Gap/PF 来源几何平均至少 1.02，且来源级 95% 区间下界大于 1.00。观测点估计 1.018，区间下界 0.990，所以未进入 G6。

## 阶段结束时可以与不可以说什么

可以说：当前间隔规则在 D1 上明显快于 P-only，与固定 PF-K2 的速度接近；D0 长窗口曾得到正向结果，D1 未达到预先设定的确认条件。现有实测支持固定 PF-K2 相对 P-only 的收益，未支持间隔策略稳定增加额外收益。

不能说：空间间隔已被证明造成了 Feature 收益差异；Gap 选择已在独立确认集胜过固定 PF-K2；该策略改善完整三维生成速度或质量；G6/T 或 G7 已运行。Target 预训练来源清单缺少完整场景 ID，来源重叠情况尚不能完全确定。

## 当前阶段决定

G0–G5 与阶段总结 G8 已完成。按实验计划，G5 未达到进入 G6 的条件，因此没有运行 T 来源确认，也没有开展 Gap 选择的 G7 完整三维输出。T 集保留为未测量来源。后续若要重启，应基于新假设另立研究计划，避免用现有未测量数据反复挑选规则。
