# G2：相同前缀单轮评测

## 结论

在已使用过的开发数据上，Gap 规则的单轮速度与固定 PF-K2 接近，当前结果没有显示它能超过 PF-K2。来源级几何平均比值为 **0.996×**，95% 来源重采样区间为 **[0.989, 1.002]**，10 个来源中 5 个更快。该规则相对 P-only 为 **1.221×**，95% 区间为 **[1.159, 1.275]**。

因此，Gap 规则确实保留了 Feature 带来的部分收益，但这组单轮数据尚未证明按 gap 选择优于每轮使用 Feature 的固定策略。连续在线评测 G3 仍是必要步骤。

## 评测规模与路由

评测使用 56 个既有前缀、10 个来源、每个前缀 8 个随机种子。P-only、固定 PF-K2 与 Gap 各运行 448 次，共 1,344 次单轮评测；另有 48 次独立插桩运行。

gap=1 的 40 个前缀走 PF-K2；gap>1 的 16 个前缀走 P-only。所有 448 个 Gap 运行均与对应固定路径在输出 Token 和分支计数上相符。Gap 规则调用 PF-K2 的比例为 71.4%。纯路由计算的中位耗时为 0.76 微秒；包含选择器封装的中位耗时为 1.67 微秒。

| 方法 | 生成 Token | 总耗时 | 汇总吞吐 |
|---|---:|---:|---:|
| P-only | 896 | 61.38 s | 14.60 Token/s |
| 固定 PF-K2 | 1,112 | 62.16 s | 17.89 Token/s |
| Gap | 1,104 | 61.94 s | 17.82 Token/s |

gap=1 子组中，Gap 与固定 PF-K2 的输出分支相同，汇总吞吐均约为 20.64 Token/s。gap>1 子组的 Gap 与 P-only 分支相同，汇总吞吐分别约为 12.28 与 12.28 Token/s。来源分层明细见 [G2_summary.json](G2_summary.json)，逐轮记录和计时剖析见 [g2_raw](g2_raw)。

## 解释范围

这些数据来自单轮短窗口，用于确认路由、分支结果和附加耗时。56 个前缀来自 10 个已用于方法探索的来源，因此结果属于开发诊断，不能代表未见来源上的表现，也不能预测连续生成轨迹。插桩运行与主计时分开，未混入吞吐比较。

本轮未训练模型，也未修改远端主工程源码。G2 中的两次无效尝试由测试脚本的路由名称和 gap 数据来源问题造成，相关日志及部分记录保存在 [failed_attempts](failed_attempts)；它们没有进入上述汇总。
