# Feature 树分支执行计划

本轮比较当前 PF-MLP、W1 树和 W2 树三种提案方式。主结果统一以同一批输入上的原始 Target 吞吐为参照；PF-MLP 用于研发横向比较，W1 用于判断 W2 增加分支后的净变化。

## 输入与运行臂

W1 使用一个 Feature 候选分支，W2 使用两个 Feature 候选分支；两者共用前缀与第二个 Position 预测。树输入节点数与实际尝试、接受数分别统计。

本轮先用 3 个开发场景，每个场景取 64/256 两种前缀，并使用 seed 45101–45103，共 18 组输入。完整测时预算为每臂 512 个输出 token，四臂合计 72 条记录。所有方法使用同一组 `prompts.json`，各臂轮转执行；每臂各自持有运行时对象。

预期运行臂：

| 运行臂 | 用途 |
|---|---|
| `original_target:target` | 主参照，执行原始 Target 解码 |
| `proposal_graph:pf_mlp` | 当前方法对照，包含提案图成本 |
| `tree_graph:tree_w1` | W1 树分支 |
| `tree_graph:tree_w2` | W2 树分支 |

每行记录同步后的外层总时长、输出 token 数、EOS、计数和各运行时差量。外层总时长覆盖运行时创建、KV 分配、图准备和捕获、前缀处理、提案、Target 验证、拒绝后的恢复、采样与缓存维护；权重加载单独记录，不并入解码时长。W1/W2 的节点数量、Feature 提案与接受数、Target 调用数都保留逐臂总量和每条记录的来源字段。

## 先做数值确认，再做完整测时

先在真实输入上确认 W1/W2 的分支输出与对应非图路径一致：同一固定输入下比较图捕获前后的 logits、节点选择、提案分布和随机种子输出；确认分布有限、总和为 1、残差分布合法，输出仍符合 P/F 顺序及位置递增规则。再做 64 token 短跑，验证四臂字段和完整成本计时。W1 与当前 PF-MLP 使用同 pair、同 seed 比较输出和共有计数；树宽度、提案宽度、变体、树运行时摘要及 PF-MLP 不含的树专用计数单列，双方共有的业务计数逐项比较。完整测时前，W1 的输出及共有计数需与 PF-MLP 一致。

数值结果与短跑均完整后再运行 3 个场景的全预算测时。若 W1/W2 的图路径和非图路径结果不一致、树节点记录缺失，或序列格式不合法，先停在数值阶段并保留原始记录，不把短跑时长当作方法结果。

## 统计口径

主表给出 PF-MLP、W1、W2 相对原始 Target 的来源等权几何平均 token/s 倍率及按来源重抽的 95% 区间。每个来源先平均该来源各前缀的 log 倍率，再对来源等权平均；bootstrap 使用 10,000 次、seed 402101。另报所有输出长度下的结果，以及比较双方均达到 512 token 的共同满预算子集。

辅助表给出 W2/MLP 和 W2/W1。倍率按每条记录实际生成 token 数除以同步外层时长计算，保留不同输出长度与 EOS，不裁剪或补齐输出。另列每臂总时长、输出长度分布、树节点数、Feature 提案数、实际进入验证的 Feature 尝试数、Feature 接受数和 Target 调用数。

图运行时统计包含首次新建图的事件数、准备/预热/捕获耗时、首次建图请求的外层时长，以及已使用图且该行没有新增图的复用子集。更严格的复用子集还要求 Target 图和提案图都没有新增事件。两种子集都以原始 Target 作主倍率分母。

## 继续条件

主表始终报告 W2/原始 Target。是否进入 W4 取决于 W2 相对当前 PF-MLP 的净提升及来源区间：只有 W2/MLP 点估计高于 1，且按来源重抽的 95% 区间下界也高于 1，才考虑下一轮扩宽。仅有 W2/原始 Target 倍率高于 1 不足以支持 W4。若本轮 W2/MLP 没有明确净提升，就停止扩宽并记录限制来自提案成本、树验证、接受率或恢复路径中的哪一项；不自动启动新训练。

## 产物

运行器输出 `plan.json`、`prompts.json`、`pipeline.json`、`records.jsonl` 和运行时摘要。独立 CPU 统计器 `patches/feature_tree_20261021/analyze_tree.py` 从原始行记录复算配对、倍率、区间、节点与接受计数，生成 `summary.json` 和 `RESULTS.md`。阶段性数值材料与完整测时记录保留在本轮独立运行目录。
