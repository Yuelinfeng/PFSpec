# 概率化 Position 提案实验

目标是同时改善有效接受量与完整解码速度。当前静态 W1 保持为现用参照；原 Target 是主加速倍率的分母。

已完成路线显示：Feature W2 扩宽的收益抵不过成本；恢复成本选择器没有稳定增益；相同 MLP 长续训没有稳定增益。本轮采用不同改动：将 Ranker 在合法 Position 候选上的正类评分归一为真正的提案分布 q，并从 q 抽样。只有一个候选时沿用原点提案。

每个候选 y 的接受概率为 min(1,p(y)/q(y))。拒绝后从归一化的 (p−q) 正部抽样，支持集包含 Target 的 EOS。P2 的 q 由实际抽到的 P1 对应状态生成。Feature MLP、Target policy、权重与 W1 图执行保持原设置。此方法不需要新训练或拟合温度。

首先在十个开发来源的 64/256/512/1024 可用完整对前缀上，用同一 Target 分布分别计算原点提案接受概率和新 q 的重合度。该诊断只衡量相同历史下的理论接受概率，不能替代在线速度。

随后进行小词表输出概率枚举、原 W1 与新 point 模式同种子对照、新 prob 模式重复解码与合法流验证。通过后运行同轮原 Target/W1/prob 的完整解码：十开发来源，64/256 前缀，三种子，512 新 token。顺序轮换，各臂独立持久图；首次建图、缓存分配、前缀计算、提案、验证、恢复、抽样与末尾同步都进入外层时间。权重加载及独立预热另记。

报告来源等权几何平均速度比与来源重采样 95% 区间，另报接受计数、恢复调用、完整预算与 EOS。prob/W1 是新增方法收益，prob/原 Target 是合计收益。不同提案的随机数消耗和输出可能不同，不要求跨方法逐 token 相同。

先进行有限诊断和小测；若不能改善接受或小测明显变慢，则停止当前实现，不增加训练和宽度。完整矩阵结束后才决定是否需要独立来源确认；没有新三维端到端实测时不沿用旧端到端倍率作为新结果。

## 初始诊断后的方向调整

39 前缀已测：原点提案接受概率 0.689961，Ranker 正类评分归一后的 q 重合度 0.684075，直接归一没有改善，故不扩大其速度矩阵。仍完成分布枚举与有限解码对照，保留完整实现和负结果。

新增两个具体候选：

- 备用 Position：在 W1 四节点外增加一个次高分 Position 节点，首次 Position 拒绝后照原规则抽样。实际残差位置等于备用时，复用其 Feature logits 与 hidden，省一次恢复调用。原接受判定和随机数顺序保持相同；备用命中另列，不并入原接受率。只有一个 Position 候选时走原四节点。
- 历史 Target Feature 分布复用：将上一已提交 Position 对应的完整 Feature policy 缓存在本请求内，用 `0.75 q_MLP + 0.25 p_previous` 提案。该 policy 在本轮提案前已经可得，当前轮尚未计算的 Target 分布不进入 q。39 条相同前缀诊断的普通重合度由 0.256183 到 0.278532，P1 概率加权进展质量由 0.181659 到 0.190564；这只是开发诊断，仍需在线确认。

混合诊断同时记录上一分布权重 0/.25/.5/.75/1，原始完整概率向量保留。选择 .25 是保留大部分现有 MLP 的保守开发候选，此诊断参与了方法选择。后续独立来源验证不能与这批开发诊断混称。

新候选首先进行同种子合法流与重复对照，随后有限同轮完整解码。只有实际速度改善时才扩大原 Target 对照及独立来源；不从初始前缀接受概率外推完整请求倍率。
