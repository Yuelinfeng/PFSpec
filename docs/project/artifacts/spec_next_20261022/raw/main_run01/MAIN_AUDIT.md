# main_run01 独立数据复算

## 范围与完整性

直接读取本目录的 `plan.json`、`prompts.json`、`pipeline.json` 和 `records.jsonl`。计划列出 10 个 development 来源、prefix 64/256、3 个 seed、512 token 上限，共 60 个 prompt 和 240 条记录。流水线标记 complete，实际也是 240/240 条、60/60 配对，每对含 `target`、`w1`、`rescue`、`reuse` 各一条；没有重复或缺臂。每条记录的 source、prefix、seed 与对应 prompt 一致，生成长度与 token 列表长度相符，240 条均记录 `sequence_validated=true`。

来源等权倍率由每个配对的 `tokens_per_second` 比值取对数，先在来源内平均，再对 10 个来源等权平均并取指数。95% 区间按来源重采样 10,000 次，seed 为 402101。结果与运行器的 `summary.json` 中 source-equal ratio 逐位一致。

## 满预算与无新增图子集

Target 在 3 个 prompt 上自然结束，故 57 对四臂都生成满 512 token。另有 56 对四臂没有运行时新建或图形状事件；两者交集为 53 对。子集倍率仍以 Target 为分母，括号内是来源重采样区间。

| 方法 / Target | 四臂均满 512（57 对） | 四臂均无新增图（56 对） | 满 512 且无新增图（53 对） |
|---|---:|---:|---:|
| W1 | 5.0129× [4.7733, 5.2284] | 5.0734× [4.8388, 5.2640] | 5.0918× [4.8502, 5.2853] |
| rescue | 5.1077× [4.8550, 5.3433] | 5.1863× [4.9694, 5.3623] | 5.2066× [4.9841, 5.3874] |
| reuse | 5.0483× [4.7849, 5.2866] | 5.0997× [4.8683, 5.2874] | 5.1145× [4.8772, 5.3111] |

以 W1 为分母，四臂无新增图子集中 `rescue/W1` 为 1.0223× [1.0162, 1.0283]；满预算且无新增图的 53 对为 1.0225× [1.0164, 1.0285]。相同两类子集中 `reuse/W1` 分别为 1.0052× [0.9849, 1.0267] 和 1.0045× [0.9843, 1.0263]。

`summarize_runs.py` 的无新增图筛选遍历所有 `*_delta` 字段，因此包括 `rescue_runtime_delta`；同时排除 `runtime_created` 与正值 `graph_setup_ms`。W1、rescue、reuse 均记录了图执行和每臂 60 次 `unsupported_query_tokens` 回退。首次运行时的捕获及图设置耗时已计入 `outer_wall_seconds`；模型权重读取不计入。

## rescue 与 W1 的逐对复核

W1 与 rescue 在 60/60 配对中 token 序列完全一致，生成长度、EOS 标记、`accepted_lengths`、树验证次数、Position/Feature 接受计数也逐对一致。新增备用 Position 节点只改变了恢复路径：

| 计数 | W1 | rescue | 差额 |
|---|---:|---:|---:|
| recovery calls | 1,314 | 834 | −480 |
| `position_rescue_hits` | 0 | 480 | +480 |
| Target calls | 13,112 | 12,632 | −480 |
| Target tree nodes | 46,784 | 51,581 | +4,797 |
| Target input tokens | 57,782 | 62,099 | +4,317 |

每个配对上 `W1 recovery_calls − rescue recovery_calls = rescue position_rescue_hits`，60/60 成立。备用节点尝试 4,797 次，命中 480 次；这 480 次不能计入 Feature 的 alpha 接受率。新增树行和 Target 输入量带来成本，整体来源等权速度仍高 1.86%，稳定子集高约 2.23%。

## reuse 的 Feature 接受与耗时

| 指标 | W1 | reuse |

| 树验证轮数 | 11,696 | 11,533 |
| Feature 分支命中 | 3,622 | 3,775 |
| 命中 / 树验证轮 | 0.3097 | 0.3273 |

reuse 的 Feature 分支命中占树验证轮次的比例增加 0.0176。它与 W1 的 60 对生成长度和 EOS 标记一致，token 序列 0/60 相同，这是提案混合后抽样轨迹变化的结果。来源等权 `reuse/W1` 为 1.0078×，区间 [0.9905, 1.0276]；满预算且无新增图的 53 对为 1.0045×，区间 [0.9843, 1.0263]。较高的 Feature 命中率尚未转化为清楚的外层速度增量。

## 自然结束与范围限制

Target 自然结束的三条记录长度分别为 361、201、73，尾 token 均为计划中的 EOS id 12096；三条都来自 prefix 256。W1、rescue、reuse 均为满 512 token、没有自然 EOS。因此主结果保留了自然结束对吞吐的实际影响，另列四臂共同满预算子集作为长度敏感性结果。Target 与 speculative 方法采用同 seed，但解码抽样轨迹可不同；逐 token 相等只用于 W1/rescue 的实现复核，reuse 不要求与 W1 完全同序列。

计划将本轮标为 development 来源。父任务另行 CPU 对照确认这 10 个开发来源与 30 个保留测试来源无交集；本轮不能替代保留来源上的独立速度复测。
