# F1/F2 联合递归训练

用户授权在保留语料生成进程的前提下开展下一步。2026-10-13 开始使用已有数据完成 CPU 联合递归对照，不运行 Target 前向，不使用 GPU，也不新增后台调度。正式解码权重保持原状。

## 输入与运行位置

运行主工程为远端 `/root/workspace/GaussianGPT`，沿用 `/root/miniconda3/envs/gaussiangpt/bin/python`。本机代码为 `patches/lfq_feature_acceptance/train_pf_joint_recursive.py`，远端同名入口位于主工程根目录，依赖已有模型、损失和数据读取模块。

F1 起点是 `profiling/feature_draft/lfq_new_onpolicy_warmstart/lfq_scratch_conditional_best.pt`；F2 起点是 `profiling/feature_draft/pf3_joint_refresh_train/pf3_depth2_best.pt`。沿用 LFQ 低 6 bit 类别与高 6 bit 条件分布、1024 维 Target 输入、256 维 Draft 状态、20×20×20 Position 坐标、temperature/top_p=0.9/0.9。不扩大网络，也不添加推理运算。

F1 训练来源为 `state_generation_512` 与 `lfq_new_onpolicy`，采样比例 40%/60%。F2 训练来源为 `pf3_depth2_data`、`pf3_refresh_stale`、`pf3_refresh_trained`，比例 15%/45%/40%。以上目录均位于远端 `profiling/feature_draft/`。存在轨迹编号的来源内采用轨迹等权，旧离线 F1 缺少编号，仍按位置采样。

F1 开发验证使用新在线数据的 16 条轨迹、6138 个位置。F2 开发验证使用原深度二数据的 16 条轨迹、1687 个位置，以及已训练提议器数据的 24 条轨迹、2553 个位置；两个来源等权。读取模块沿用原有数据来源、Teacher 策略和父权重配对验证，并核对可用编号中的训练/验证重叠。旧离线 F1 缺少编号，因此无法从编号证明其与其他来源完全独立。保留测试集不读取。

## 对照设计

每次更新分别抽取 F1 与 F2 两批数据。损失采用已有的联合 CE、最终采样分布重合度和 12-bit 边际监督，总损失为 `loss_F1 + 0.25 * loss_F2`。两组仅改变 F2 梯度进入 F1 状态生成层的路径：

| 版本 | F1 更新 | F2 更新 | F2 梯度进入 F1 状态 |
| --- | --- | --- | --- |
| detached | 独立 F1 监督 | 使用重新计算的 F1 状态 | 不传递 |
| joint | F1 与 F2 监督 | 使用重新计算的 F1 状态 | 传递 |

F2 两个 token embedding 沿用当前模型的固定参数设置。F1 全部参数参与训练；F2 损失可更新 F1 的状态生成层，但不直接更新 F1 输出头。F1 输出头仍由独立 F1 标签监督。

两组使用相同父权重、seed=164039、AdamW lr=3e-5、weight_decay=0.01、batch_size=128、梯度范数上限 1。固定各运行 4 轮，每轮每层 30000 个位置。固定轮数便于比较同一计算预算，不因各组验证结果不同而改变训练长度。数据采样器拥有各自固定随机种子，两组采样顺序相同。

F2 始终使用记录中的 `hprev、fprev、p1、f1_draft、p2`，重新计算 `x1=F1(hprev,fprev,p1)`，再预测 F2。Teacher 标签只适用于记录中的 token 前缀，训练中不重新采样 F1。改变后的提议分布需要未来真实在线采集才能评价。

选模分数为 F1 按轨迹重合度，加上 0.25 倍 F2 按来源与轨迹等权重合度。父模型为第 0 轮候选，同时保留每轮、每层、每来源与每条轨迹的结果。该分数用于开发集选模，不能解释为在线联合接受率或加速比；必须单独报告 F1 是否下降。

F1 与 F2 成对保存，F2 沿用现有加载器要求的 F1 文件指纹字段。载入后再次完整评价，要求与选中结果一致。没有添加新的权重配对机制。

## 执行与验证

CPU 梯度验证已通过：仅 joint 的 F2 损失产生 F1 状态层梯度，detached 不产生；两个版本均不向 F1 输出头直接传递 F2 梯度，F2 固定 embedding 也没有梯度。

实际前台命令：

```bash
CUDA_VISIBLE_DEVICES='' OMP_NUM_THREADS=1 MKL_NUM_THREADS=1 PYTHONDONTWRITEBYTECODE=1 \
  nice -n 19 /root/miniconda3/envs/gaussiangpt/bin/python -u train_pf_joint_recursive.py \
  --out-dir profiling/feature_draft/pf_joint_recursive_20261013/cpu_comparison
```

日志为远端 `profiling/feature_draft/pf_joint_recursive_20261013/cpu_comparison.log`。输出目录中的 `comparison.json` 保存两个版本及其成对差异；各子目录 `summary.json` 保存完整训练记录。输出目录已存在时入口不覆盖既有结果。

训练使用 CPU FP32、单线程与低优先级。代码不载入 CUDA 模型、不停止现有进程；仍会使用部分内存与读取带宽，不能保证对并行语料作业完全零影响。开始前语料进度为 367/500，生成 PID 为 368154，顺序任务 PID 为 368943。

## 结果与限制

两组均完成 4 轮，累计训练 480000 个位置，即每组每层 120000 个。训练与逐轮验证合计约 338.54 秒，不含启动、数据读取和最终重新载入验证。对照组保留第 0 轮父模型，联合组选中第 2 轮。

| 模型 | F1 按位置 | F1 按轨迹 | F2 按来源与轨迹等权 |
| --- | ---: | ---: | ---: |
| 父模型 / detached 选中结果 | 28.9468% | 29.6134% | 24.4702% |
| joint 第 2 轮 | 28.9220% | 29.5934% | 24.9143% |
| joint 相对父模型，百分点 | −0.0248 | −0.0200 | +0.4441 |

联合候选的 F2 在原深度二验证源上按轨迹增加 0.4467 个百分点，16 条轨迹中 13 条改善，描述性 95% 区间为 +0.1206 至 +0.7824 个百分点；在已训练提议器验证源上增加 0.4415 个百分点，24 条中 17 条改善，区间为 +0.2221 至 +0.6619 个百分点。F1 的 16 条轨迹中 8 条改善，平均变化 −0.0200 个百分点，区间为 −0.2282 至 +0.1771 个百分点。

相同第 4 轮的 joint 与 detached 比较，F1 增加 0.0554 个百分点，F2 增加 0.5893 个百分点；两个 F2 来源的 40 条轨迹全部高于相同轮次对照。该比较位于 `same_epoch4_difference.json`。第四轮 joint 的 F1 仍低于父模型，因此保留第二轮作为当前综合候选。

这些结果支持 F2 损失进入 F1 状态层具有小幅开发集收益，幅度不足以承诺在线加速。两组使用同样的全局梯度范数裁剪，joint 新增的状态梯度也可能改变整体裁剪比例；没有逐层记录裁剪前范数，不能把变化全部归因于某个单独参数模块。来源比例属于抽样概率，实际抽中数会有波动；目前日志没有保存各来源实际抽样计数。F2 验证只有两个已有验证来源，不包含 stale 训练来源的独立验证。

两组成对权重均通过现有 `load_base` 与 `load_depth2` 实际载入，完整验证结果与选中结果一致。最终保留远端 `cpu_comparison/joint/lfq_scratch_conditional_best.pt` 和 `cpu_comparison/joint/pf3_depth2_best.pt`。对照组两份权重与原父权重逐张量相同，验证完成后已移除这两个重复文件；原权重、日志、指标与精确清单 `weight_cleanup.json` 保留，可从父权重恢复。没有生成最后轮次的额外权重。

结束时语料进度为 388/500，生成进程 368154 与顺序任务 368943 均继续运行。当前 CPU 训练已经完成退出，没有修改语料数据与相关作业。

置信区间按轨迹重采样 3000 次，验证集参与了轮次选择，且只运行一个训练 seed，因此只作描述。保留测试集未读取。CPU 训练不能替代实际 GPU 解码测速，本轮没有新增加速比结论。最近已有独立在线对照仍为 K=2 约 1.7309×、K=3 Refresh 约 1.6727×，不能将本轮开发重合度变化换算成吞吐提升。

后续优先使用当前成对候选做独立测试与真实 K=2/K=3 接受率评价，再决定是否采集新提议分布的 F2 标签；需要 GPU 的步骤保留到现有作业完成之后。当前不替换正式权重、不继续扩充输出头监督，也不同时引入动态长度或空间 Delta。

GPU 作业完成后，用户已授权继续上述独立评价，见 [独立测试与在线测速](PF_JOINT_EVALUATION_2026-10-13.md)。本页中的“测试集未读取”仅描述 CPU 训练阶段。
